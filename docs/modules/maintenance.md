# 维护与批量工作流

维护任务都是显式触发的长任务：有进度、可取消、失败有清单。它们不改变“原图不可变”的原则，只清理可重建缓存或用户明确要求删除的内容。

已实现：重建缩略图（走任务总线，可选重算 pHash / 主色）、永久删除与清空回收站的待释放标记与后台释放任务（`ReleaseGarbage`）。描述导出/回填、孤儿清理、包压缩、库检查、导出仍为 S8 计划。

## 描述工作流

原软件的流程是：导出无描述图片 → 外部打标 → 回填描述。新结构继续保留，但文件名使用内容哈希：

```text
导出：<library>/output/<content_hash>.<ext>   以及可选的 manifest.json
回填：<library>/output/<content_hash>.txt     第一行作为描述
```

- “导出无描述图片”：把描述为空的图片复制到 `output/`，不移动原图；可选上限数量、是否转 BMP（兼容旧外部工具）。
- “回填描述”：扫描 `output/*.txt`，按文件名匹配 `content_hash`；命中则更新 `description`、`description_source='import'`、`modified_at`。
- 可选的 `manifest.json` 给出 `content_hash`、尺寸、文件夹、当前标签，方便外部工具；没有 manifest 也能按文件名回填。
- 回填默认只填空描述；可选覆盖，覆盖前显示数量确认。
- 导出/回填完成后不自动删除 `output/`，由用户确认清理。

## 清理孤儿文件

- 扫描图库内用户文件夹（不含 `.artbank/`、`recycle/`、`output/`）。
- 文件名符合 `<content_hash>.<ext>` 且 DB 中存在对应行 → 正常。
- DB 中没有该哈希，或扩展名/文件夹不匹配 → 视为孤儿。
- 孤儿先移动到 `recycle/`，不直接删除；清单可导出。确认后再清空回收站。
- 反向检查：DB 行存在但原图缺失 → 标记为“缺失文件”，在回收站/维护页显示；不要静默删除行。

## 缩略图维护

- **重建缩略图**（已实现）：工具栏「任务 → 批量任务…」，范围可选当前选择 / 文件夹 / 集合 / 视图 / 全库；默认只补缺失，可勾选重做已有并顺带重算 pHash / 主色。重新解码原图、生成 512px、追加到 pack、在事务里更新指针与 `thumb_version`；连续失败 5 张自动停止。
- **缺失缩略图**：`thumb_segment=0` 或读取失败时，详情/网格显示占位；用同一条批量任务补建。
- **包压缩**：当未引用字节超过阈值（默认 20%）或用户手动触发：
  1. 新建 segment（新文件名）；
  2. 按图 id 顺序复制仍被引用的 blobs，记录新偏移；
  3. 在一个写事务里批量更新 `images.thumb_*` 与 `thumb_segments`；
  4. 提交后删除旧 segment 文件。
- 压缩期间新缩略图写入新 segment；读取按 DB 指针，不依赖旧文件，因此不需要停机。
- 包格式只追加，不做原地块分配；删除/重写造成的垃圾由压缩回收。

## 特征包维护

- embedding/pose 存放在 `features/<kind>-<model>-<dim>-<dtype>-<hash>.pack`，`feature_blobs` 记录 model/dim/offset/length。
- 模型变更后，旧向量保留但标记为不兼容；维护页可“重算全部 embedding/pose”或“清理不兼容向量”。
- 特征包同样只追加；清理时可重写压缩。特征是可重建数据，丢失可重算。

## 库检查

- **快速检查**：遍历 `images` 行，检查原图是否存在、大小是否一致；不计算哈希。20 万行可在秒级完成。
- **完整校验**：对选中/全库重算 BLAKE3 并与 `content_hash` 比较；昂贵，只在显式触发时运行，显示进度与可取消。
- **数据库检查**：`PRAGMA quick_check` / `integrity_check`；失败时只报告，不自动修复。
- 检查结果不自动改数据；用户可选择“标记缺失”“移到回收站”“清理孤儿”。

## 图片空间优化（估算）

批次 1 已实现只读估算；替换原图的写路径尚未实现。

- 入口：工具栏「任务 → 优化图片空间…」，范围可选当前选择 / 文件夹 / 集合 / 视图 / 全库。
- 参数：质量档位（极高 / 高 / 中）、输出格式（JPEG / WebP）、长边上限、三个重算开关、是否跳过已处理过的图片、抽样数量（100 / 200 / 500，默认 200）。
- 只读：估算走 `scan` lane，不写数据库、不写操作记录、不改文件，也不产生临时文件；可取消，结果只缓存在内存（最近 5 条）。
- 候选：`bpp < 0.12`、输出 JPEG 时带 alpha、以及样本解码后确认的 16 位源会被跳过。`optimized_at` 标记在 schema v6（批次 2）接入，因此当前「已处理过」计数恒为 0。
- 抽样：按「有损源 / 无损源 × 6 个 bpp 桶」交叉分层，样本量按候选体积分配且每层至少 3 张；样本真实解码并按阶梯质量编码，回解码后计算 PSNR 与局部坏点占比。PSNR 底线随源类型分两套（有损 / 无损），坏点占比只作诊断，不参与裁决。
- 外推：每层用样本的 `Σ新字节 / Σ原字节` 得到节省率，再乘以该层候选总体积；跳过分类（画质不达标、省得太少、16 位、失败）按样本比例外推。误差用分层 bootstrap（300 次）。
- 输出：候选张数与体积、处理/跳过占比（按张数，图例同时给体积）、跳过分类明细、预计节省与误差、预计耗时、样本质量分布、收益曲线、分文件夹明细、样本失败清单（最多 20 条）。
- 收益曲线：横轴是已处理的候选体积占比，纵轴是累计节省；按执行顺序（bpp 从高到低）累加，每个点带 `elapsedSeconds`，耗时按像素折算而不是按体积线性分摊。界面上标注 20% / 50% / 100% 三个里程碑，并在曲线右侧列出各自的累计节省与耗时。
- 命令：`start_batch_task` 的 `kind = "optimizeEstimate"` 携带 `optimize` 与 `estimateSampleSize`；结果用 `get_optimize_estimate(taskId)` 读取。
- 实现：判据、阶梯编码、PSNR/坏点、EXIF/ICC 搬运与去 Orientation 在 `src-tauri/src/imageops/optimize.rs`；分层、抽样、外推在 `src-tauri/src/library/optimize_estimate.rs`；任务与结果缓存在 `src-tauri/src/app/state.rs`；界面在 `src/app/OptimizeDialog.tsx`，占比环图与收益曲线在 `src/app/OptimizeCharts.tsx`。

## 临时文件

- `.artbank/temp/` 只放原子写入与编辑中间文件；打开图库时清理一次。
- 导入/保存崩溃后可能留下 temp 文件；清理只删除 temp 目录内文件，不触碰原图。
- 删除类操作先写待释放标记；记录过期或清空操作记录后，`ReleaseGarbage` 任务按批次删行、删文件，失败留下标记并在下次任务中重试。
- 一次释放按 400 张一块：块内先提交删行事务，再删文件；释放任务本身不可取消，卡在块边界也不会留下半删的行。
- `.artbank/undo/` 存放编辑等操作的暂存文件；打开图库时删除没有对应 `operations.id` 的目录。

## 图库管理

- 添加/打开/切换/关闭/移除见 [图库与元数据](library.md)。
- 移除只移除列表项，不删除文件；UI 必须明确提示。
- 重命名只改显示名与清单名称，不改目录名。
- 不支持在应用内删除整个图库目录；用户可在资源管理器中自行处理。

## 导出

- 导出选中图片到用户选择的目录：复制原图，保留扩展名；可选导出元数据 JSON/CSV。
- 导出不修改图库；目标目录已存在同名文件时默认跳过并报告，不静默覆盖。
- 大文件导出走流式复制，显示进度与取消。

## 验收

- 孤儿扫描只移动孤儿，不误伤正常文件；DB 行缺失原图时能显示。
- 缩略图压缩后所有可见缩略图仍能加载，旧 segment 被删除，`thumb_version` 正确。
- 完整校验能发现人为改坏的原图；快速检查不会误报大小相同的篡改。
- 描述回填按哈希匹配，不依赖旧哈希或扩展名；空描述默认不被覆盖。
- 所有长任务可取消，取消后图库一致、临时文件可清理。
