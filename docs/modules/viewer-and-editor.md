# 查看器与图像处理

查看器负责“看”和“轻度几何编辑”；图像处理负责色彩/LUT/频域/卷积。两者最终都通过同一条“新内容发布”路径写回图库。

## 查看器

入口：双击缩略图或列表行，Enter 打开。视图覆盖主工作区，Esc 关闭。

能力：

- 适应窗口 / 1:1 / 滚轮缩放 / 拖拽平移。
- 上一张/下一张：按当前视图的结果顺序，不重新查询全库。
- 顺时针旋转 90°、水平翻转、垂直翻转；仅影响显示与最终保存，不立即改文件。
- 裁剪：在显示坐标上画矩形，换算到原图像素坐标；保存时由 Rust 执行。
- 调尺寸：输入目标宽高或比例；可选输出质量与格式（JPEG/PNG/WebP）。
- 复制图片到剪贴板、拖出到资源管理器（后续）。
- 元数据侧栏：标签、评分、描述、文件夹、哈希、尺寸、导入时间、主色。
- 姿势叠加：有 pose 数据时用 SVG/Canvas 画 33 点骨架；没有时提供“检测姿势”按钮（调用 AI 服务）。
- 全屏模式。

大图：浏览器 `<img>`/`createImageBitmap` 加载原图。超过设定像素数的图片可使用降采样预览（按需生成），编辑保存仍使用原图。

## 保存语义（重要）

编辑保存不是“覆盖原文件”，而是：

1. Rust 读取原图，应用几何/处理操作，得到新像素。
2. 编码到 `.artbank/temp/`，同时计算 BLAKE3。
3. 若新哈希与**另一张**图片冲突：拒绝保存并提示（不自动合并）。
4. 若新哈希与当前图片相同：内容未变，不产生新文件（元数据可照常保存）。
5. 发布新文件 `<folder>/<newHash>.<ext>`；写新缩略图到 pack，重算 pHash/主色，更新宽高/大小/格式。
6. 在同一个写事务里更新 `images` 行（id 不变）；提交后删除旧文件（若没有其他行引用）。
7. 清除该图的 embedding 与 pose（内容已变），保留标签、评分、描述、集合引用。描述是否保留由用户选择，默认保留。

崩溃安全：新文件先落 temp 并同步，rename 后才改 DB；最坏情况留下孤儿文件，由维护任务清理。不会出现“DB 指向不存在的文件”。

查看器的旋转/翻转/裁剪只保存一次；图像处理的参数链也只在用户点保存时落到全分辨率。

## 图像处理

参考原 `image_editor`，但把“全分辨率 Mat 快照栈”改为“参数化操作链”。

### 操作

| 操作 | 参数 | 说明 |
| --- | --- | --- |
| 色彩变换 | 输入/输出 gamma，3×3 RGB 矩阵 | 在去 gamma 的线性空间做矩阵，再回 gamma |
| LUT3D | `.cube` 文件、强度 0-1 | 三线性插值 |
| 频域滤波 | 频率曲线（控制点）、强度 0-1 | 在 Lab-L 通道做 DFT，按径向频率曲线缩放幅度，再 IDFT |
| 卷积 | 7×7 核、强度 0-1、预设 | 在 Lab-L 通道卷积；预设来自设置/内置 JSON |

后续可加：曲线、色温、锐化。先保证原功能。

### 预览

- 预览在**降采样副本**（最长边约 1280px）上由 Rust 渲染，返回 JPEG/WebP 字节或临时文件 URL。
- 参数变化防抖（约 80-120ms）；只允许一个预览任务在跑，新请求取消旧任务。
- 预览与最终保存调用同一份算子实现，保证 WYSIWYG；不在前端用 CSS/WebGL 复制算法。
- 1MP 预览的色彩变换/卷积通常在数毫秒到数十毫秒；DFT 较慢，单独显示“计算中”。
- 操作链是数组 `[{kind, params}]`；撤销/重做移动索引，不保存像素副本。
- 预览可从最近一次中间结果继续，但缓存只保留有限步，内存有上限。

### 保存

- 把操作链应用到全分辨率原图；按目标格式编码。
- 与查看器共用“新内容发布”流程。
- 原图格式不支持透明/高位深时，按输出格式转换；转换规则在 UI 中显示。
- 失败时保留编辑会话，用户可以继续改或另存。

## 独立编辑器

原软件有独立的“图像处理”窗口，可从剪贴板/文件载入。这里保留为同一编辑器组件的“独立会话”：

- 不绑定 `images` 行时，“保存”走“另存为文件”而不是更新图库。
- 绑定图片时走上面的图库保存。
- 不引入第二套算子实现。

## 验收

- 旋转/翻转/裁剪/调尺寸保存后：缩略图、pHash、主色、宽高、大小全部更新；标签/评分/集合不变；旧文件被清理。
- 编辑后的图在查看器中立即显示新内容；浏览器缓存通过 `thumb_version` 失效。
- 预览与保存结果在相同参数下逐像素一致（允许编码误差；比较时解码后比较）。
- 撤销/重做 50 步不产生全分辨率像素副本，内存稳定。
- LUT/DFT/卷积在 4K 图上保存耗时可接受（目标 <2s，DFT 可更慢），保存期间 UI 可继续浏览。
- 大图（>50MP）不会一次性无上限分配内存；超过限制给出可行动错误。
