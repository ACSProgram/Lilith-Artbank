# 分阶段路线图

本文是 2026-09-05 迁移分析报告的替代执行计划。旧报告已归档到 `planning/archive/2026-09-05-ImageLibrary迁移分析报告.md`；它的背景分析仍可读，但结论以本文为准。

## 决策摘要

- 只做图库本体：导入/去重、浏览、元数据、筛选排序、集合、回收站、查看器、裁剪/旋转/调尺寸、图像处理、维护。
- 不做 PinBoard/PasteBoard/ImagePaste、调色盘、色彩测试、截屏小工具。
- 元数据 SQLite；原图 BLAKE3 内容寻址；缩略图追加式 pack；浏览器解码 WebP/JPEG。
- AI（description/embedding/pose）走本机 HTTP `/v1`；应用托管服务进程，但本阶段不打包 Python 环境。
- 不读旧 `.data`，不做应用内数据迁移；迁移脚本后续单独立项。
- 无公开版本号、CHANGELOG、LICENSE/法务材料。

## 与旧报告的差异

| 主题 | 旧报告 | 现在 | 原因 |
| --- | --- | --- | --- |
| 元数据 | SQLite | SQLite（确认） | 20 万行实测：首屏 0.12ms、深分页 0.53ms、FTS 0.48ms |
| 缩略图存储 | 逐文件 WebP + 分片目录 | 追加式 `.pack` + DB 指针 | 150×20KB 随机读 pack 0.60ms vs 逐文件 9.69ms；避免 20 万小文件 |
| 缩略图显示 | 浏览器 `<img>` 解码 | 浏览器 `<img>` 解码（确认） | 150 张 512px 冷加载 0.44-0.46s，远低于 1s |
| DDS/BC | 删除 | 不引入 | 浏览器解码已达标，WebGPU 自绘不划算 |
| 图片身份 | pHash 当主键 | BLAKE3 内容哈希 + 稳定 id；pHash 只做相似度 | 编辑后哈希会变；标签/集合必须引用稳定 id |
| 编辑历史 | 全分辨率 Mat 快照 | 参数化操作链 + Rust 降采样预览 | 内存稳定，预览与落盘同一实现 |
| AI | 可选后置 / 旁路服务 | 统一本机 HTTP 服务，应用托管进程 | 用户决定；离线不影响图库 |
| 小工具 | 可不迁 | 明确不做 | 项目定位是素材管理，不是绘画辅助 |
| 数据迁移 | 一次性导出工具 | 仍是一次性脚本，但不进应用、不在本阶段 | 避免应用长期背旧格式 |
| 大库策略 | 分层缩略图目录 | 追加 pack + 键集分页 + 不整库载入 | 目标 20-50 万张、数百 GB |

## 阶段总览

| 阶段 | 内容 | 新增代码预算 | 依赖 |
| --- | --- | --- | --- |
| S0（已完成） | 工程骨架、设置、图库生命周期、schema v1、应用外壳、初步基准 | ~2.5k | — |
| S1 | 性能原型 + 导入与缩略图管线 | ~3k | S0 |
| S2 | 虚拟化网格/列表、查询与选择 | ~3k | S1 |
| S3 | 元数据编辑、搜索/筛选/排序、集合、回收站 | ~3k | S2 |
| S4 | 查看器与几何编辑 | ~2.5k | S2 |
| S5 | 图像处理（色彩/LUT/DFT/卷积） | ~2.5k | S4 |
| S6 | AI 服务托管与批量任务 | ~2.5k | S3 |
| S7 | pHash/颜色/CLIP/pose 相似度与高级集合 | ~2k | S6 |

“新增代码”指新增实现行数，不含文档、生成文件与测试数据；每阶段应落在 2-3k，超过就拆，低于 2k 可与相邻阶段合并。阶段结束必须通过验收再进入下一阶段。

## S0 工程骨架（已完成）

- Tauri 2 + React 19 + TypeScript + Vite 6；无边框自绘标题栏、深色工作台、通知/确认弹窗。
- 设置持久化（图库列表、AI 参数、性能参数、界面参数）。
- 图库清单、SQLite schema v1、单写多读连接池、图库创建/打开/关闭/移除/重命名。
- 欢迎页、图库入口、设置页、浏览器预览 mock。
- 初步性能基准：20 万元数据、缩略图 pack vs 文件、Chromium 解码。

验收：`npm run typecheck`、`npm run build`、`cargo check`、`cargo test` 通过；浏览器预览可创建/打开图库；真实 Tauri 窗口待用户手动验收。

## S1 性能原型 + 导入与缩略图管线

**目标**：先把“150 张缩略图在真实 Tauri 窗口 ≤1s”钉死，再完成导入内核。

前半（性能原型，~0.8k）：

- 注册 `thumb://` 自定义协议，从 pack 按偏移读字节，带正确 MIME 与缓存头。
- 写一个最小 pack 写入器/读取器与 150 张触发页面；在真实 WebView2 窗口测冷/热加载。
- 验证 WebP 编码方案：优先静态链接 libwebp；确认发布产物无额外 DLL；失败则回退 JPEG/PNG。
- 门槛：150 张 ≤1s（硬上限 3s）；缩略图包读取不慢于本地文件；启动不载入全量元数据。未达标先调整方案，不进入后半。

后半（导入，~2.2k）：

- 文件/目录/拖放/剪贴板输入；导入参数（文件夹、标签、评分、重复策略）。
- 流式 BLAKE3 + 临时文件 + 原子发布；EXIF 方向；解码上限。
- 512px 缩略图、256 位 pHash、4/8 主色；缩略图追加到 pack 并写 DB 指针。
- 精确重复跳过/合并；感知重复提示；批内去重。
- 后台任务：rayon 工作池、单写通道、进度事件、取消、失败清单。
- 导入 UI：队列、进度、结果、失败详情。

验收：

- 1,000 张混合格式导入不冻结 UI；取消后已完成项一致、临时文件可清理。
- 精确重复只保留一行；感知重复只提示。
- 缩略图指针完整；删除 pack 后显示占位而不是崩溃。
- 导入吞吐至少 20 张/秒（开发档，含特征与缩略图）；实测写入性能文档。

## S2 虚拟化网格与列表

**目标**：20 万行元数据下滚动稳定，前端不持有全库数组。

- 查询引擎：`LibraryQuery`、键集游标、基础筛选（文件夹/扩展名/评分/标签）、排序（评分/时间/大小）、分页。
- 命令：`query_images`、`get_filter_counts`、`get_folders`、`get_tags`（基础版）。
- 前端：虚拟化网格（列数/尺寸自适应、视口前后预取）、列表视图、缩略图协议、占位/失败重试。
- 交互：单击/Ctrl/Shift/Ctrl+A、右键菜单、Enter 打开查看器（占位）、Delete 待 S3、键盘滚动。
- 拖出到资源管理器（Windows OLE）评估；失败则提供复制图片/路径。
- 请求竞态：请求代次、过期结果丢弃、错误重试。

验收：

- 20 万条合成库滚动 60fps 目标；DOM 节点只保留视口 + 缓冲。
- 首屏/深分页/文件夹/标签查询满足预算（见性能文档）。
- 一页 150 张缩略图在真实窗口 ≤1s。
- 切换筛选/排序不残留旧页。

## S3 元数据、搜索、集合与回收站

**目标**：把图库变成可管理、可检索的素材库。

- 详情侧栏：查看/编辑评分、标签、描述、文件夹；复制哈希/描述；主色展示。
- 批量编辑：共同文件夹/评分/标签；标签增删；文件夹移动（原子 rename + DB 更新）。
- 标签与文件夹：自动补全、计数、按标签/文件夹筛选；标签重命名/删除的全局影响提示。
- 搜索：FTS5 trigram；少于 3 字回退 `LIKE`；当前视图/全库切换。
- 筛选面板：文件夹、扩展名、评分、标签（any/all）、时间/大小、有描述/有 embedding/有 pose、颜色与 pHash 相似度（基础）。
- 排序菜单：评分、导入时间、大小、pHash/颜色相似度（目标图）。
- 集合：新建/重命名/删除/排序、加入/移出、交集/并集/差集、视图撤销。
- 回收站：软删除、恢复、清空（危险确认）、永久删除。

验收：

- 组合筛选结果正确；计数与列表一致；FTS 中文子串可用。
- 批量编辑只影响选择集；文件夹移动失败可回滚。
- 集合引用 id，图片编辑换哈希后仍保留。
- 回收站删除/恢复/清空语义清晰；清空后原图与缩略图指针都被清理。

## S4 查看器与几何编辑

**目标**：双击看图、旋转/翻转/裁剪/调尺寸并安全保存。

- 全屏查看器：适应窗口/1:1/缩放/平移、上一张/下一张、Esc、全屏。
- 几何编辑：90° 旋转、水平/垂直翻转、裁剪（显示坐标→原图坐标）、调尺寸/质量。
- 保存：新 BLAKE3 → 新文件 → 事务更新行 → 旧文件清理；重算缩略图/pHash/主色；清 embedding/pose；保留标签/评分/集合。
- 姿势叠加：有 pose 时画 33 点；无 pose 时按钮调用 S6 的 AI（先禁用）。
- 复制图片、拖出、元数据侧栏。
- 大图降采样预览与内存上限。

验收：

- 编辑 round-trip 后列表缩略图立即更新；浏览器缓存通过 `thumb_version` 失效。
- 标签/评分/集合保留；embedding/pose 清除；旧文件不残留（无其他引用时）。
- 大图不一次性无上限分配；失败有可行动错误。
- 预览与保存结果一致（几何操作应逐像素一致）。

## S5 图像处理

**目标**：保留原软件的图像处理能力，但更安全、可撤销。

- 操作：输入/输出 gamma + 3×3 RGB 矩阵、LUT3D（.cube）、Lab-L 频域曲线、7×7 卷积（含强度与预设）。
- Rust 预览：降采样（约 1280px）+ 防抖 + 单任务；预览与保存共用算子。
- 操作链撤销/重做（不存全分辨率像素）；日志/参数面板。
- 保存：全分辨率应用操作链，走 S4 的新内容发布流程。
- 独立会话：从剪贴板/文件载入，不绑定图库时“另存为”。

验收：

- 预览与保存结果一致（允许编码误差）。
- 50 步撤销内存稳定；4K 保存 ≤2s（DFT 可更慢）。
- LUT/卷积预设可复用；失败保留会话。
- 不引入第二套算子实现。

## S6 AI 服务托管与批量任务

**目标**：description / embedding / pose 可用，服务离线时图库不受影响。

- 设置：baseUrl、executablePath、port、autoStart；进程启动/探活/重启/退出/日志。
- HTTP 客户端：`/v1/health`、`/v1/models/ensure`、`/v1/embed/image`、`/v1/embed/text`、`/v1/pose`、`/v1/describe`；超时/重试/取消。
- 任务：为选中/当前视图/缺失项生成 embedding、pose、描述；进度、取消、失败清单；默认只填空描述。
- 存储：feature pack + `feature_blobs`；描述写 `images.description`，带 source/model。
- 语义搜索 UI：text→embedding→本地余弦扫描；结果按 id 回页。
- 离线：AI 按钮禁用，显示状态与错误；不阻塞本地功能。
- mock server 测试：成功、400、422、503、超时、重试、取消。

验收：

- 批量任务完成/取消/失败行为符合文档；已完成结果保留。
- 用户手写描述不被“只填空”覆盖；`description_source` 正确。
- 语义搜索只用同 model/dim 向量；结果可分页。
- 真实服务接入由用户手工验证；服务关闭时应用正常。

## S7 相似度与高级集合

**目标**：找相似、按相似度排序、集合运算在 20 万级可用。

- pHash：常驻紧凑数组，SIMD/位运算扫描；目标图相似、全库相似对（LSH/BK-tree 或分桶）避免 O(n²)。
- 颜色：4/8 色加权距离；目标图筛选与排序。
- CLIP：同 model/dim 的 image embedding 余弦；文本搜索已在 S6，补相似图片。
- Pose：33 点相似度，沿用原软件的权重概念（躯干/四肢/轮廓/角度容差）。
- 集合高级：交集/并集/差集、保存为集合、视图撤销、从当前筛选创建集合。
- 结果缓存：同一目标/查询的结果在内存缓存，失效条件明确。

验收：

- 20 万 pHash 单目标扫描 <50ms；全库相似对分组可接受（不 O(n²) 卡死）。
- 颜色/CLIP/pose 排序不阻塞 UI；向量扫描内存可控。
- 集合运算结果正确、可保存、可撤销。
- 目标图编辑后相似度缓存失效。

## S8 维护、批量工作流与体验补全

**目标**：长期使用的清理、重建、导入导出与快捷键。

- 描述导出/回填：`output/<content_hash>.<ext>` + `<content_hash>.txt`；manifest 可选。
- 孤儿文件扫描/移动、缺失文件报告、清理账本重试。
- 缩略图重建、缺失补建、pack 压缩；特征包清理/重算入口。
- 库检查：快速（存在/大小）与完整（BLAKE3）；结果可导出。
- 导出选中图片到目录；批量元数据编辑增强。
- 快捷键总表、日志/诊断入口、设置页补全、浅色主题（可选）。
- 多图库切换体验、最近库、错误恢复。

验收：

- 孤儿扫描不误伤；清理账本可重试。
- 缩略图压缩后所有指针有效；旧 segment 删除。
- 完整校验能发现篡改；快速检查不误报。
- 长任务可取消；取消后库一致。
- 用户按快捷键表完成一次完整工作流（手工验收）。

## S9 规模化验收、性能硬化与打包

**目标**：在 20-50 万张规模上交付可用的单文件 exe。

- 20 万条合成库 + 真实小样本（复制到临时目录）；冷/热启动、滚动、筛选、缩略图、导入、导出。
- 冷磁盘缓存测量；WebView2 自定义协议复测；内存峰值；GDI/句柄/线程数。
- 崩溃/取消/断电语义检查（不承诺断电自动化验证）。
- 打包：release 构建、单 exe、确认无额外 DLL；WebView2 系统运行时依赖写入文档。
- 最终 UX 打磨、空状态、错误文案、可访问性基础。
- 更新架构/性能/交接文档。

验收：

- 性能预算全部满足；一页 150 张 ≤1s（硬上限 3s）。
- 20 万级滚动与筛选无明显卡顿；内存不随总量线性增长。
- 单 exe 在干净 Windows 11 上可启动；除 WebView2 系统运行时外不需要用户安装 DLL。
- 用户完成手工验收；路线图归档。

## 风险与待定

- WebP 编码器构建（libwebp 静态链接 vs 纯 Rust）在 S1 决定；若引入 DLL 必须先征得用户同意。
- 拖出到资源管理器在 WebView2 中需要 Windows OLE，S2 评估；失败则保留复制路径。
- 真实美术图的 pHash 阈值与主色算法需要样本调参；S1/S7 用真实小样本验证，不修改真实库。
- 语义搜索内存（200k×1024 f32 ≈ 800MB）需要实测；可能改用 f16/分块。
- 大图解码内存上限与 EXIF 方向在 S1 定稿。
- 描述回填的旧外部流水线格式（`output/<hash>.txt`）在新结构下使用内容哈希，需要迁移脚本配合；应用内只认新格式。
