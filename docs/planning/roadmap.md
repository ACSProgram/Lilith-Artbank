## 已定方向

这些结论已落在代码与[系统架构](../architecture/overview.md)里，后续阶段不再重新讨论：

- 只做图库本体：导入/去重、多级文件夹、浏览与检索、元数据、集合、回收站、操作记录与撤销、查看器、裁剪/旋转/调尺寸、维护与压缩。
- 不做 PinBoard/PasteBoard/ImagePaste、调色盘、色彩测试、截屏小工具；图像处理（色彩/LUT/DFT/卷积）已取消。
- 元数据 SQLite；原图 BLAKE3 内容寻址；缩略图与特征都是追加式 pack；浏览器负责解码。
- AI（embedding/pose/description）走本机 HTTP `/v1`，应用托管 Python 进程；`server/` 随便携包分发，Python 环境与模型由用户放入程序目录。
- image/text embedding 用 `siglip2-giant-opt-patch16-384`，1536 维、fp16 落盘，检索前减全库均值；向量走 mmap 扫描。
- pose 相似度按原程序 1:1 移植，权重与索引不得自行改动。
- 不读旧 `.data`，应用内不做旧库迁移。
- 不做公开版本号、CHANGELOG、LICENSE/法务材料。

## S9 规模化验收、性能硬化与打包

**目标**：在 20–50 万张规模上交付可直接运行的便携文件夹。

- 20 万条合成库 + 真实小样本（复制到临时目录）：冷/热启动、滚动、筛选、缩略图、导入、导出。
- 冷磁盘缓存测量；WebView2 自定义协议复测；内存峰值；GDI/句柄/线程数。
- 前端已加载页回收（长时间滚到全库末尾时内存不随已加载行增长）。
- 崩溃/取消/断电语义检查（不承诺断电自动化验证）。
- 打包：release 构建、单 exe、确认无额外 DLL；`npm run pack:portable` 产出 exe + `server/` 的便携文件夹，不生成 NSIS；`python_embeded/` 与 `resources/models/` 由用户放入。
- 最终 UX 打磨、空状态、错误文案、可访问性基础。

验收：

- 性能预算全部满足（见[性能基准](../guides/performance.md)），一页 150 张 ≤1s（硬上限 3s）。
- 20 万级滚动与筛选无明显卡顿；内存不随库总量线性增长。
- 单 exe 在干净 Windows 11 上可启动；除 WebView2 系统运行时外不需要用户安装 DLL。
- 用户完成手工验收；本文件与相关计划一并归档。

## 风险

只列影响 S9 的开放风险；已关闭的取舍见[系统架构](../architecture/overview.md)的“关键取舍记录”。

- **pack 分段策略**：默认 1 GiB/段在 20 万张、真实缩略图体积下的段数、句柄与回收窗口未实测，S9 前用真实样本定。
- **SigLIP2 50 万条**：1536 维 fp16 向量包约 1.6 GB，检索走 mmap 顺序扫描，冷页缓存行为与耗时未知；超出预算再评估 ANN。
- **前端已加载页不回收**：长时间滚到全库末尾会让内存随已加载行增长，S9 处理。
- **分面计数边界**：2 字搜索与超大集合仍超 100 ms 预算，靠筛选面板加载态兜底；真实库的 `filter_counts` 标签分支是连接地板（见性能文档），S9 前视需要决定是否拆分请求。
- **完整校验的真实耗时没有测过**：758 GB 按 500 MB/s 是 25 分钟，但 G: 盘的实际顺序读带宽未知，机械盘可能超过 1 小时。第一次全库跑完要把实测值写进[性能基准](../guides/performance.md)。
- **空闲回收会和用户抢磁盘**：3 分钟阈值意味着「开着窗口发呆」也会触发；让位能在 1–2 秒内停手，但已复制的那部分作废（最多白费一个段的 IO）。真实用起来觉得烦就把阈值调到 5 分钟，或在设置里关掉自动回收。
- **描述能力**：需要视觉语言模型与对应加载代码，`/v1/describe` 契约保留但本轮不实现。
- **真实窗口验收欠账**：S1–S8 与各插入批次的大量界面行为只过了自动检查，用户手工验收仍是各阶段的出口条件，清单在[待办](todo.md)。
