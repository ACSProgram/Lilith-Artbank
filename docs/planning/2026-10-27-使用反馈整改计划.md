- 统一 `DataChange` + `planDataChange`：一次写入只推进真正需要失效的面板，不再让所有面板订阅同一个版本号。
- 排序与数据刷新保留旧行、重取已加载范围、按活动图锚定滚动；只有换结果集才清空列表、回到顶部、清空选择。
- 本地写入按已知 id 精确剔除选择；外部任务/MCP 的范围变化清空选择；相似参考、比较图与查看器活动图主动复核。
- 新增只读命令 `get_image_states`；`library-changed` 携带结构化 `change`；权限、确认队列与执行路径未变。
- 已确认的四条决策（保持滚动并锚定、外部变化清空选择、参考图失效即移除、估算保留并提示复核）见归档记录的“已确认决策”，后续批次按此口径。

### 批次 2：详情与批量编辑

- 详情信息顺序按反馈调整；描述从“常驻编辑框”改为“只读展示 + 编辑态”。
- 编辑态出现保存、AI 生成、取消；复制在只读与编辑态都可用。进入/退出编辑不丢草稿，除非用户明确取消。
- 主色按权重比例展示，给最小宽度；保留精确百分比的可读入口。
- 批量标签：读取选中图片的共同标签并展示；点击即移除；添加走统一标签输入（自动补全、去重、数量上限）。
- 导入标签复用同一输入与解析规则，去掉“逗号分隔”的文案与实现。
- 不做：不改标签 schema；不做标签层级/分类；不改变批量操作的撤销记录粒度。

### 批次 3：文件夹树与会话状态

- 文件夹排序从“常驻模式”改为“一次性动作”：右键某个文件夹，对其子文件夹排序，可选是否递归；排序结果写回手动顺序。
- 虚拟入口用于“只看该文件夹直属图片”，与现有“包含子树”筛选区分；UI 形式在批次开始时定。
- 多选文件夹拖动支持一次移动到目标文件夹或一次调整同级顺序；与图片多选拖动、Shift/Ctrl 选择、悬停展开兼容。
- 持久化窗口位置、大小、最大化状态与文件夹展开集合；异常屏幕布局要能回退到默认。
- 顺带核对 `FolderDelete` / `FolderMove` 记录标题不带路径的问题，若改动小则纳入。
- 不做：不改文件夹物理目录布局；不做跨库拖放；不保留旧的常驻排序模式作为隐藏选项。

### 批次 4：后台任务健壮性与并发

- 任务线程 panic、线程启动失败、任务体提前返回都必须让任务进入终态，并释放 lane 与操作记录。
- 明确 release 下 `panic = "abort"` 的可观测性边界：哪些异常能兜底，哪些只能留下日志。
- 重新定义并发：写任务排队、拒绝还是合并；AI/扫描是否继续并行；前端如何显示排队/冲突。
- 任务历史：确认“清空记录”的对象，决定是否增加清空入口与可释放内存/记录数展示。
- AI 服务崩溃是否自动重启作为决策项评估，本批先不实现；`ai::job` 的偶发失败补测试隔离。
- 不做：不改 SQLite 单写连接；不引入外部任务队列；不把长时间写任务拆成无协调的并行写。

### 批次 5：MCP 接口一致性与规则自描述

- 列表分页：优先 `tags_list` 与 `folders_list`，补稳定的 `nextCursor`/`total`；保留默认按图片数排序、名称搜索与安全上限。
- 顺带核对 `history_list`、`collections_list` 是否需要同样的游标；`search_images`、`find_similar`、`image_sheet` 已是分页接口，不重做。
- 规则自描述：`library_info` 明确区分三档、阈值只在询问档生效、完全档不进入确认队列、只读档没有写入能力；服务端 instructions 与写工具描述统一口径。
- 标签筛选：评估 `tagPresence: any/has/missing` 与 `excludeTagIds`，并决定是否同步到浏览界面，避免 MCP 与界面两套语义。
- 分面：确认“标签分面不应用 tagIds”是标准自排除行为；默认不改，只在输出/文档中说明，必要时增加显式收窄参数。
- 标签管理：重命名/删除可做 MCP 平价；合并需要先定关系迁移、去重、源标签删除与撤销语义，并决定是否同时补界面。
- 不做：不改变三档权限模型与 100 张阈值本身；不开放永久删除、清空回收站、压缩、像素编辑或普通图库批量 AI；不为了分页放宽单页上限。
- 退出标准：超过 500 个标签/子文件夹可以完整遍历；AI 能正确复述完全档与询问档的差别；标签缺失/排除过滤有明确语义；标签管理写入进入操作记录并可撤销。

### 批次 6：性能专项

- 语义搜索冷启动：分开测服务进程、文本塔加载、文本编码、均值计算、均值重复计算、全库向量扫描、分页取图。
- 均值缓存：普通 embedding 写入、临时区特征、模型切换后的失效与持久化策略。
- 移动：分别测图片逐张 rename/更新、文件夹目录 rename、历史记录写入、文件夹计数重算、前端刷新。
- 筛选与计数：打开筛选面板拉标签、无筛选分面计数、子树分面计数、集合计数；区分 SQL、IPC/JSON 与渲染。
- 大库体验：20 万/39 万行首屏、翻页、滚动、内存、已加载页回收、常驻视觉索引内存。
- 决定 `temp/viewer/` 预览缓存是否需要 LRU 或体积上限；只在实测累积速度后决定。
- 只在基准证明必要时加缓存/索引；每个热点补性能文档与基准。
- 不做：不提前上 ANN；不做全量内存化；不用跨机器墙钟比较。

### 批次 7：压缩估算准确性

- 先复现“时间低、节省空间也偏”的组合偏差，确认用户使用的抽样档位与实际样本像素分布。
- 检查“跨层按体积、层内按张数”的抽样是否让重尾大图长期缺席；检查耗时按像素外推与节省率按字节聚合是否共用同一偏差。
- 评估按像素/尺寸分层、层内按体积加权、提高上限或自适应抽样；输出时间与节省空间的误差范围。
- 执行前校验扩展：候选数量/体积之外的目录消失、文件消失、内容变化、范围变化。
- 真实库回测：大图占比高与大图占比低两种范围，各跑估算与实际执行对比。
- 不做：不把估算变成全量预编码；不承诺精确值；不引入新的临时文件依赖。

## 跨批次原则

1. 先测量，后优化。批次 1、6、7 都先留基线，再决定缓存、索引或抽样策略。
2. 数据变化必须回答“谁失效、谁保留”。不允许以“全量刷新”作为默认答案。
3. 所有暂存/快照都要有代次、版本或指纹；没有的，至少在执行/展示前复核对象仍存在且范围未变。
4. 前端模块边界、Tauri 薄命令、SQLite 单写、真实库只读等既有约束不变。
5. 每批结束：自动检查、同步模块文档、用户真实窗口验收；代理不启动界面。
6. 不把“计划实现”写成“已经验收”；未完成事项继续写 `todo.md`。

## MCP 反馈评估：值得改与保持不动

| 编号 | 结论 | 说明 |
| --- | --- | --- |
| M1 | 值得改 | `tags_list` 与 `folders_list` 的 500 条硬上限没有游标，超过上限的内容对 AI 完全不可达；这是能力缺口，不是有意的安全边界。保留排序默认与单页上限，只补稳定游标。`history_list` 的上限与操作记录最大步数相同，`collections_list` 的数据量通常较小，二者可按一致性补游标，但优先级低。 |
| M2 | 值得改，但不改权限行为 | 三档模型与“询问档超过 100 张需确认”是既定行为，应保持；问题在于 `library_info` 把 `approvalThreshold` 无条件展示，AI 会误以为完全档也受它约束。只改说明与返回字段，不改实际拦截逻辑。 |
| M3 | 值得改 | 标签缺失/排除是真实筛选能力缺口。需要先定语义并同步到浏览界面，否则 MCP 与界面会出现两套标签筛选。保留 `tagMode: any/all` 的既有行为。 |
| M4 | 不建议改默认 | 分面计数对自身维度排除当前筛选是标准分面搜索行为，改掉会让“选了一个标签后继续看其它标签计数”失效。应补文档与输出说明；确需收窄时增加显式参数，而不是改默认。 |
| M5 | 部分值得改 | 重命名/删除在界面已有，补 MCP 平价是合理的；合并连界面都没有，先定语义并决定是否同时补界面，避免出现只有 AI 能用的破坏性能力。 |

保持不动的 MCP 特性：

- 三档权限模型与“询问档超过 100 张需确认”的阈值本身；完全档不弹确认，只读档拒绝写入。
- 永久删除、清空回收站、图片空间优化、像素编辑、普通图库批量 AI 生成不开放；临时区特征生成是唯一例外。
- `dryRun` / `confirmedCount` 数量核对、一次调用一条历史记录、MCP 写入在进程内串行。
- `search_images` 单页 50、`images_get` 50 张、选择器上限、拼图格数等安全上限；分页不意味着放宽单页。
- `tags_list` 默认按图片数从高到低、不返回 0 张标签；`find_similar` 的单结果槽与 token 失效规则。
- 只读档不隐藏写工具，避免客户端缓存的 `tools/list` 因切档失效。

## 待决策

这些问题会实质影响行为或架构，进入对应批次前需要用户拍板。

1. **并发策略**：写任务冲突时应排队、快速失败，还是合并请求？用户更在意“立即知道不能做”，还是“提交后自动排队”？
2. **任务历史缓存**：任务界面里的“历史缓存”指后台任务记录、撤销记录，还是待释放文件？三者释放的资源量级不同。
3. **虚拟直属图片入口**：放在文件夹树内作为虚拟子节点，还是放在工具栏/面包屑作为“只看直属”开关？前者更直观但会增加树行数，后者不改变树结构。
4. **一次性文件夹排序**：排序依据只允许名称/图片数，还是也允许按当前手动顺序微调？递归时是逐层排序还是所有后代统一排序？
5. **描述编辑**：保存只靠按钮，还是失焦也保存？AI 生成是直接写入还是先进入草稿？空描述显示占位还是隐藏整段？
6. **批量标签**：共同标签为空时是否显示“无共同标签”；添加是否允许新建标签；一次最多添加多少个。
7. **抽样与误差**：是否接受“绝对张数档位”继续作为默认，还是改成比例档位？估算结果是否需要显示误差区间/置信提示？
8. **窗口持久化**：是否引入 Tauri 窗口状态插件，还是写进现有设置；多显示器变化时优先恢复位置还是优先保证窗口可见。
9. **MCP 分页语义**：统一用 offset 还是 keyset 游标；游标字段叫 `nextCursor` 还是沿用各工具现有命名；`tags_list` 按图片数排序时如何保证翻页不重不漏。
10. **MCP 标签排除**：是增加 `tagPresence: any/has/missing`、`excludeTagIds`，还是扩展 `tagMode: none`；是否同步到浏览界面，避免 MCP 与界面两套筛选语义。
11. **MCP 标签管理**：重命名/删除是否只做 MCP 平价；合并是否同时补界面；合并时图片关系迁移、重复关系去重、源标签删除与撤销记录如何定义。
12. **MCP 标签分面**：保持“标签分面不应用 tagIds”的默认行为并只补说明，还是增加一个显式的“按当前 tagIds 收窄”参数。
13. **MCP 规则呈现**：`library_info` 是否按档位返回 `approvalThreshold: null`，还是改成完整的 `approval: { mode, appliesInMode, threshold, alwaysApprove }`；是否让每个写工具回执带 `confirmationRequired`。

## 风险

- 批次 1 触及全局刷新与失效，回归面最大；需要先把“变化类别 → 失效对象”列全，否则容易修好闪烁、引入过期数据。
- 批次 3 的多选文件夹拖动与排序会同时影响选择、拖放、操作记录与撤销；需要先定一次提交的语义。
- 批次 4 若改变并发策略，可能把“快速失败”变成“长时间排队”，需要前端明确展示排队状态。
- 批次 6 的缓存/索引若没有基准支撑，容易把内存换成另一种卡顿。
- 批次 7 的抽样调整会改变用户看到的估算数字；需要同时解释误差，而不是只追求更接近实际。
- 窗口位置持久化在多显示器/远程桌面下容易恢复出屏幕外窗口，需要可见性回退。
- MCP 列表分页在标签计数/文件夹数量变化时可能出现重漏；需要稳定 tie-break 与明确的快照口径。
- MCP 标签合并是破坏性写入；如果只给 AI 开放而不补界面，会让能力边界不可见，必须在批次 5 先定语义与权限。
