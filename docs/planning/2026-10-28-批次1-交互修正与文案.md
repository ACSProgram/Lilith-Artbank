## 已确认决策

| 问题 | 结论 |
| --- | --- |
| 图片拖到文件夹行的落点 | 图片载荷整行都算 `inside`；文件夹载荷仍按上 25% / 中 50% / 下 25% 判定 `before` / `inside` / `after`，保留同级排序。 |
| “直属图片”伪行 | 接受图片拖放，等同拖到它的父文件夹；不接受文件夹拖放（经过时无高亮、松手不移动）。这样既补上死区，也不把“父文件夹与直属行之间”变成一个含义模糊的排序位置。 |
| 详情与批量的回收站操作 | 由当前是否回收站视图决定，单图、多选、查看器详情一致：普通视图只显示“移入回收站”，回收站视图只显示“恢复 / 永久删除”。 |
| 导入运行中的弹窗 | 保持模态阻塞，不改非模态；只修文案与重复标题。 |
| 描述编辑框 | 按内容自动撑高，至少不低于只读态高度；输入时同步调整；去掉右下角手动缩放，避免下一次输入把手动高度覆盖。详情栏自身滚动。 |
| “清除筛选” | 改为次要按钮并加清除图标；“清除搜索”暂不同步，等真实窗口看整体平衡后再定。 |
| 后端与数据契约 | 五项都不改 Tauri 命令、SQLite、`DataChange` 或任务契约；只改前端组件、样式与一个纯函数测试。 |

## 一、现状核对

### 1.1 图片拖到文件夹的判定区（编号 5）

拖放控制器在 `src/shared/useDragSort.ts`：

- `resolveTarget` 用 `elementFromPoint` 找最近的 `[data-drop-root]` / `[data-drop-folder]`，根行固定 `inside`，文件夹行按 `(y - top) / height` 分三段：`< 0.25` 为 `before`、`> 0.75` 为 `after`、其余 `inside`（`src/shared/useDragSort.ts:99`、`:107-110`）。
- 图片载荷只在 `inside` 时允许放置（`src/app/LibraryWorkspace.tsx:399-400`），`handleDrop` 里也有同样的早退（`src/app/LibraryWorkspace.tsx:290-291`）。
- 文件夹行本身整行都有 `data-drop-folder`（`src/modules/library/FolderTree.tsx:442-443`），所以“命中”确实是整行，问题只在位置判定。

后果：

- 文件夹行按 `padding: 5px 8px`、12px 字号计算，行高约 26–28px，上下各 25% 只有约 7px。图片拖到行上边缘或下边缘会得到 `before` / `after`，被 `canDrop` 拒绝：没有高亮，松手也不移动。用户感知到的可落区域只剩中间约一半。
- “直属图片”伪行（`src/modules/library/FolderTree.tsx:490-512`）只有 `folder-tree-row` 类，没有 `data-drop-root` / `data-drop-folder`，也不是文件夹拖动的起点。拖图片经过它时 `resolveTarget` 返回 `null`，形成一条完整的死区；它又紧贴在父文件夹行下方，进一步压缩了父文件夹行下半部分的有效面积。
- 文件夹拖动的 `before` / `after` 是必要的：它承担同级排序与跨父级插入（`src/app/LibraryWorkspace.tsx:346-375`），不能一起去掉。

### 1.2 单图与多选的回收站操作（编号 6）

- 单图按图片自身的 `deletedAt` 决定按钮：未删除只显示“移入回收站”，已删除显示“恢复 / 永久删除”（`src/modules/library/Inspector.tsx:863-884`）。
- 批量无条件同时渲染三个按钮（`src/modules/library/Inspector.tsx:1385-1395`）。普通视图里多选活跃图片也会看到“恢复 / 永久删除”：恢复对未删除行不会产生变化，永久删除会被后端拒绝（`src-tauri/src/library/metadata.rs:1343-1348`），属于会失败的无效入口。
- 键盘删除已经按视图分支：普通视图移入回收站，回收站视图永久删除（`src/modules/library/LibraryView.tsx:1791`）。
- 右键菜单按每个菜单项的 `deletedAt` 显示“移入回收站”或“恢复 / 永久删除”（`src/modules/library/LibraryContextMenu.tsx:210-235`）。由于普通视图只查询未删除行、回收站视图只查询已删除行（全库搜索也排除回收站），当前不会出现同一菜单里两种状态混杂，行为与“按视图决定”等价。
- 查看器也复用同一个详情侧栏（`src/app/ViewerHost.tsx:119-153`），并且查看器可以停在回收站来源上（`src/shared/viewerSession.ts:44-45` 的 `expectTrashed`）。如果只改 `LibraryView`，查看器里的单图操作会与网格不一致。
- 文案：共同标签空时显示“没有共同标签”，部分标签折叠标题是“部分图片有”（`src/modules/library/Inspector.tsx:1260-1280`），与“全部 N 张都有 / 部分共同标签”的语义不成对。

## 二、目标行为

### 2.1 图片拖放

1. 图片拖到任意文件夹行的任何位置（上边缘、正文、下边缘、展开按钮、右侧计数）都解析为 `inside`，整行高亮，松手移入该文件夹。
2. 图片拖到根行“全部图片”仍是 `inside`（移到根目录）。
3. 文件夹拖动保持现状：上 25% 为 `before`、下 25% 为 `after`、中间 `inside`；悬停 600ms 自动展开只对 `inside` 生效。
4. “直属图片”行接受图片：解析为它所属父文件夹的 `inside`，整行高亮，松手把图片移入父文件夹。文件夹拖动经过该行不产生目标、不高亮、不展开、松手无动作。
5. 拖动过程中跟随指针的 ghost、Esc 取消、拖动后抑制一次 click、自动滚动都不变。

### 2.2 回收站操作

1. 普通视图：单图与多选都只显示“移入回收站”；不显示恢复与永久删除。
2. 回收站视图：单图与多选都只显示“恢复 / 永久删除”；不显示移入回收站。
3. 查看器侧栏跟随打开时的来源：从回收站打开的查看器只显示恢复/永久删除，从普通视图打开的只显示移入回收站。
4. 临时视图维持现状：不显示任何回收站操作，只显示临时区说明。
5. 右键菜单保持按项状态显示；由于视图与行状态一一对应，行为与 1–3 一致，不改菜单结构。
6. 文案“部分图片有 (N)”改为“部分共同标签 (N)”。

### 2.3 导入运行中

1. 标题继续承担阶段：运行中显示“正在扫描输入目录 / 正在导入 / 正在收尾”，完成页显示“导入完成 / 导入已取消 / 导入失败”，选项页仍是“导入图片”。
2. 副标题改为“导入完成前无法使用其他功能，可以取消导入。”
3. 正文 heading 删除阶段名，只保留当前文件与百分比；完成页不显示 heading 的现状不变。
4. `dismissible`、`handleClose`、遮罩、底部“取消导入”都不变。

### 2.4 描述编辑

1. 点“编辑描述”时，输入框高度**不小于只读正文高度**；长描述不再缩回。
2. 输入、删除、粘贴换行时高度随内容同步变化；空内容时回落到 84px 最低高度。
3. 取消/保存后回到只读 div，高度按正文自然恢复；不改变详情栏自身的滚动行为，不把工作区撑开。
4. 切图后编辑态仍按当前图片的草稿重新计算，不复用上一张的测量值。
5. 去掉手动拖拽缩放；`Ctrl/Cmd+Enter` 保存、失焦不保存等现有语义不变。

### 2.5 清除筛选

1. 摘要条里的“清除筛选”显示为带边框的次要按钮，并带清除图标；文字与图标都可点击。
2. 摘要条字号保持 10.5px，不为了按钮放大整条摘要；按钮沿用 `button-sm` 的 11.5px。
3. “清除搜索”暂时保持 ghost；等用户手工验收整体平衡后再决定是否同步。
4. 空结果态的 `primary` 按钮、筛选面板内的“清除筛选”都不变。

## 三、实现落点

### 3.1 拖放：按载荷类型与目标行类型解析

新增 `src/shared/dragModel.ts`，只放纯函数与类型：

```ts
import type { DragPayload, DropPosition } from "./useDragSort";

/** 图片只需要“移入”；文件夹拖动才需要上下边缘用于同级排序。 */
export function dropPositionFor(
  kind: DragPayload["kind"],
  ratio: number,
): DropPosition {
  if (kind === "images") return "inside";
  return ratio < 0.25 ? "before" : ratio > 0.75 ? "after" : "inside";
}

/** 直属图片行只接受图片，并且等同于拖到父文件夹。 */
export function directRowAccepts(kind: DragPayload["kind"]): boolean {
  return kind === "images";
}
```

`useDragSort.ts`（`src/shared/useDragSort.ts`）：

- `resolveTarget(x, y)` 改为 `resolveTarget(x, y, kind)`，`onPointerMove` 调用处（`:214`）传 `drag.payload.kind`。
- 选择器加入 `[data-drop-direct]`：
  - 先判断 `data-drop-root`；
  - 再判断 `data-drop-direct`：`directRowAccepts(kind)` 为 false 时返回 `null`；为 true 时读 `Number(element.dataset.dropDirect)`，返回 `{ kind: "folder", folderId: id, position: "inside" }`；
  - 其余走现有 `data-drop-folder`，位置改用 `dropPositionFor(kind, ratio)`（替换 `:109` 的三段判断）。
- `applyHighlight`、hover 展开、canDrop 检查都不改结构；图片在文件夹行/根行/直属行解析出的都是 `inside`，因此现有的 `canDrop`（`src/app/LibraryWorkspace.tsx:400`）与 `handleDrop` 早退（`:291`）继续成立，作为不变量保留。

`FolderTree.tsx`（`src/modules/library/FolderTree.tsx`）：

- 行本身已有 `folder-tree-row` 类，`inside` 高亮由 `.folder-tree-row[data-drop-position="inside"]`（`src/styles/index.css:5028-5031`）直接生效，不需要新增样式。

### 3.4 描述编辑：按内容撑高，去掉手动缩放

## 六、用户手工验收

代理不启动应用、不截图、不驱动窗口；以下步骤由用户执行。

### 6.1 图片拖放

1. 在文件夹树里找一个有子文件夹的文件夹，确保它已展开并显示“直属图片”行。
2. 从网格拖一张图片，分别落在父文件夹行的上边缘、正文中间、下边缘、展开箭头与右侧计数上：每次都应整行 `inside` 高亮，松手后图片进入该文件夹。
3. 拖一张图片到“直属图片”行：整行高亮，松手后图片进入该文件夹（不是只显示直属图片）。
4. 拖一个文件夹经过“直属图片”行：不应有高亮、展开或排序提示；松手不移动。
5. 拖一个文件夹到另一个文件夹行的上边缘/下边缘：仍应出现 `before` / `after` 的 2px 插入线，松手后同级顺序正确；拖到中间仍是移入。
6. 拖到“全部图片”根行：移入根目录，行为不变。

### 6.2 回收站操作

1. 普通视图选中 1 张：详情只显示“移入回收站”。
2. 普通视图多选 3–5 张：批量区只显示“移入回收站”，不再出现恢复/永久删除。
3. 移入回收站后打开回收站视图，单选与多选都只显示“恢复 / 永久删除”。
4. 从回收站多选恢复：回到普通视图后搜索这些图片，确认已恢复。
5. 从回收站打开查看器：右侧详情只显示恢复/永久删除；恢复后查看器应退出并回到回收站视图。
6. 临时视图：单图与多选都没有回收站操作。
7. 多选后查看“部分共同标签”折叠标题，文案应为“部分共同标签 (N)”。
8. 右键菜单：普通视图只有“移入回收站”，回收站视图只有“恢复 / 永久删除”。

### 6.3 导入运行中

1. 选择若干文件开始导入，进入运行态。
2. 标题只出现一次阶段名（如“正在导入”）；正文只显示当前文件与百分比，不再出现第二个“正在导入”。
3. 副标题为“导入完成前无法使用其他功能，可以取消导入。”
4. 尝试点右上角关闭、按 Esc、点击遮罩：都不应关闭弹窗。
5. 点“取消导入”：应能取消并进入完成/取消页；完成后点“完成”关闭。
6. 扫描、收尾阶段标题应分别显示“正在扫描输入目录”“正在收尾”，正文仍只有文件与百分比。

### 6.4 描述编辑

1. 找一张描述超过 8 行的图片，记录只读态高度。
2. 点“编辑描述”：输入框高度不低于只读态，不再缩回。
3. 连续回车增加几行：高度同步增长；删除到空：回落到 84px 左右的最低高度，不出现内部滚动条。
4. 输入时详情栏本身可滚动，工作区与网格不被撑开或推移。
5. 取消、保存、切到另一张图再切回：草稿与高度都按对应图片恢复，不串用上一张的高度。
6. 长描述按 `Ctrl/Cmd+Enter` 保存仍生效；失焦不保存。

### 6.5 清除筛选

1. 设置扩展名或评分筛选，摘要条出现。
2. “清除筛选”应显示为带边框的次要按钮并带清除图标，一眼能看出可点击。
3. 点击后筛选清空，按钮消失。
4. “清除搜索”仍是普通文字样式（本轮不改）；观察两者并排是否平衡，把结论反馈给代理。

## 七、边界、风险与后续

- **直属图片行的文档冲突**：`docs/modules/browse-and-query.md:305` 现在写“该行不参与多选、拖放与右键菜单”。实现后要改为“不作为文件夹拖动目标，但图片可拖到该行移入父文件夹”；`:310` 的“拖到文件夹行中间”要改为“拖到文件夹行任意位置”。这两处不改会让文档直接误导后续开发。
- **普通视图隐藏恢复/永久删除**：这是已确认决策。入口在回收站视图的视图栏；右键菜单在普通视图也只保留移入回收站。手工验收要覆盖“从回收站恢复”的完整路径，避免用户找不到入口。
- **右键菜单不改**：菜单按项状态渲染，与视图规则在当前查询条件下等价。若以后出现“混合状态的菜单”（例如跨范围选择），需要重新评估，不属于本轮。
- **描述自动撑高**：`scrollHeight` 在隐藏或未挂载时可能为 0；`useLayoutEffect` 只在编辑态执行，且用 `Math.max(..., 只读高度)` 兜底。如果用户手动缩放被去掉后仍希望调整，需要另开入口；本轮按“内容决定高度”收口。
- **短描述仍会变高**：空/短描述从只读的一两行增长到 84px 最低高度，这是编辑区的最小操作空间，不是缩回；手工验收时请把它与“长描述缩回”分开看。
- **导入文案不承诺后台**：保持模态阻塞，不再写“可以继续使用其他功能”；非模态导入记入后续待评估，不在本轮实现。
- **清除搜索暂不同步**：按计划等真实窗口看整体平衡；如果用户验收认为仍像文字，再单独改，不与本轮混在一起。
- **不做**：不改工具栏整体布局；不把导入改成可关闭；不从回收站移除恢复/永久删除；不为拖放引入第三方库；不改数据库、Tauri 命令、`DataChange`、任务进度或线程模型。
- **完成后的文档同步**：`docs/modules/browse-and-query.md`（拖放 `:305`、`:308-311`；详情/批量 `:342-349`；描述 `:344`）、`docs/modules/import.md`（导入界面 `:134-135`）。批次完成后补实现记录，再把本文移入 `docs/planning/archive/` 并更新归档索引。
