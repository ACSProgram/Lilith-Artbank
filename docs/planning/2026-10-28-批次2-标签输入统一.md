# 使用反馈整改 批次 2：标签输入统一

日期：2026-10-28
状态：**准备稿，尚未实现**。本文件只写方案、现状核对、测量与验收口径，不代表任何代码已经落地或界面已经验收。正文行号是 2026-10-28 的调查快照，并行批次实现后会变化。

范围对应《[使用反馈整改计划（第二轮）](2026-10-28-使用反馈整改计划（第二轮）.md)》的编号 3 与批次 2。本批次只统一标签输入、建议下拉、chip 展示与标签管理器的搜索来源；不改标签 schema、不做层级/分类、不改 64/32 上限、不把改名自动变成合并、不改筛选语义。

本批次只改前端组件、标签管理器与文档，不改 Rust、数据库、任务层、MCP 与导入流水线。与并行批次的文件重叠见第八节。

## 一、本批次决策

| 问题 | 结论 |
| --- | --- |
| 统一到什么程度 | 四个入口共用同一套 chip 基座与建议列表。详情、批量添加、导入是 chip 编辑器；标签管理器的改名/合并是单名输入，只共用建议外观与数据来源，不改成 chip 多选。 |
| 聚焦但输入为空 | 显示常用标签：后端按图片数降序取前 200 个，过滤已选/排除后展示 12 个。200 是 `search_tags` 的上限，保证详情已有 64 个标签时仍有足够候选。 |
| 输入后的建议 | 走现有 `search_tags`；去抖 160ms；同样过滤已选/排除；最多展示 12 个。 |
| 建议项计数 | 显示 `N 张`，来自 `TagInfo.imageCount`；口径与标签管理器一致，排除回收站与临时区。 |
| 建议里怎么区分“新建” | 建议项始终带图片数；输入非空时下拉底部显示“回车添加「当前文本」”。不把某个名字标成“新建”，避免与已有标签混淆。 |
| 标签管理器列表搜索 | 空查询仍载入图片最多的 500 个；非空查询改走后端 `search_tags`，最多 200 个，达到上限时提示缩小范围。 |
| 合并目标搜索 | 不再过滤本地 500 条，改为后端搜索；最多 50 个，空查询显示图片最多的 50 个。 |
| 改名输入 | 复用同一套建议外观，但选中建议只填入名称，不自动保存、不自动合并；保存仍走现有 `rename_tag`，重名仍报“已经有同名标签”。 |
| 改名建议位置 | 用内联列表展开，不用绝对定位浮层；标签管理器本身在可滚动 modal 里，浮层会被 `.tag-manager-list` 裁剪。 |
| 是否缓存常用标签 | 不新增缓存。聚焦或输入时现查；一次查询约 25–45ms。批量候选仍只由 `tagVersion` 驱动。 |
| 后端与数据 | 不需要改 Rust。`search_tags` 空查询已返回按图片数降序的标签，且 `TagInfo` 已带 `imageCount`。 |
| 上限 | 详情单图 64、批量暂存 64、导入 32，均不变。 |
| 0 张标签 | 保持现状：后端只返回至少有一张有效图片的标签，管理器看不到 0 张标签。清理入口仍留在待办。 |
| 分页 | 本批次不做标签搜索分页；200/50 的上限用提示说明。超过时输入更具体的关键词。 |

补充约定：

- 后端没有任何标签时，空聚焦不显示空下拉，也不报错；图片自身没有标签不影响常用标签建议。
- 建议查询失败时静默关闭下拉（沿用现有行为），不阻塞输入；标签管理器的搜索失败要有可见提示。
- 输入法组合态（`isComposing`）下回车仍不提交；本批次不额外拦截组合态期间的查询。
- 建议列表只支持点击选择；`Enter` 仍提交当前输入文本，不引入方向键高亮。方向键导航不在本批次范围。

### 2.2 建议下拉

`TagInput` 当前行为（`src/shared/components/TagInput.tsx`）：

- 建议只在输入文本非空时请求（`:79-83`）；聚焦且为空时清空建议，不显示常用标签。
- 自动补全回调只返回名称数组（`searchSuggestions?: (query: string) => Promise<string[]>`，`:27`），因此下拉无法显示图片数。现有的两个建议回调都只做 `.map((tag) => tag.name)`（`Inspector.tsx:79-81`、`LibraryWorkspace.tsx:278-282`）。
- 请求返回后过滤已选/排除、截断 12 条（`:90-98`）；请求的是 12 条，过滤后可能不足 12 条。
- 下拉项只有名称（`:163-181`）；没有“按回车添加当前文本”的说明。
- 输入框没有 `onFocus`（`:130-152`），所以无法在聚焦时展开候选。

### 2.3 chip 展示

当前有三套结构，视觉大多依赖同一组 class，但 DOM 与可交互区域不同：

1. 详情已有标签：`span.tag-chip` + 名称按钮（可选）+ X 按钮（`Inspector.tsx:571-610`）。
2. 批量移除候选：`button.tag-chip.tag-chip-remove`，整块点击移除，内部是名称、计数 `em`、X 图标（`:938-969`）。
3. `TagInput` 暂存 chip：`span.tag-chip` + 名称静态文本 + X 按钮（`TagInput.tsx:113-128`）。

三处的字号、内边距、圆角与 hover 基本一致，但重复维护；批量候选与输入 chip 的计数、禁用、选中态样式分散在 `src/styles/index.css:2850-3000`。

### 2.4 标签管理器

- 主列表：`load()` 用 `libraryApi.getTags(500)`（`:39-49`），`visible` 在本地 `name.toLowerCase().includes` 过滤（`:124-127`）。超过 500 个有图标签时，搜索找不到列表外的标签。
- 合并目标：`mergeCandidates` 同样从本地 `tags` 过滤（`:128-133`），只排除源标签 id；目标标签必须已经在载入的前 500 个里才能看到。
- 改名：普通输入框，没有候选；保存调用 `renameTag`，后端在重名时返回“已经有同名标签”（`src-tauri/src/library/metadata.rs:902-931`），不会自动合并。
- 操作成功后会 `load()` 重新取前 500（`:66-79`）；查询状态没有单独的加载/失败处理。
- 弹窗正文在 `.modal-body` 内滚动（`src/styles/index.css:722-726`），标签行列表自身也有 `overflow-y`（`:3213-3221`）。改名建议如果做成绝对定位浮层，会被这两层滚动容器裁剪。

### 2.5 后端能力与口径

现有 `search_tags` 已够用，不需要新增命令：

- `search_tags(query, limit)` → `query::search_tags`（`src-tauri/src/library/query.rs:688-694`）。
- 空查询走 `list_tags_page(database, None, ...)`（`:703-706`），按 `image_count` 降序、再按名称升序（`:783-788`）。
- 非空查询按名称 `LIKE '%q%'` 过滤，`limit` 被限制在 1–200（`:707`），排序规则相同。
- 只返回至少有一张有效图片的标签；回收站与临时区的计数会被扣除（`:710-793`）。
- `TagInfo` 序列化为 `{ id, name, imageCount }`（`query.rs:260-266`）。
- 命令是异步阻塞执行：`src-tauri/src/app/commands.rs:393-405`；状态层只读：`src-tauri/src/app/state.rs:874-882`。
- 前端 API：`src/modules/library/api.ts:158-165`；浏览器预览：`src/modules/library/mock.ts:169-186`。

结论：**本批次不需要 Rust 改动**。建议下拉的“空聚焦常用标签”“计数”“全库搜索”都能通过现有 `search_tags` 的 `limit` 与空查询行为实现。

## 三、目标行为

### 3.1 统一 chip 基座

新增 `src/shared/components/TagChip.tsx`，作为三处 chip 的唯一展示基座。它只负责外观与可交互区域，不调用后端，不决定筛选或移除的业务语义。

建议接口：

```ts
export interface TagChipProps {
  name: string;
  /** 当前标签是否正在参与筛选。 */
  active?: boolean;
  /** 部分图片持有：降低强调，用于批量移除候选。 */
  muted?: boolean;
  /** 名称右侧的附加信息，例如 `全部` 或 `12/30`。 */
  count?: React.ReactNode;
  /** 名称按钮的 title；不传则名称为静态文本。 */
  nameTitle?: string;
  onNameClick?: (event: React.MouseEvent<HTMLButtonElement>) => void;
  /** 名称右侧的移除按钮。 */
  onRemove?: () => void;
  removeLabel?: string;
  /** 整块 chip 作为按钮时的动作（批量移除候选）。 */
  onActivate?: () => void;
  activateLabel?: string;
  activateTitle?: string;
  disabled?: boolean;
  /** 整块按钮模式下最右侧的图标，默认 X。 */
  trailing?: React.ReactNode;
}
```

渲染规则：

- 有 `onActivate`：根元素是 `<button type="button" class="tag-chip tag-chip-remove">`，整块可点，内部为名称、可选计数、`trailing`；不嵌套 `<button>`。
- 没有 `onActivate`：根元素是 `<span class="tag-chip">`；`onNameClick` 存在时名称是 `<button class="tag-chip-name">`，否则是静态 `span`；`onRemove` 存在时追加 X 按钮。
- `active` 加 `is-filtering`；`muted` 加 `is-partial`；`disabled` 传给所有可点元素。
- 名称与计数都要有 `title`/`aria-label` 的完整文本，长名称用 CSS 截断，不撑破侧栏。

三处落点：

| 位置 | 使用的 props | 必须保留的语义 |
| --- | --- | --- |
| 详情已有标签 | `nameTitle`、`onNameClick`、`onRemove`、`active` | 名称点击打开筛选菜单；Ctrl/Cmd 点击直接叠加；X 从图片移除。 |
| 批量共同/部分标签 | `onActivate`、`count`、`muted`、`activateTitle`、`activateLabel` | 整块点击从拥有该标签的选中图片移除；共同标签显示“全部”，部分标签显示 `拥有数/总数`。 |
| `TagInput` 暂存 chip | `name`、`onRemove`、`removeLabel`、`disabled` | 名称不响应点击；X 只从暂存数组移除，不写库。 |

视觉统一：

- 同一套 `padding`、`border-radius`、字号、间距、hover、`:focus-visible`。
- 计数统一用 `em.tag-chip-count`，颜色用 `--text-faint`，不抢名称。
- 可点击名称与整块按钮都要有键盘焦点样式。
- `is-filtering` 的实心强调、`is-partial` 的弱化描边保持现有含义，不互换。

### 3.2 建议下拉

新增 `src/shared/components/TagSuggestions.tsx`，作为建议列表的唯一展示组件；`TagInput` 与标签管理器共用。

建议接口：

```ts
export interface TagSuggestion {
  name: string;
  /** 已有该标签的图片数；不传则不显示计数。 */
  imageCount?: number;
}

export interface TagSuggestionsProps {
  items: TagSuggestion[];
  onPick: (name: string) => void;
  /** 内联展开：用于 modal 里的改名/合并，不用绝对定位。 */
  inline?: boolean;
  /** 底部说明，例如“回车添加「…」”。 */
  footnote?: React.ReactNode;
  /** 没有任何建议时仍可显示的一句提示。 */
  emptyText?: string;
}
```

渲染：

- 每项是 `<button type="button">`，左侧名称，右侧 `{imageCount.toLocaleString()} 张`；长名称省略，`title` 给完整名称。
- `onMouseDown` 阻止默认行为，避免点击时输入框先失焦。
- 列表有最大高度与内部滚动，12 条约 260px 以内。
- 内联模式下不绝对定位，宽度跟随输入区域，随行高展开。

`TagInput` 行为：

- 输入框 `onFocus`：记录聚焦并打开建议。
- 聚焦且文本为空：立即请求 `searchSuggestions("")`，用 `filterTagSuggestions` 过滤已选/排除后展示前 12 个。
- 文本非空：去抖 160ms 请求；同样过滤、去重、截断 12 个。
- 请求池由调用方决定；建议统一请求 200 个（`search_tags` 的上限），再在组件内过滤，避免详情已有 64 个标签或批量排除共同标签后把 12 个名额占满。
- 输入变化时重新打开建议；提交一个标签或点击建议后关闭，直到下一次输入或重新聚焦。
- `Escape` 关闭建议，不移除已选 chip，也不清空文本。
- 输入非空时底部显示“回车添加「{trim 后的文本}」”；没有匹配项时显示“没有匹配的标签”并保留这句底部说明。
- 聚焦为空且没有任何候选时不渲染空下拉。
- `max` 已达到、`disabled` 或没有 `searchSuggestions` 时不打开建议。
- 组合态回车不提交，沿用现有 `event.nativeEvent.isComposing` 判断。

`filterTagSuggestions` 放在 `src/shared/tagNames.ts`（纯函数，供组件与测试共用）：

```ts
export interface TagSuggestion {
  name: string;
  imageCount?: number;
}

export function filterTagSuggestions(
  items: readonly TagSuggestion[],
  blocked: readonly string[],
  limit = 12,
): TagSuggestion[];
```

规则：名称 trim、忽略空串、忽略大小写去重、排除项忽略大小写、保留首次出现的大小写与 `imageCount`、按输入顺序取前 `limit` 个。

同文件增加一个可测的请求规则，明确“空聚焦立即查、非空去抖”：

```ts
export function tagSuggestionRequest(text: string): {
  needle: string;
  debounceMs: number;
};

// 空串或纯空白 → { needle: "", debounceMs: 0 }
// 非空 → { needle: trim 后的文本, debounceMs: 160 }
```

- `exclude` 为详情已有标签；达到 64 个后输入禁用并显示上限提示，不再显示建议。
- 聚焦空输入显示常用标签；输入后显示匹配标签；建议项显示图片数。

- 新增标签后，下一次聚焦重新查询，计数以最新库为准。

### 3.4 批量添加

- 沿用暂存 chip + “添加”一次提交；`commitOnBlur` 保留，点“添加”前提交未回车的文本。
- `exclude` 只排除“全部选中图片都有”的标签；部分标签仍可出现，因为添加到全部选中图片是合法操作。
- 聚焦空输入显示常用标签；建议项显示图片数；上限仍是 64。
- 建议查询失败不影响批量侧栏其它区块。

### 3.5 导入初始标签

- 沿用 chip 暂存、最多 32 个、开始导入前提交未回车文本。
- 建议回调由 `LibraryWorkspace` 注入，类型改为返回 `TagSuggestion[]`；导入模块仍不直接依赖 `libraryApi`。
- 聚焦空输入显示常用标签；建议项显示图片数；选中只加入暂存 chip，不立即写库。

### 3.6 标签管理器

#### 3.6.1 主列表搜索

- 打开时仍载入图片最多的 500 个（`getTags(500)`），用于无查询时的浏览。
- 查询为空：显示这 500 个；现有“列表只显示图片最多的 500 个”的提示只在确实达到 500 时出现，文案补一句“搜索可找到不在列表里的标签”。
- 查询非空：去抖 160ms 后调用 `libraryApi.searchTags(query, 200)`；显示后端结果，不再在本地 500 条里过滤。
- 搜索中保留旧结果并显示轻量加载指示；首次搜索显示“正在搜索…”。
- 搜索失败：显示“读取标签失败：…”并保留旧结果；不把列表清空。
- 结果数达到 200 时提示：“匹配较多，只显示图片最多的 200 个，输入更多字符缩小范围。”
- 查询清空后回到 500 条初始列表；如果期间做过改名/删除/合并，初始列表也要重新载入。
- 过期响应按代次丢弃；初始 500 的载入与搜索共用代次，查询非空时晚到的初始结果不能覆盖搜索结果；关闭弹窗后不再写状态。

#### 3.6.2 合并目标

- 打开“合并到…”时，不再从本地 `tags` 过滤，改为后端搜索。
- 空查询：`searchTags("", 50)`，排除源标签 id，显示图片最多的 50 个。
- 非空查询：去抖 160ms 后 `searchTags(query, 50)`，同样排除源标签 id。
- 每项显示名称与 `N 张`；候选列表复用 `TagSuggestions`（inline），点击时按名称找到对应的 `TagInfo`，再走现有合并确认。
- 加载中显示“正在读取…”，失败显示错误与重试入口；没有候选时显示“没有可合并的标签”。
- 结果数达到 50 时提示“只显示图片最多的 50 个，输入更多字符缩小范围。”
- 合并确认文案、影响数量、操作记录与刷新逻辑不变。

#### 3.6.3 改名输入

- 输入框保留当前名称；进入改名时不主动展开建议（文本非空）。
- 用户修改或清空后，去抖 160ms 调用 `libraryApi.searchTags(text, 50)`，排除当前标签 id，过滤后最多显示 12 个。
- 清空后聚焦继续显示常用标签，与其它入口一致。
- 建议用内联列表展开在输入行下方，外观与 `TagSuggestions` 相同，不用绝对定位浮层。
- 点击建议只把名称填入输入框并关闭列表；不自动保存、不自动合并。
- 建议查询失败时不清空输入、不阻塞保存；在输入下方显示一行“建议读取失败”，下一次输入重试。
- 回车与“保存”仍调用 `renameTag`；目标名称已存在时，保持现有错误语义“已经有同名标签”，不跳转合并。
- `Escape` 取消改名；已有行为不变。

### 3.7 失效与一致性

- 本批次不新增全局缓存。建议数据在每次聚焦/输入时重新查询；标签管理器在每次操作后重新查询当前视图。
- 批量移除候选仍由 `tagVersion` 驱动（`src/modules/library/dataChange.ts:346-349`、`src/modules/library/LibraryView.tsx:621-623`），本批次不改。
- 改名/删除/合并成功后，标签管理器重新载入初始 500 与当前搜索；`onChanged` 仍发出 `tagCatalog`。
- 图片标签写入、标签改名/删除、导入标签完成时，下一次建议查询会拿到新数据；不为下拉单独引入版本号。
- 计数口径：建议与标签管理器都使用 `TagInfo.imageCount`，排除回收站与临时区；不在界面上另算。

风险与已知边角：

- **标签管理器 200 条上限**：匹配超过 200 个时只显示图片最多的 200 个，最弱的匹配需要更具体的关键词才能看到。真实库当前 174 个有图标签不会触发；若未来超过 200，再评估分页命令。
- **改名建议与重名**：选中已有名称后保存仍报错，这是有意保留的语义；用户可能误以为点击建议就会合并，验收时重点确认。
- **内联建议撑高行**：改名建议在 modal 内展开会增加行高；用最大高度与内部滚动控制，不把整个弹窗撑出屏幕。
- **每次聚焦一次聚合查询**：真实库几十毫秒；如果大库或慢盘上明显卡顿，再考虑在会话内缓存“常用 12 个”并以 `tagVersion` 失效，本批次不做。
- **计数口径**：建议与标签管理器的图片数排除回收站与临时区；用户若拿它和全库总数对比，可能看到差值。这是现有标签列表口径，不新增说明文字。
- **长标签名**：真实库存在 `/`、`<>`、`_*` 等字符；建议项必须省略显示而不是按分隔符截断。
- **组合态**：中文输入法组合期间可能触发建议查询；回车仍不提交。若实际体验出现闪动，再单独加组合态抑制。
- **文件重叠**：本批次会改 `src/modules/library/Inspector.tsx`、`src/styles/index.css`、`src/modules/import/ImportDialog.tsx`、`src/app/LibraryWorkspace.tsx`。批次 1 也改 Inspector 的多选/描述与样式，批次 4 也改 Inspector 的空选态与文件夹详情；并行实现时必须按区块拆 hunk，不要整文件重排。本批次不改 Rust，避免与批次 5/6/7 冲突。
- **打开期间的外部标签变化**：标签管理器在打开时载入，自身操作后刷新；打开期间由导入/MCP/其它任务新增或改名的标签不会自动出现，关闭重开即可看到。本批次不把 `tagVersion` 接进管理器，避免与正在编辑的行冲突；若需要实时刷新，另开小批次。
- **本文件不是验收记录**：实现完成后另写实现记录，未验证项继续留在 `docs/planning/todo.md`。
