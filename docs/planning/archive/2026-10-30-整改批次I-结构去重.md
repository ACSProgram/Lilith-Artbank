## 改了什么

### 文件夹聚合只留一份

新增 `src-tauri/src/library/folder_tree.rs`：一次读取文件夹行，提供按 id/小写路径查找、祖先、子树 id、直属计数累加到祖先、子文件夹数。路径比较统一走 `paths::folder_within`，与数据库 `COLLATE NOCASE` 同口径。

- `library/query.rs` 的 `list_folders`、`list_trash_folders`、`folder_stats` 的子文件夹数与整树计数改用它；删掉 `all_folders` 与 `expand_folder_counts` 两份局部实现。
- `library/folders.rs` 的 `subtree_folder_ids`、`ancestor_folder_ids` 改用它，写路径不再各拼一套 SQL/前缀回溯。
- 新增 4 个单测：大小写不一致的祖先、子树包含自身、计数累加到每一级祖先、子文件夹数排除选中行。

### id 校验只留一份

新增 `src-tauri/src/library/ids.rs`：`unique_positive`（正整数、按输入顺序去重）与 `ensure_max`（上限）。元数据批量写、集合、任务范围解析与能力查询共用；上限与错误文案仍由调用方决定，集合列表的 `id 无效` 随之细化为 `集合 id 无效` / `图片 id 无效`。另加 2 个单测覆盖去重与上限边界。

### 路径守卫只留一份

`library/paths.rs` 新增 `ensure_within` 与 `ensure_canonical_within`（后者用于批量删除时复用已 canonicalize 的根）。文件夹目录、目标目录与 `ContentRemover` 三处改为调用它，不再各写一份 `canonicalize + starts_with`。

### 任务通道只留一份

`app/tasks.rs` 新增 `TaskBus::begin_blocking_task`：排队、资源准入、panic 兜底、终态与 `TaskRunGuard` 都走任务总线。`app/commands.rs` 的 `run_write_task` 只负责在阻塞线程里调用它；原来手写的 `begin_queued + catch_unwind + finish_from` 已删除。`begin_queued` 失败时任务也不会停在排队中。

### MCP 写工具入口闸

`mcp/tools/write.rs` 新增 `WriteGate`（模式校验、MCP 写串行、图库上下文一次取齐）与 `pre_write_checks`（`confirmedCount`、可用性、空选择）。`images_update`、`images_move`、`images_trash`、`images_restore`、`collections_create`、`collections_modify`、`collections_membership` 与 `folders_modify`、`tags_modify` 这九个同步写工具改用同一个入口闸；各工具自己的预览、资源申请与写入实现保持不变。`confirmed_outcome` 改收预览 JSON 的引用，成功路径不再复制一份。

### 前端进度共用部件

新增 `src/app/taskProgress.tsx`：`taskProgressState`（活动、取消中、已结算张数、百分比）、`TaskProgressBar`、`CancelPendingNote`。

- 任务胶囊、批量任务、空间优化、维护检查、相似分组五处改用同一进度条与取消说明；取消中统一显示「等当前批次提交完成，已执行的部分不会撤销。」。
- 原来 `.task-row-note` 与 `.optimize-cancel-note` 两条相同样式合并为 `.task-cancel-note`。
- 各对话框的布局、标题与统计行不变；维护检查仍用 3px 细条（保留 `maintenance-progress-bar` 的外形）。

### 文档同步

`docs/modules/library.md`、`browse-and-query.md`、`mcp.md` 与 `docs/architecture/ai-reading-guide.md` 补上新入口与文件位置；`current-handoff.md`、`todo.md` 与归档索引更新到批次 I。

## 用户需要手工验收

1. **进度与取消**：分别打开批量任务、空间优化、维护检查、相似分组，开始任务后点取消，确认进度条转斜纹并出现「等当前批次提交完成，已执行的部分不会撤销。」；任务胶囊里的取消说明与它们一致。布局与改动前相比不应有位置/字号变化（维护检查的进度条仍为细条）。
2. **MCP 写工具**：询问档对 `images_update` 先 `dryRun` 再带 `confirmedCount` 执行；对 `images_trash`、`folders_modify` 的 move/delete、`tags_modify` 的 delete/merge 走一次确认卡，批准后结果与撤销记录正常；`collections_create` / `collections_membership` / `images_restore` 各执行一次。
3. **文件夹计数与撤销**：在临时库里建 `Art/Sub`、改名为 `ART/Sub`、移动、移入回收站再恢复，确认树计数、文件夹概览子文件夹数与撤销/重做结果一致。
4. **排队写任务**：让一个长任务占住元数据写或文件夹路径，再触发批量移动/批量标签，确认冲突提示、排队与取消后的终态与改动前一致。
