## 实施中的关键取舍

- 历史与重做都使用 `operation_chunks`：原始逆数据描述撤销方向，撤销时另写 `format='redo'` 的快照；重做只读 redo chunks。
- 永久删除与清空回收站只写 `purge_operation_id`；记录过期或清空记录后才由 `ReleaseGarbage` 删行删文件。
- 待释放行只在回收站视图与全库搜索显式排除；普通/集合视图靠 `deleted_at IS NULL`，避免 20 万行文件夹排序首页从 39 ms 退化到 81 ms。
- 批次 2 后把撤销改为“保留记录 + 重做”。新的 `history::write` / 写入内容的 live 批次在同一事务里删除灰色记录；`begin_live` 本身不动重做分支，避免被 write lane 拒绝的导入清掉用户可重做的记录。
- 编辑与导入的原图暂存到 `.artbank/undo/<op>/`，撤销/重做在两侧移动文件；撤销编辑会清空该图 `feature_blobs`，不恢复派生特征。
- 标签关系按批写 JSON，避免一次性大 JSON；删除标签的撤销优先用原 id 重建，同名标签已存在时合并关系。
- 集合创建/删除/运算/相似分组保存完整快照（行 + `(imageId, position)`），重做按原 id 重建；加入/移出记录旧 `updated_at` 与条目位置。
