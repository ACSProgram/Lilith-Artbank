## 背景

第二轮代码复核在估算、执行与文档里定位到 13 项问题，其中内容安全（动画/多页源被压成单帧）、漏斗口径、断电发布顺序与导入孤儿三类会直接损坏图片或让行指向坏文件。计划据此拆成两批：批次 1 只解决用户能看到和能判断的问题，批次 2 改执行写路径与断电保护。

## 批次 1（提交 `05dfed6`）

- 内容安全前置补丁：`SkipReason::AnimatedOrMultipage` 与 `optimize::multiframe_guard`。GIF 只看数据库格式列，走前置桶；APNG 认 `acTL`、动画 WebP 认 RIFF `ANIM`、多页 TIFF 看 IFD 链，读文件后计入候选内跳过。估算与执行共用同一条判据，动画/多页源不再被替换成单帧。
- 抽样五档：50 / 200 / 500 / 1000 / 2000，滑块按索引走，五个标签与停靠点一一对应；删掉 300ms 防抖与硬编码吞吐，等待时间改由本会话上次实测的 `sampleElapsedMs / sampleCount` 折算；候选不足时结果页显示实际样本张数。
- 任务接管：`OptimizeEstimate` 自带 `options`、`scope`、`scopeLabel`、`sampleSize`、`libraryId`；对话框按「执行中 → 估算中 → 本次结果 → 已完成估算 → 默认配置」恢复，「返回修改」记下已放弃的 taskId，换库或结果属于别的图库时不接管；估算运行中改参数，回来的结果按签名丢弃。
- 打开延迟：新增 `get_query_total` 只做计数，对话框先出现、范围计数后补；任务上下文拆成 `active` / `data` 两个窄上下文，网格与浏览界面不再跟着每 150ms 的任务快照重渲染。
- 漏斗闭合：前置排除（已紧凑、已处理、透明、超 WebP、GIF）、候选内跳过（色彩、16 位、画质、省得太少、动画/多页、解码后判定、失败）与「内容重复」各有落点；外推后各桶先按比例收窄，再令 `process = candidate − Σskip`，四条不变量严格成立。
- 节省率上限从替换阈值 `MAX_SIZE_RATIO` 改为 1.0；`is_smaller_enough` 用 `round` 换算百分比，避免截断把阈值收紧一个百分点。
- 耗时拆成 `work` / `write` / `finish` 三段，样本额外真实执行 BLAKE3 与勾选的重算（结果丢弃，只留耗时）；收益曲线三点各自加权（像素 / 预测输出字节 / 张数），最后一点等于总预计耗时。

## 批次 2（本提交）

- 平台层 `platform/fs.rs`：`rename_durable` 在 Windows 用 `MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`，其他平台退回标准 rename；`flush_directory` 打开目录句柄后 `FlushFileBuffers`，系统/文件系统报「不支持」时只记调试日志并按依赖 write-through 处理，其他错误照常上报。
- `LibraryDb::with_durable_writer`：破坏性写任务期间把写连接临时提到 `synchronous = FULL`，结束后无论成败恢复原值；普通编辑仍是 `NORMAL`。
- 执行发布顺序：文件数据 `sync_all` → 持久化 rename → 每个目标目录 flush 一次 → FULL 事务提交 → 并行删旧图。任一前置步骤失败就删掉本批已发布的新文件；提交返回前不删旧图。
- 孤儿接管：目标内容文件已存在时先查有无行引用该 `content_hash`；没有则按 BLAKE3 校验目标文件，一致就接管，不一致（截断孤儿）就删掉重发。只有这条罕见路径读目标文件算哈希。导入发布路径用同一套判断，并在入库失败时不删接管来的文件。
- 去重复读：`decode::decode_bytes` 从已读字节解码，`encode_one` / `sample_one` 不再为解码第二次读盘；`failed_outcome` 保留已经发生的读取耗时，失败样本不再把 IO 耗时记成 0。
- 阶梯效率：`PixelBuffer` 把像素转换一次，编码与 PSNR 比对复用同一份缓冲；先判体积再算 PSNR，当前质量缩不到 95% 就按「省得太少」早退；MSE 改整数累加。
- 线程与批次：编码线程 `min(核数−1, 8)`，估算与执行共用；批次保持 1000 张。
- 提交与删除：本批新哈希一次批量查询（分块 `IN`）替代逐张 `SELECT`，批内重复用内存集合挡住唯一约束；同一批目标目录只 `create_dir_all` 一次；旧图在提交后并行删除，`ContentRemover` 只 canonicalize 一次根目录、父目录按文件夹缓存。
- 执行报告与校准：报告新增 `prefilterSkipped` / `candidateSkipped` / `duplicateSkipped` 与分段耗时、删除数；执行结束用这些实测值写 `meta` 表的 `optimize.calibration.v1`，估算优先用本库校准替换保守常数（处理 ≥20 张、有输出字节且四项数值合理时才更新）。
- 基准：新增 `perf_encode_threads`、`perf_optimize_batch_size`、`perf_estimate_vs_actual` 三个临时库基准，数字写进性能文档。

## 与计划的差异

- 全局 `synchronous = FULL` 改成就地的作用域开关：只覆盖压缩提交与释放任务删行，避免普通编辑、MCP 写每次都多付一次 WAL fsync。
- 目录 flush 在本机可用，但系统不支持时按「依赖 write-through」处理并写进文档边界，没有在失败时中止整批。
- 没有做拔电注入测试；只验证了发布顺序、提交失败回滚、孤儿接管与平台层调用。
- 批次大小仍是 1000：基准里提交只占个位数毫秒，发布与删除才是写入侧主体，换批次大小没有决定性收益。
- 缩略图追加仍在提交事务内，未搬到事务外；报告里的 `commitMs` 明确包含这部分。

## 收尾整理（本提交）

- 校准换算扣掉 fsync 再算每字节写盘秒数，避免估算里把 fsync 计两遍。
- 执行失败清单转发到任务句柄，任务胶囊能看到具体图片与原因；此前报告里的失败清单只留在内存。
- 临时文件夹不再能作为压缩范围：`OptimizeDialog` 把该项置灰并说明原因，后端在估算与执行入口一并拒绝——临时图片关闭图库时整目录清空，压缩只会留下一条无用记录。
- 清点并统一了发布失败、flush 失败与提交失败三处「删除本批新文件」的实现，补上 `new_hash` 等于原哈希、批内重复、孤儿接管等判断的注释。
- 文档补正：导入发布改为「核对哈希 → 持久化 rename → 目录 flush → 入库」，维护文档补上校准口径（每字节写盘不含 fsync）、失败清单落点与执行报告的实测字段。

## 遗留边界

- 断电只保证批次边界上「行不会指向坏文件、旧图不会先于提交被删」，不承诺任意时刻的全库快照一致，也不做启动时的全库孤儿扫描。
- 导入改为逐张 flush 目录，代价与压缩侧同级（约 0.4 ms/张）；导入吞吐没有再跑一次 `perf_import_1000` 复测。
- 估算精度依赖本库校准记录：首次执行前用保守常数，慢盘会偏低，第二次起按实测收敛。
