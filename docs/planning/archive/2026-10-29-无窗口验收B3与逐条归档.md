## 二、入口与场景

新增三个无头命令模块，入口仍只做参数解析、状态装配与领域函数调用：

- `src-tauri/src/headless/optimize.rs`：`optimize estimate`；场景 `optimize_flow`（估算 → 可选改选/截断/删文件/移入回收站 → 用同一估算凭证执行 → 返回任务、错误、操作记录）。
- `src-tauri/src/headless/ai.rs`：`ai status|health|ensure|embed-text|shutdown|embed|pose|pose-get|describe|search|similar|groups|keeps|temp-features|features`；场景 `ai_search_flow`（语义搜索 + 相似分页 + 相似 id + `find_similar` + 翻页）与 `ai_temp_flow`（临时导入 → 特征 → 两种范围搜索 → 关库重开后的计数）。
- `src-tauri/src/headless/mcp.rs`：`mcp status`；场景 `mcp_bridge` 与 `mcp_modes`。桥接用当前 exe 的 `--mcp-stdio` 子进程，读写 JSON-RPC 行，不启动真实客户端。

估算凭证、语义/相似结果 token、MCP 审批队列与临时文件夹都是进程内状态，跨进程会失效。这四处流程因此放在同进程场景里编排，不拆成多条命令；`optimize estimate` 仍保留为只读命令，单独执行时只验证估算，不执行。

夹具增加 `seed` 与 `tweak` 两个旋钮：`seed` 让同尺寸样本内容不同；`tweak` 在右下角翻转若干像素的红色最低位，用来造 pHash 相近的近似重复图（实测 1 个像素即可形成一组）。两者只影响 `fixture write-image|corpus` 生成的样本。

MCP 审批有效期增加只在 `headless` 构建生效的 `LILITH_MCP_APPROVAL_TTL_MS`，`approval::ttl()` 同时驱动 `expires_at` 与 `library_info` 的 `timeoutMinutes` 文案；GUI 构建仍是 10 分钟。

## 三、测试与结果

### `acceptance_optimize`（3 默认 + 1 heavy）

- `estimate_and_execute_replace_sources_and_record_history`：12 张 256×256 BMP 估算为 WebP，执行后 12 张全部替换、原文件消失、新文件更小、只产生一条 `optimize` 记录；再次估算 `skipOptimized=12`。
- `stale_grant_and_source_drift_are_rejected_or_trimmed`：120 张 64×64 BMP。改档位后执行被拒（参数指纹）；移入回收站 1 张后执行被拒（候选集合变化）；截断 1 张（低于 1% 阈值）时继续，摘要显示“未纳入候选 1 张”；截断 3 张（高于阈值）时拒绝。
- `no_candidates_and_temp_scope_fail_clearly`：全 JPEG 走跳过路径时任务仍完成并返回跳过数；临时区范围明确报错。
- `heavy_optimize_300_textures`：300 张 256×256 纹理，重档，默认跳过，本轮未跑。

发现并固定的行为：全 JPEG 时候选集并不为空，任务以“全部跳过”完成，因此测试断言 `candidateCount>0`、`processed=0`、`skipped=6`，不再假设启动前报错。

### `acceptance_ai`（2 默认）

- `protocol_retries_validates_and_reports_offline`：假服务下逐项调用 status/health/ensure/embed-text；5xx 连续两次后成功，计数 3 次尝试；4xx 只请求一次；维度不足返回“维度不匹配”；shutdown 后停服，status 与搜索返回离线文案。
- `batch_features_search_similar_groups_and_temp_area`：6 张样本 + 一对单像素微调图（导入时 `perceptualThreshold=0`），按 BLAKE3 内容哈希定位行；embedding/pose/描述后语义搜索分页、相似分页与 `find_similar`；pHash 7 + embedding 0.5 分组命中近似重复对；范围只有一张时无组；阈值 8 被拒；`keeps` 返回保留 id；文本模型不一致报错；临时区生成 3 张特征后两种范围搜索正确，关库重开后临时区为 0。

假服务在测试进程内用 `TcpListener` 启动，线程/连接保活，返回确定性 8 维向量（四象限颜色均值）。第一版每次请求后关连接，Windows 上偶发 10053 导致重试计数抖动；改为 keep-alive 并增加 `reset_retry_attempts()` 后稳定。

### `acceptance_mcp`（3 默认）

- `stdio_bridge_lists_and_calls_tools`：真实 `--mcp-stdio` 子进程，工具数 24、服务名正确；完全档 `approval.threshold=null`；`search_images`/`tags_list` 可调用；退出后运行时文件消失；`logs/mcp.log` 有桥接与工具调用行。
- `modes_approvals_expiry_library_switch_and_restart`：只读档写入报错；询问档 `dryRun` → 待确认 → 拒绝/批准/过期；换库清空确认单；完全档直接移入回收站；服务口令轮换；停服后调用返回错误；审计日志包含导入与工具行。
- `occupied_port_keeps_settings_and_reports_error`：端口被占用时设置保存成功且可重读，状态为 enabled 但 running=false、错误含“无法监听”，不写运行时文件。
