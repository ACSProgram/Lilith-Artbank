范围对应《[使用反馈整改计划](2026-10-27-使用反馈整改计划.md)》的编号 10、11、13、14，以及 `todo.md` 并入的 `FolderDelete` / `FolderMove` 记录标题问题。本批次只改文件夹树的排序、直属图片入口、多选拖动、窗口与展开状态；不改文件夹物理目录布局，不做跨库拖放，不保留旧的常驻排序模式。

## 已确认决策

| 问题 | 结论 |
| --- | --- |
| 直属图片入口 | 放在文件夹树内，作为虚拟子行。只在文件夹同时有子文件夹和直属图片时显示；该行显示“直属图片 N”。点击后只显示直接放在该文件夹的图片，面包屑追加“直属图片”。多选文件夹时不提供该入口。 |
| 一次性排序依据 | 只提供“名称”和“图片数（含子文件夹）”两种依据，可升序/降序；不提供“图片数（直接）”依据。 |
| 递归语义 | 勾选“包含所有后代”时，每个父级各自排序自己的直接子文件夹，不把所有后代混成一层；不勾选时只排当前文件夹的直接子文件夹。 |
| 排序写回与撤销 | 排序结果直接写回 `folders.sort_index`；一次排序一条操作记录，可整体撤销/重做。排序不再保留任何常驻模式或 `localStorage` 状态。 |
| 窗口持久化 | 使用 Tauri 的窗口状态插件。窗口信息跟随系统应用配置目录，不要求随便携目录迁移；只保存位置、大小、最大化状态，不保存全屏。 |
| 窗口异常回退 | 启动后检查窗口是否仍在任一显示器内；完全在屏幕外时回到主显示器居中，尺寸超过显示器时收缩到可用范围。 |
| 多选拖动的撤销粒度 | 一次拖动（移动或排序）只写一条操作记录，撤销整体回退。 |
| 同时选中父与子 | 只移动最外层父文件夹，子文件夹随父一起移动；不因同时选中而报错。 |
| 展开状态持久化 | 按图库分别保存展开的文件夹路径；换库各自恢复；没有保存过的图库仍默认展开顶层文件夹。 |
| 记录标题 | `FolderMove`、`FolderDelete` 的标题补上路径；`FolderRename` 本批次不改。 |

## 一、现状

### 1.1 文件夹排序是常驻模式

- `FolderTree` 在 `localStorage` 里保存 `lilith.folderSort`，支持 `manual / name / total / direct` 与升降序（`src/modules/library/FolderTree.tsx:63`、`:86`、`:131`）。标题栏有常驻排序按钮与弹层（`:316`、`:501`）。
- 拖放只在 `folderSort.mode === "manual"` 时启动（`:374`），排序弹层还明确提示“切换到手动后才能拖动文件夹调整顺序”（`:536`）。
- 树的显示顺序由 `buildFolderTree(folders, folderSort)` 决定（`src/modules/library/folderTreeModel.ts:44`）；`LibraryView` 自己构建树时用的是默认手动顺序（`src/modules/library/LibraryView.tsx:295`）。
- 后端 `reorder` 已经支持一次移动多个同级文件夹（`src-tauri/src/library/folders.rs:296`、`:349`），但前端只传一个 id（`src/app/LibraryWorkspace.tsx:342`）。
- 新建与移动文件夹追加到同级末尾（`src-tauri/src/library/import.rs:94`），排序位当前没有“一次性批量重排”的入口。

### 1.2 没有“只看直属图片”的筛选

- `FolderInfo` 已同时返回 `directImageCount` 与 `totalImageCount`（`src-tauri/src/library/query.rs:234`、`:620`）。文件夹行只显示总数（`src/modules/library/FolderTree.tsx:410`），悬停标题同时给出直接与含子文件夹数量（`:372`）。
- 浏览筛选 `folder_ids` 只表示“包含子树”：`FOLDER_SUBTREE_SQL` 用路径自身与后代前缀匹配（`src-tauri/src/library/query.rs:935`、`:1097`）。根目录路径为空时视为整库，不做限制。
- 后端任务范围已经有“文件夹 / 含子文件夹”两种语义（`src-tauri/src/app/tasks.rs:746`、`:811`），但浏览界面没有对应的“直属”视图。
- 前端筛选结构 `LibraryFilters` 没有直属标记（`src/modules/library/types.ts:16`）；查询键、选择裁剪、标签点击筛选都只按 `folderIds` 判断（`src/modules/library/model.ts:166`、`src/modules/library/dataChange.ts:385`、`:406`）。

### 1.3 文件夹拖放只支持单个

- 拖放载荷只有两类：图片集合或单个文件夹（`src/shared/useDragSort.ts:4`）。
- 文件夹行的 `pointerdown` 只传一个 `node.id`（`src/modules/library/FolderTree.tsx:374`）；`LibraryWorkspace` 的拖放回调也只处理一个 `item.folderId`（`src/app/LibraryWorkspace.tsx:308`）。
- 落在文件夹中间表示“移入”，落在上/下四分之一表示“放到前面/后面”（`src/shared/useDragSort.ts:99`、`:109`）。`canDrop` 只按单个被拖文件夹判断是否落入自身或后代（`src/app/LibraryWorkspace.tsx:365`）。
- 后端 `move_to` 只移动一个文件夹（`src-tauri/src/library/folders.rs:194`）；`reorder` 虽然支持多个 id，但要求全部已经在同一父级（`:340`）。
- Shift 范围选择、Ctrl 多选与悬停展开已经存在（`FolderTree.tsx:177`、`useDragSort.ts:231`），多选拖动需要与它们共存。

### 1.4 窗口与展开状态都不持久化

- 主窗口由 `tauri.conf.json` 固定 `center: true`、1440×900、最小 1040×640（`src-tauri/tauri.conf.json:13`、`:21`）。项目没有窗口状态插件，`Cargo.toml` 里也没有对应依赖（`src-tauri/Cargo.toml:35`）。
- 窗口按钮只提供最小化、最大化、关闭、全屏命令（`src-tauri/src/app/commands.rs:123`），没有保存位置与大小。
- `FolderTree` 的 `expanded` 初始化时展开顶层节点（`src/modules/library/FolderTree.tsx:105`），之后没有写回任何存储。`initialized` 只保证每个组件实例执行一次；换库时组件不重新挂载，旧库的展开 id 会残留。
- 展开状态只存在组件内存里，重启应用必然回到“展开全部顶层”。

### 1.5 记录标题不带路径

- 移动文件夹固定写“移动文件夹”（`src-tauri/src/library/folders.rs:212`），删除固定写“删除文件夹”（`:402`）。多选移动会进一步放大“看不出动了哪些文件夹”的问题。
- 创建标题已经包含路径（`:84`）；重命名只写新名称（`:130`），本批次不处理。

## 二、目标行为

### 2.1 文件夹树只保留手动顺序

- 移除标题栏的常驻排序按钮、排序弹层与 `lilith.folderSort` 存储；树始终按 `sortIndex`、再按 id 显示。
- 右键任一文件夹（包括“全部图片”根行）出现“排序子文件夹…”。没有子文件夹时该项禁用；根行只提供这一项排序动作。
- 排序对话框：

  - 依据：名称 / 图片数（含子文件夹）。
  - 方向：升序 / 降序。
  - 选项：包含所有后代。没有更深层可排时禁用，并说明只影响哪些层级。
  - 一句后果提示：会改写这些文件夹的手动顺序，可用一次撤销恢复。
  - 确认后一次写入，完成后提示实际调整了多少个文件夹；顺序没有变化时不写记录。

- 排序只改 `sort_index`，不改物理目录、不改图片归属、不刷新图片列表；只更新文件夹树与计数。
- 不勾选递归时，只重排目标文件夹的直接子文件夹；勾选后，目标文件夹及其每个后代都各自重排直接子文件夹，层级不混合。

### 2.2 直属图片虚拟行

- 当文件夹同时满足“有直接子文件夹”和 `directImageCount > 0`，并且处于展开状态时，在它的文件夹行下面显示一行“直属图片 N”。N 为直属图片数。
- 该行不是真实文件夹，不参与 Shift 范围选择、不参与 Ctrl 多选、不能作为拖动载荷、不能作为放置目标、不显示文件夹右键菜单。
- 点击虚拟行后：当前筛选变为“只包含该文件夹的直属图片”；文件夹树中该父文件夹保持选中，虚拟行显示为当前项；面包屑在当前文件夹后追加“直属图片”。
- 面包屑：

  - 点击“全部图片”清空文件夹筛选并退出直属模式。
  - 点击父文件夹名称回到该文件夹的“含子树”视图，退出直属模式。
  - 点击“直属图片”保持直属模式。

- 多选文件夹时删除直属标记；选择变化、换视图、删除当前文件夹时同样退出直属模式，避免留下指向不存在范围的筛选。
- 直属模式可以和标签、评分、扩展名、搜索等现有筛选叠加；排序、选择、批量任务等沿用当前查询。
- 根目录不显示虚拟行；根目录的直属图片仍包含在“全部图片”中。

### 2.3 多选文件夹拖动

- 按下已选中的文件夹行并拖动时，载荷是全部选中的文件夹；按下未选中的行时只拖该行，不改变原选择。
- 拖动载荷显示“N 个文件夹”或单个名称。
- 落点语义：

  - 落在文件夹中间：全部文件夹移入目标文件夹；若目标就是它们当前的父级，则移动到该级末尾。
  - 落在某文件夹上/下边缘：全部文件夹移动到该文件夹所在父级，并保持拖动前彼此的相对顺序，整体插入到目标之前/之后。
  - 落在根行：全部移入根目录末尾。

- 选中集合里同时有父与子时，只保留最外层父；子文件夹随父移动，不单独再移动一次。
- 任一被拖文件夹与目标相同，或目标是任一被拖文件夹的后代时，禁止放置并提示“不能把文件夹移动到自身或子文件夹”。
- 目标父级已有同名文件夹、被拖文件夹之间 leaf 重名、磁盘目录冲突时，整次操作失败，不做部分移动。
- 一次拖动写一条操作记录，撤销整体回退；同名冲突、权限失败等错误只提示，不留下部分状态。
- 悬停展开、拖到树边缘自动滚动、Esc 取消、拖动结束后的 click 抑制保持现有行为。

### 2.4 窗口与展开状态

- 窗口状态交给 Tauri 插件：保存位置、大小、最大化；不保存全屏、可见性或边框状态。
- 启动时插件恢复状态后，再检查窗口可见性：

  - 与任一显示器有至少 120×40 物理像素的交集就保留。
  - 完全在屏幕外：窗口回到主显示器居中。
  - 未最大化但尺寸超过所在显示器：收缩到该显示器尺寸以内，再居中。
  - 最大化状态不主动改成普通窗口。

- 文件夹展开状态按图库保存：

  - 存储键包含图库 id，值为展开文件夹的相对路径数组。
  - 没有保存记录时，默认展开顶层文件夹。
  - 有记录时按路径映射回当前 id；已经不存在或改名的路径忽略。
  - 展开/折叠、拖动悬停展开、因选中而自动展开祖先都会更新记录。
  - 换库后各自恢复；当前选中文件夹的祖先仍会自动展开，优先于保存的折叠状态。

## 三、数据与接口

### 3.1 浏览筛选增加 `folderDirect`

`LibraryFilters` 增加一个可选布尔字段，默认 `false`：

```rust
#[serde(default)]
pub folder_direct: bool,
```

前端 `LibraryFilters` 增加 `folderDirect: boolean`，`emptyFilters` 返回 `false`，`normalizeFilters` 原样保留，查询键与查询身份自动包含它。

SQL 语义：

- `folder_direct = false`：保持现有子树条件。
- `folder_direct = true` 且 `folder_ids` 非空：使用选中 id 本身，`images.folder_id IN (?, …)`，不再展开后代。
- `folder_direct = true` 且 `folder_ids` 为空：等价于没有文件夹限制（前端不会产生这种状态）。
- 根目录 id 在直属模式下只匹配 `folder_id = root_id`，不能沿用“空路径等价整库”的快捷分支。
- 文件夹分面仍按原有“排除自身维度”的规则，不应用文件夹条件；其它分面应用直属条件。

接口边界：

- MCP 的 `McpQuery::to_library_query` 显式写 `folder_direct: false`，本批次不把直属模式暴露给 MCP（留给 MCP 批次评估）。
- 任务范围 `Folder { include_subfolders }` 已有自己的直属于段，不改。
- 标签点击筛选在 `scope = "folder"` 时保留 `folderDirect`；`rowInTagScope` 在直属模式下要求图片所在路径正好等于选中文件夹路径。
- 数据变化裁剪选择时，`selectionAfterChange` 的文件夹分支读取 `query.filters.folderDirect`：直属模式下图片移动到子文件夹即离开结果；移动到所选文件夹本身仍保留。
- `filterSummary` 与活动筛选提示在文件夹计数后追加“（直属）”。

### 3.2 新增批量放置命令 `place_folders`

用途：把多个文件夹一次移动到目标父级，并可插入到指定位置。

```rust
pub struct FolderPlacement {
    pub folder_ids: Vec<i64>,
    pub parent_id: i64,
    /// None 表示追加到末尾；Some(n) 表示最终同级顺序中的插入位置。
    pub sort_index: Option<i64>,
}
```

执行顺序：

1. 去重并按当前显示顺序保留；去掉被另一个选中文件夹包含的后代，只保留最外层。
2. 校验 id 有效、都是普通文件夹、不是临时文件夹；目标父级有效且不是任一被拖文件夹本身或后代。
3. 计算每个文件夹的新路径；拒绝 leaf 重名、已存在路径、磁盘目标目录已存在、源目录不存在。
4. 逐个 `fs::rename`；任一失败时按相反顺序把已移动目录搬回，整体失败。
5. 在同一写事务里更新每个子树的 `path`，设置目标父级新的同级顺序，写入操作记录。
6. 事务失败时同样反向搬回目录。

历史记录：

- 一次操作一条 `FolderMove` 记录，标题包含目标路径，例如“移动 3 个文件夹到「画作/线稿」”。
- 每个被移动文件夹写一条现有 `FolderPathChange`（旧/新路径、旧/新排序位）；路径不变但排序位变化的文件夹也写，撤销与重做按当前路径判断方向，现有逻辑可直接复用。
- 目标父级中因插入而位移的其它兄弟文件夹，写入新的排序变化 chunk（id、旧排序位、新排序位）。为此在 `ChunkFormat` 增加一个 JSON 子类，撤销时恢复旧值、重做时恢复新值；旧记录不受影响。
- 旧父级中被移走的兄弟不重排；删除元素后相对顺序不变，留下的空位不影响显示。
- `affected` 为被移动的文件夹数。

前端路由：

- 落在文件夹中间 → `placeFolders(ids, targetId, null)`。
- 落在根行 → `placeFolders(ids, rootId, null)`。
- 落在上/下边缘 → 先确定目标父级；如果所有被拖文件夹本来就在该父级，调用现有 `reorderFolders(ids, parentId, index)`，保持一条 `FolderReorder` 记录；否则调用 `placeFolders(ids, parentId, index)`，一次完成跨父级移动与插入。
- 插入位置按“排除被拖文件夹后的同级顺序”计算，保持被拖文件夹之间的当前顺序。

### 3.3 现有 `reorder_folders` 支持多选

后端已经支持多个 id；前端只需要：

- 把被拖文件夹按当前 `sortIndex`、id 排序后传入；
- 落点索引按排除这些 id 后的兄弟列表计算；
- 失败时提示，不改本地顺序。

### 3.4 新增一次性排序命令 `apply_folder_order`

前端已经持有全部 `FolderInfo` 与计数，名称排序使用现有 `Intl.Collator("zh-Hans-CN", { numeric: true, sensitivity: "base" })`，因此顺序在浏览器侧计算，后端只负责校验与写入。

```rust
pub enum FolderSortKey { Name, Total }

pub struct FolderOrder {
    pub parent_id: i64,
    pub folder_ids: Vec<i64>,
}

pub fn apply_folder_order(
    db: &LibraryDb,
    folder_id: i64,
    key: FolderSortKey,
    descending: bool,
    recursive: bool,
    orders: &[FolderOrder],
) -> AppResult<Vec<FolderInfo>>;
```

契约：

- `folder_id` 是排序起点；`orders` 中出现过的父级必须等于它或位于它的子树内。
- 每个 `FolderOrder.folder_ids` 必须恰好覆盖该父级的全部普通子文件夹一次；父级不存在、集合不完整、重复 id 都拒绝。
- 递归只影响前端生成哪些父级；后端按 orders 执行，不自行展开。
- 在一个写事务里把每个父级的子文件夹重编号为 `0..n-1`；只记录实际变化。
- 一次排序一条 `FolderReorder` 记录，标题包含起点路径、依据与是否递归，例如“按图片数排序「画作」的子文件夹（含所有后代）”。
- 没有任何变化时不建记录，返回当前文件夹列表。
- 前端限制 orders 的父级数与总 id 数（建议 20,000 个父级、100,000 个 id），避免异常载荷。

前端排序辅助：

- 名称：现有 collator，平手按 id 升序。
- 图片数：`totalImageCount`，降序时反向；平手按 id 升序。
- 不勾选递归：只生成起点文件夹的一组 order。
- 勾选递归：对起点及其所有后代中“子文件夹数 ≥ 2”的父级各生成一组 order。

### 3.5 虚拟行与展开状态的前端模型

- `flattenVisible` 继续保持“只返回真实文件夹行”，Shift 范围选择、锚点与拖放目标不变。
- 渲染时在真实文件夹行之后插入虚拟行，条件：已展开、有子文件夹、`directImageCount > 0`。虚拟行使用 `node.depth + 1` 的缩进。
- `FolderTree` 新增 props：`directFolderId: number | null`、`onSelectDirect: (folderId: number) => void`、`libraryId: string`。
- 展开状态：

  - 存储键：`lilith.folderExpanded.<libraryId>`。
  - 值：文件夹相对路径字符串数组。
  - 初始化：读取并映射为 id；没有记录时展开顶层；读取失败按没有记录处理。
  - 写回：展开集合变化后写入；捕获存储异常，不阻塞交互。
  - 文件夹删除/改名后裁剪不存在的 id。

### 3.6 窗口状态插件

- `Cargo.toml` 增加 `tauri-plugin-window-state = "2"`；`lib.rs` 在 `Builder` 上注册。
- 只启用 `POSITION | SIZE | MAXIMIZED`，不保存全屏、可见性与边框。
- 插件按 Tauri 约定写入系统应用配置目录；用户已确认接受，不要求随便携目录迁移。
- 启动后增加一个纯函数式校验：给定保存的物理矩形与显示器矩形列表，返回“保留 / 居中 / 收缩后居中”。`lib.rs` 在 `setup` 里读取窗口当前位置与 `available_monitors()` 并应用。
- 收缩阈值：至少保留 120×40 物理像素可见；尺寸上限为所在显示器尺寸，留 40 像素边距；最大化状态不调整尺寸。

### 3.7 记录标题

- `FolderMove`：单文件夹标题“移动文件夹「旧路径」”；批量标题“移动 N 个文件夹到「目标路径」”。
- `FolderDelete`：标题“删除空文件夹「路径」”。
- 路径在进入写事务前用读连接读取；极端情况下若路径在读取后、事务前被改动，标题可能短暂滞后，但操作本身仍以事务内路径为准。保持实现小、不动记录格式。

| 目标 | 子树计数 | 直属计数 | 直属 150 张分页 |

## 八、边界、风险与后续

不做：

- 不改文件夹物理目录布局、不引入虚拟目录。
- 不做跨图库拖放。
- 不保留常驻排序模式或隐藏的 `localStorage` 排序开关。
- 不提供多选文件夹的“直属图片”合并筛选；直属入口只针对单文件夹。
- 不把直属模式暴露给 MCP；不改任务范围 `includeSubfolders` 的既有语义。
- 不改 `FolderRename` 标题。
- 不改文件夹删除的前置条件（仍只删空文件夹）。

风险与已知边角：

- 多文件夹移动涉及多次目录 rename，文件系统本身没有事务；实现必须先全部校验，再按顺序移动，失败时反向搬回。断电等不可控中断仍可能留下部分目录移动，这与现有单文件夹移动同级，不在本批次扩大处理范围。
- 新的排序变化 chunk 必须保持旧 `FolderMove` 记录兼容；撤销/重做测试要覆盖旧记录。
- 窗口插件把状态写入系统应用配置目录，用户已确认接受；它不负责屏幕可见性，必须在启动后补校验。
- 虚拟行不进入 Shift 范围选择，用户从父行 Shift 到下一行时不会选中虚拟行；这是有意行为，避免把“只看直属”混进多选。
- 展开状态存路径，改名/移动后的子树会丢失展开；可以接受，避免为改名维护 id 映射。
- 直属筛选在回收站视图叠加 `purge_operation_id` 时可能逐行回表；真实库当前回收站为空，先按普通视图验收。若后续回收站量大，再评估索引。
- 一次性排序的顺序由前端计算，若排序期间文件夹被外部创建/删除，后端会拒绝并提示重试；不会静默使用过期集合。
