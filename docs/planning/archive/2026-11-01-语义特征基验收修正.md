# 语义特征基验收修正（2026-11-01）

主库实测首次建基与「个人」子树回填之后，用户在真实窗口里发现两处问题，这一轮修掉并补齐口径。记录只写改了什么、为什么改、验证到什么程度；当前状态见[当前状态](../current-handoff.md)，剩下的事在[待办](../todo.md)第 19 组。

## 一、模式门限改成跟随范围

原实现里「偏重主体 / 偏重构图」要求**全库**没有待补齐的语义描述子，用户只回填了「个人」子树（1 477 张）时两个模式一直置灰，提示“剩余 422 740 张”。但重排候选本来就只来自当前范围，范围内的描述子齐了就够用。

- Rust：`pending_descriptors(handles, model, dim, basis_id, scope)` 取代原来的全库 `feature_pending`；`Folder` / `Collection` / `View` / `Temp` / `Library` 走 `TaskScope::to_library_query()` + `query::pending_stats`，`Selected` 走 `query::selected_pending_stats`（`json_each` 展开，一条语句）。`similar_ids_by_feature` 与 `semantic_feature_pending` 都改成按范围统计，错误文案区分「全库还有 N 张」与「当前范围还有 N 张」。
- 前端：`get_semantic_feature_pending` 增加 `scope` 参数，找相似面板按当前范围查询并在换范围时重新统计；置灰文案改成「本范围内还有 N 张没有语义特征」。
- 附带收益：个人范围（1 477 行）的计数从 1.6 s 降到毫秒级。

## 二、取消任务不再切 meta

`execute` 原来只判断 `outcome.is_ok()`，而取消路径也返回 `Ok(())`（终态由任务总线按取消标记决定），于是**中途取消也会把 `meta.feature_basis` 切到新基**：已处理图片指向新包、未处理图片留在旧包，两种模式的检索会同时失真，与“取消不动 meta、旧包继续服务”的设计相反。

改成 `outcome.is_ok() && !task.should_cancel()` 才提交。新增两个单测：`completed_run_switches_basis_meta`（跑完切 meta）与 `cancelled_run_keeps_previous_basis_meta`（假服务在收到第一张图时请求取消，跑完这一张但 meta 不变）。

## 三、两个热读命令改为异步

`get_feature_summary`（5.4 s）与 `get_semantic_feature_pending`（1–6.6 s）原来写成同步命令，跑在 Tauri 主线程上，查询期间整个界面冻住——用户感知是“筛选、相似都卡三秒，UI 都卡”。两条改走 `run_blocking`（`spawn_blocking`），与 `get_library_stats`、`find_similar_images` 同一套写法；慢只慢在面板数据上，界面不再停。命令名与前端调用方式不变，`trace::read_async` 保留同样的慢查询与失败记录。

## 四、代码与文档清理

- `descriptors::rerank` / `pointers`：包名已进入过滤条件，按包分组变成死代码，改为单包 mmap + 单次偏移查询；`pointers` 不再返回包名。
- `basis::write_pair`：临时文件改用 `std::fs::rename` 落盘（原注释说“Windows 上 rename 不能覆盖已有文件”是错的，`std::fs::rename` 会用 `MoveFileEx` 覆盖），换基不再留半份文件。
- `ensure_image_capability` 改用 `AiError::invalid`，删掉三处手写结构体；`basis_cancel` 去掉多余的 `let _ =`；`client::basis_finish` 的注释改成“1536 维协方差”。
- `fit_basis.py`：删掉已经不起作用的 `--seed`，`--maxsim-sample` 默认值与应用对齐（200 → 1400）。
- `mcp_features` 视图说明补上 `spp` / `maxsim` 与对应 dim 口径（视图本来就会返回这两类行，文档只写了 embedding / pose）。
- `todo.md` 第 19 组按现实库证据重写：首次建基、每图三条记录、失败 0 已在主库验证；剩下拟合阶段观感与取消、小库兜底、全量回填、换基演练、换库、v12 升级、三模式真实验收。
