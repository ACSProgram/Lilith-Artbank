## 转换结果（2026-10-24）

- 主库 `G:\Lilith Image Library`：393 151 条旧记录 → 390 788 个唯一内容 → 390 542 张入库；2 363 条重复按内容合并（标签并集、评分取高、导入时间取早、描述保留首个非空）；81 649 条 pose 转 f32；556 个标签；耗时 17 230.3 s（约 4 h 47 min）。
- 测试库 `G:\Lilith Test Library`：旧 `测试` 图库整体移出主库后按单库模式迁移，9 455 张、0 失败/重复、87 条 pose；耗时 147.6 s。
- 颜色与 pHash 不搬运，按新算法重算；缩略图重建为 512px WebP 写入追加式 pack；旧 pHash 文件名改为 `<BLAKE3>.<ext>`。
- 失败内容：246 条超过 1 亿像素的记录 + 1 条未引用副本，共 247 条、7.3 GiB，连同文件夹/标签/评分/描述/pose/BLAKE3/尺寸移到 `G:\Lilith Image Library Failed`，`manifest.jsonl` 保留可识别信息。这批内容至今未入库。
- 清理：两库旧 `.data`、`recycle`、`output`、`temp`、孤儿与重复隔离区已删除（主库约 41.7 GiB）；库内 `.artbank/migration` 已删除。
- 校验：`verify --hash` 两库 integrity=ok，缺失/大小/元数据/缩略图/pose/哈希全为 0，未引用文件 0；最终复验未重算 690 GiB 原图哈希。

## 迁移期确立、今天仍生效的决定

这些结论已落在[系统架构](../../architecture/overview.md)的“关键取舍记录”与各模块契约里，迁移期文档不再重复论证：

- 元数据只走 SQLite（bundled，不附 DLL），页面查询用键集游标，不整库载入。
- 原图按 BLAKE3 内容哈希命名，图片 id 作稳定代理键；pHash 只用于相似度。
- 缩略图与特征写追加式 `.pack`，数据库只记指针；实测随机读比逐文件快约 16 倍。
- 浏览器只解码当前页缩略图，不引入 DDS/BC 与 WebGPU 自绘管线。
- 单库会话，设置只存一个 `libraryPath`；文件夹是真实磁盘目录，路径本身是身份。
- AI 走本机 HTTP `/v1`，应用托管 Python 进程；embedding 用 SigLIP2 1536 维 fp16 + 均值中心化，旧库的 1024 维 CLIP 向量不搬运。
- 姿势相似度按旧程序 1:1 移植，权重与索引不得自行改动。
- 不做 PinBoard/PasteBoard/ImagePaste、调色盘、色彩测试、截屏小工具。
- 设置与日志写在程序根目录，不读旧 AppData 设置、不做设置迁移；v1 设置的 `libraries[]`/`lastLibraryId` 在读取时收敛为单个 `libraryPath`，之后不再写回旧字段。
