## A. 立即修（会误导 AI 或让用户白操作）

### A1. 语义搜索：明确要求英文（AI 说明 + 界面提示）

- **现状**：中英文向量实测差异明显（无关句余弦 0.607 vs 0.328；「用自己的描述找回自己」中文 1/3、英文 3/3）。工具描述里没有任何语言提示；界面占位文案用的是中文例子，进一步引导中文输入。
- **改哪里**：
  - `src-tauri/src/mcp/server.rs`：`find_similar` 描述加一句「语义检索（`mode=text`）请用英文描述，中文命中质量明显下降」。
  - `src/modules/library/LibraryView.tsx:1695` 占位文案、`:1683` 按钮 `title`：改成英文示例（如 `a woman in a red cloak, side view`），并保留一句「中文可用但英文更准」。
- **规模**：纯文案，2 个文件、约 6 行。零逻辑风险。

### A2. 临时区同内容会挡住图库导入（对应 `todo.md` 待决策项）

- **现状**：先导临时区、再导图库，`duplicatePairs` 指向临时行（`imageId` 在 `.artbank-temp`），图库一张都进不来。
- **改哪里**：`src-tauri/src/library/import.rs:215 find_by_hash_state` 增加「是否包含临时区」的参数；图库导入（`import/pipeline.rs:327/951`）传「排除临时」，临时导入保持现有口径。回执里把这类命中单独计数（见 C1）。
- **规模**：Rust 约 40 行 + 1~2 个测试；**但口径要先定**（见 C1），否则返工。

### A3. `similarity` 选择器的 `limit` 在写入时不生效

- **现状**：`selection.rs:340` 注释写明「写入按全部命中解析，`limit` 只影响读取分页」。实测 `find_similar(limit=20)` 后用 `limit:3` 选，`dryRun` 给 `selected:20`。同理，写入最多取 10000 条（`MAX_SELECTION_LIMIT`），不是「全部」。
- **判断**：行为是**有意设计**，问题在 schema 与描述没说明，AI 会按字面理解。
- **两条路**（需选一条）：
  1. 删掉写入选择器里的 `limit` 字段（读路径 `resolve_page` 另有一套），文案写「写入取结果槽全部命中（最多 10000 条）」——约 10 行，最省。
  2. 让写入也按 `offset/limit` 切片 —— `selection.rs` 写入分支加切片约 15 行 + 单测，语义更符合直觉。
- **规模**：小。

### A4. 普通图库的特征生成保持不开放（确认）

- **决定**：按你的意见维持刻意设计，不给 MCP 开。
- **但要补文案**：`import_start` 与 `tasks_get` 的描述加一句「通过 MCP 导入的图片没有语义特征，语义搜索找不到它们；需要用户在界面手动运行批量 AI 任务」。否则 AI 导完会承诺「帮你找相似的」。
- **规模**：2 处描述字符串。

## C. 待你决定（决定前不要动代码）

### C1. 临时区重复的口径（已决策：丢弃临时行再入库）

同一张图既在临时区、又要入库时怎么算「重复」：

- **方案 1（已采纳，实现时修正）**：图库导入查重忽略临时行。注意：`images.content_hash` 是全表 `UNIQUE`，只让查重忽略临时行仍会被唯一约束挡住，所以实现成「写事务里先删掉占着该哈希的临时行，再正常入库」，临时目录里的副本在提交后清理；被丢弃的行数记 `tempReplaced`。
- **方案 2**：仍然算重复，但回执里单独标 `tempDuplicatePairs`，提示「关库后会消失，重新导入即可」。不解决「想入库」，只解释原因。
- **方案 3**：入库时接管临时行（把 `folder_id` 改成目标文件夹、补一条操作记录），不重复复制文件。最干净，但要动导入管线与撤销语义，风险最大。

### C2. 临时导入自己的查重范围

现在临时导入也会命中图库里的同内容图。要不要区分「临时区内部重复」「与图库重复」两类？影响 A2 的实现。

### C3. `similarity.limit`：删字段（A3-1）还是实现切片（A3-2）

**已采纳 A3-2**：写入按 `offset` / `limit` 切片，省略 `limit` 时仍取整个结果槽。

### C4. 要不要给 MCP 加文件夹写操作（已采纳，扩展为四种动作）

实测澄清：文件夹删除**不是回收站功能**，`library/folders.rs:365` 只允许删「没有子文件夹、没有图片、磁盘目录为空」的文件夹，有内容直接报错。所以风险很低。
现在的问题是 `images_move` 会自动建目录，MCP 却没有删除入口：不撤销就留下空目录（撤销能连带清掉，实测过）。

**已实现**：新增 `folders_modify`，`action` 取 `create` / `rename` / `move` / `delete`，四种动作都走操作记录、都能撤销，临时文件夹与根目录不可改名/移动/删除；询问档下 `move` / `delete` 需确认。领域层补 `create_with_id` / `rename_with_id` / `move_to_with_id` / `delete_with_id` 与 `info` / `find_id` / `deletion_blocker`（删除判据与真删共用，`dryRun` 与执行同口径）。

### C5. 回收站图片 `capabilities.embedding=false` 的含义

这些图其实有向量，只是不参与扫描。字段名容易被读成「没算过」。

**已处理**：读代码确认 `capability::image_capabilities` 查的是 `feature_blobs` 是否存在，就是「算没算过向量」，不改值；只在 `docs/modules/mcp.md` 的 `images_get` 说明里补一句「有没有向量 ≠ 参不参与全库扫描」。

### C6. 语义搜索是否只做「提示英文」

**已按「提示即可」实现**：工具描述与界面占位文案都写明用英文，不做翻译层、不换多语言文本塔；质量本身留给独立阶段。

### G2. 本轮新发现

**N1（已修）`folders_modify` 的操作记录没有「AI · 」前缀。** 用户截图反馈：`新建文件夹「MCP实测/子目录A」`、`重命名文件夹为「子目录B」`、`删除文件夹` 三条都没有前缀，而同屏的「AI · 导入 1 个路径」「AI · 移动图片到「test」」都有。

- **根因**：前缀只写在两条收尾路径里——`mcp/tools/write.rs::finish_write`（评分/标签/描述/回收站/集合）与 `app/state.rs`（导入、移动任务）；`mcp/tools/folder.rs::finish` 只做了界面刷新，漏了 `history::prefix_label`。
- **改动**：`folder.rs` 新增 `mark_ai_origin(database, operation_id)` 并在 `finish` 里调用，四种动作统一；补单测 `folder_operations_are_labelled_as_ai_writes`（依次建/改名/删，断言标题以「AI · 」开头，且 `None` 时不报错）。
- **验证**：`cargo test --lib` 298 通过、5 ignored。**界面复查需要重启应用**——复跑时运行的是修复前的二进制，所以截图里仍是旧行为。

**其余写入路径已逐条核对，没有第二处遗漏**：`images_update` / `images_trash` / `images_restore` / `collections_create` / `collections_modify` / `collections_membership` 走 `finish_write`；`images_move` 与 `import_start` 由 `state.rs` 的任务收尾统一打前缀（`start_mcp_import` 里由 `from_mcp` 决定 label）；`temp_features_generate` 明确不写操作记录、`history_undo`/`history_redo` 只改状态不新建记录，两者本就不需要前缀。界面上「永久删除」「移入回收站」没有前缀是正确的——它们是在界面里点的。

**N2（未修，建议单独处理）`FolderDelete` / `FolderMove` 的记录标题不带路径。** `library/folders.rs` 里这两处用的是固定文案「删除文件夹」「移动文件夹」，界面上看不出动的是哪个文件夹；`FolderCreate` / `FolderRename` 是带名字的。改它会影响界面记录，属另一处口径，本轮不动。
