# 命令记录与日志轮换计划

日期：2026-10-28
状态：已实现并归档（2026-10-28）。自动检查通过，真实窗口验收未做，验收清单在[待办与待决策](../todo.md)的“日志与命令记录”。
范围：只做「命令记录」与「日志轮换」，对齐 Lilith Artworks 的**常规档**（事件驱动、常开、零噪声）。不含诊断档的周期性探针、取证通道与看门狗。

## 1. 目标

出问题时能只靠 `logs/` 回答三个问题：

1. 用户刚才做了什么？——每条写命令的 `started` / `finished` 成对出现，顺序即操作顺序。
2. 那一步成没成、花了多久？——`finished` 带 `elapsed_ms`，失败带错误原文。
3. 这是哪一次运行？——每行带 `[run:xxxxxx]`，可按运行从轮转文件里切出单次会话。

以及三个已确认的缺陷要一并修掉（见 2.2、2.3、2.4）。

## 2. 现状核实

### 2.1 已有的

`src-tauri/src/lib.rs:42-57` 接好了 `tauri-plugin-log 2.10.1`：

- `TargetKind::Folder` → 程序根目录 `logs/lilith-artbank.log`
- `TargetKind::Stdout`
- `.level(LevelFilter::Info)` 写死
- `max_file_size(4_000_000)`、`RotationStrategy::KeepSome(5)`
- panic hook 落 `log::error!("panic: ...")`（`lib.rs:64-68`）

代码里 100 处日志调用：warn 65、error 14、info 13、debug 8、trace 0。
`logs/lilith-artbank.log` 跨 3 天只有 44 行，内容仅启动横幅、schema 升级、MCP 启停。

### 2.2 缺陷一：日志时间是 UTC

插件默认格式闭包用的是 `DEFAULT_TIMEZONE_STRATEGY`（`UseUtc`），与 `Builder::timezone_strategy()` 无关。实测：日志最后一行 `[2026-10-27][08:46:17]`，而文件 mtime 是本地 `16:46`，差 8 小时。排查时日志时间与用户描述的时间对不上，必须改成 `UseLocal`。

### 2.3 缺陷二：`debug` 是死代码

`Builder::level()` 设置的是 fern `Dispatch` 的静态过滤，早于 `log::set_max_level` 生效且不受其影响。等级写死 Info 后，8 处 `log::debug!` 在调试构建里也不会输出。去掉 `.level()`，改由 `log::set_max_level` 统一控制，才能让调试构建拿到 debug 档。

注意：`log` crate 的 `max_level` 默认是 `Off`。一旦去掉 `.level()`，就必须在**构建插件之前**调用 `set_max_level`，否则整份日志全空。

### 2.4 缺陷三：命令层零记录

89 个 `#[tauri::command]`，`commands.rs` 里 0 条日志。命令失败只以 `Result<_, String>` 回前端，日志里查不到。命令形态统计：

| 分类 | 数量 | 说明 |
| --- | --- | --- |
| 写命令（改变状态或有外部副作用） | 51 | 同步 35、异步 16 |
| 读命令（返回 `Result`，不改变状态） | 30 | 同步 15、异步 15 |
| 无 `Result` 返回值 | 8 | `get_settings`、`get_mcp_status`、`list_mcp_approvals`、`inspect_library_path`、`get_app_info`、`list_tasks`、`get_similarity_groups_result`、`get_optimize_estimate` |

命令体高度规整：89 个里 64 个是单表达式（`AppError::command(state.xxx(..))` 或 `run_blocking(app, move |state| ..).await`）；需要包装的 81 个里 57 个单表达式、24 个多行，多行中 15 个带 `?`。

## 3. 设计

### 3.1 等级策略

对齐常规档：**发布构建 Info、调试构建 Debug**，环境变量 `LILITH_ARTBANK_LOG_LEVEL` 覆盖（`off|error|warn|info|debug|trace`）。

- 在 `run()` 开头、构建 `tauri::Builder` 之前调用 `log::set_max_level(trace::baseline_level())`。
- 删除 `.level(log::LevelFilter::Info)`。
- 不提供设置页开关，不做运行时切换（那是诊断档的事）。

### 3.2 行格式与运行标识

自定义 `format` 闭包，对齐参考项目的可解析前缀：

```text
2026-10-28 17:13:30[run:3f9a12][INFO][command] command finished: name=trash_images elapsed_ms=12 outcome=ok
```

- 时间：`TimezoneStrategy::UseLocal.get_now()`，秒级；毫秒精度由消息里的 `elapsed_ms` 承担，不放进前缀（避免每行多 4 字符）。
- `run_id`：6 位十六进制，`OnceLock` 缓存，取值为启动纳秒低位与进程号异或。同一次运行内稳定、不同次大概率不同。
- `target`：命令记录统一用 `target: "command"`，便于 `grep '\[command\]'`；其余日志仍用模块路径。
- 保留 `[LEVEL]` 与 `[target]` 位置不变，现有 grep 习惯不失效。

### 3.3 轮换

参数维持用户确认值，只把它们提成具名常量并补一行启动记录：

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `LOG_MAX_FILE_SIZE` | `4_000_000` | 单文件 4MB |
| `LOG_KEPT_FILES` | `5` | 保留 5 份归档 |

实际行为（已核对插件源码 `tauri-plugin-log-2.10.1`）：

- 活动文件 `logs/lilith-artbank.log`；
- 轮转时改名为 `logs/lilith-artbank_2026-10-28_17-13-30.log`（秒级时间戳，本地时区）；
- `KeepSome(5)` 保留 5 份归档，**活动文件不计入**，因此上限是 6 个文件约 24MB；
- 秒级文件名使同名 `.bak` 分支实际不会触发。

不做时间轮换：插件只支持按大小，按天轮换需要自写 rotator，超出本批次范围。

### 3.4 命令记录分档

| 档 | 覆盖 | 成功 | 失败 | 慢 |
| --- | --- | --- | --- | --- |
| 写命令（51） | 51 个 | `started` + `finished`（含 `elapsed_ms`） | `warn` | — |
| 读命令（30） | 30 个 | 不记录 | `warn` | 超过阈值记 `warn` |
| 无 `Result`（8） | 不包装 | — | 无失败路径 | — |

- 写命令低频（用户操作驱动），成对记录才有时间线价值：进程在操作中途崩溃时，只有 `started` 没有 `finished` 就是现场证据。
- 读命令里 `query_images`、`query_image_ids`、`get_image_states`、`get_viewer_source` 会随滚动和翻页反复触发，成功不记录是硬要求。
- 读命令慢阈值默认 500ms（元数据分页预算 50ms 的 10 倍）；`semantic_search`、`find_similar_images` 在大库上天然较慢，单独用 3000ms。
- 不记录命令参数：参数含路径、文件名、描述文本等用户内容，且数量类信息已由操作记录表承担。需要关联时用 `[run:]` + 时间戳对齐 `history` 表。

### 3.5 API

新建 `src-tauri/src/app/trace.rs`，导出 8 个函数：

> `format` 的签名要与插件要求一致：`Fn(FormatCallback, &std::fmt::Arguments, &log::Record) + Send + Sync + 'static`。`FormatCallback` 走 `tauri_plugin_log::fern::FormatCallback`（插件 `pub use fern`），不新增依赖。

```rust
/// 本次运行的短标识（6 位十六进制）。
pub(crate) fn run_id() -> &'static str;

/// 基线等级：LILITH_ARTBANK_LOG_LEVEL 优先，否则调试构建 Debug、发布构建 Info。
pub(crate) fn baseline_level() -> log::LevelFilter;

/// 日志行格式：本地时间 + [run:xxxxxx] + [LEVEL] + [target]。
pub(crate) fn format(out: FormatCallback, message: &Arguments, record: &Record);

/// 写命令：started/finished 都记，失败记 warn。
pub(crate) fn write<T>(name: &str, run: impl FnOnce() -> Result<T, String>) -> Result<T, String>;
pub(crate) async fn write_async<T>(
    name: &str,
    run: impl Future<Output = Result<T, String>>,
) -> Result<T, String>;

/// 读命令：成功不记，失败与超阈值记 warn。
pub(crate) fn read<T>(name: &str, run: impl FnOnce() -> Result<T, String>) -> Result<T, String>;
pub(crate) async fn read_async<T>(
    name: &str,
    run: impl Future<Output = Result<T, String>>,
) -> Result<T, String>;

/// 读命令的慢阈值可调版本，供语义搜索与找相似使用。
pub(crate) async fn read_async_with<T>(
    name: &str,
    threshold_ms: u64,
    run: impl Future<Output = Result<T, String>>,
) -> Result<T, String>;
```

调用点写法（不改变原有控制流，`?` 留在闭包内仍然正确）：

```rust
// 同步写命令
pub fn trash_images(state: State<'_, AppState>, image_ids: Vec<i64>) -> Result<u64, String> {
    trace::write("trash_images", || AppError::command(state.trash_images(&image_ids)))
}

// 异步读命令
pub async fn get_tags(app: AppHandle, limit: Option<u32>) -> Result<Vec<TagInfo>, String> {
    trace::read_async("get_tags", run_blocking(app, move |state| state.tags(limit))).await
}

// 多行写命令：闭包包住原函数体
pub fn save_settings(state: State<'_, AppState>, settings: Settings) -> Result<Settings, String> {
    trace::write("save_settings", || {
        let previous = state.settings.snapshot();
        let saved = AppError::command(state.settings.replace(settings))?;
        // …原逻辑不变…
        Ok(saved)
    })
}
```

`write` 内部的日志：

```rust
log::info!(target: "command", "command started: name={name}");
let started = Instant::now();
let result = run();
let elapsed = started.elapsed().as_millis();
match &result {
    Ok(_) => log::info!(target: "command", "command finished: name={name} elapsed_ms={elapsed} outcome=ok"),
    Err(error) => log::warn!(target: "command", "command failed: name={name} elapsed_ms={elapsed} error={error}"),
}
result
```

`read` 只在 `Err` 与 `elapsed > threshold` 时写，成功且不慢时零分配、零落盘。

## 8. 风险与回退

| 风险 | 处理 |
| --- | --- |
| 去掉 `.level()` 后忘记 `set_max_level`，日志全空 | `set_max_level` 放在 `run()` 最前，先于插件构建；验收第 1 条直接暴露 |
| 调试构建切到 debug 后日志变多 | 现有 debug 只有 8 处，量可控；发布构建仍是 Info |
| 闭包改动影响借用与 `?` 语义 | 包装只加一层，原表达式整体内移，不重排语句；`cargo check` 全覆盖 |
| 81 处改动漏改 | 用 grep 计数自检，等于 81 才算完成 |
| 命令记录把日志撑大 | 写命令低频、读命令成功不记，实测一天正常使用预计增加几十到几百行 |
| 回退 | 全部改动集中在 `trace.rs`（新增）、`lib.rs`、`commands.rs`，删除 `trace.rs` 并回退两处调用即可，无数据格式变更 |

## 9. 不做的事

- 不做原生看门狗、心跳、面包屑、取证 Worker。
- 不做设置页「详细日志」开关与运行时等级切换。
- 不记录命令参数（数量、路径、文本）。
- 不改 `logs/mcp.log` 与 `logs/ai-server.log` 两条旁路。
- 不做按天轮换。
- 不改前端任何代码，不改数据库 schema，不改操作记录语义。

### 10.1 收尾复核修正

计划里对插件行为的判断有两处错误，实现完成后按 `tauri-plugin-log 2.10.1` 与 `fern 0.7.1`
源码复核并修掉：

1. **`set_max_level` 放错了位置**。计划要求「在构建插件之前调用」，理由是 `log` 的
   `max_level` 默认 `Off`。实际上插件的 `attach_logger` 自己会调用一次
   `log::set_max_level`，取的是 fern dispatch 的等级（未设 `.level()` 时是 `Trace`），
   而插件初始化在应用 `setup` 之前，于是早设的基线被覆盖成 `Trace`——
   `LILITH_ARTBANK_LOG_LEVEL` 完全失效，发布构建还会输出 `debug` 记录。改为在应用
   `setup` 的第一句调用。
2. **`.format()` 被 `.timezone_strategy()` 覆盖**。`Builder::timezone_strategy` 内部会把
   dispatch 的格式重置成插件默认格式，计划里「插件默认格式与 `timezone_strategy` 无关」
   只在完全不调用它时成立。原顺序是 `.format()` 在前，自定义格式（含 `[run:]`）被静默
   丢弃。改为 `.timezone_strategy()` 在前、`.format()` 在后。

顺带：启动横幅里的 `rotation=4MB×5` 改为由 `LOG_MAX_FILE_SIZE` / `LOG_KEPT_FILES` 算出，
不再手写；`logging.md` 的 `.level(` 自检命令改为只匹配调用行。

检查结果：

- `cargo check`、`cargo check --all-targets`：通过，无告警。
- `cargo test`：410 passed / 0 failed / 9 ignored。
- `cargo fmt --check`、`git diff --check`、`npx tsc --noEmit`：通过。
- `grep -c "trace::write\|trace::read" src-tauri/src/app/commands.rs` = 81。
- `grep -n "^\s*\.level(" src-tauri/src/lib.rs`：无输出。

遗留：现有 `logs/lilith-artbank.log` 里的历史行是 UTC 时间，新行是本地时间，同一文件会混着两种时基，直到轮转或手动清空。验收时如需干净对照，可先删掉这个文件再启动。真实窗口验收未做（见 `todo.md`）。
