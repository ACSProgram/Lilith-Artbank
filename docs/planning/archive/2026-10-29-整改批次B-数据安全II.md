## L2：写事务里的文件动作统一补偿

问题：`history::write` 的事务里直接 `rename`/发布文件/建目录，只有个别路径写了局部回滚，且四种写法各不同。提交期错误（磁盘满、SERIALIZE 失败）或写闭包后面的步骤失败时，磁盘已经改了而事务整体回滚，行指向的目录或文件在磁盘上不存在；用户看不到任何提示。

做法：

- 新增 `library/fs_journal.rs`：`FileJournal` 记录五类已落地动作——`Renamed`（文件或目录搬移）、`Created`（新建目录）、`CreatedTree`（本次专属的暂存目录树）、`Removed`（删除空目录）、`Published`（发布新文件）。`rollback()` 逆序撤回，撤回失败只记日志、不掩盖原始错误。
- `FileJournal` 带 `armed` 标志：`armed()` 构造的日志在析构时自动撤回（覆盖 panic 展开），提交成功后 `disarm()`；`Default` 得到未装填的日志，撤销/重做按记录显式 `rollback()`，语义不变。
- 同时把两件原本各写一份的文件原语搬进来：`rename_path`（原 `folders::rename_directory`，含 Windows 只改大小写的中转路径）与 `move_file`（原 `maintenance_actions` 的同卷 rename + 跨卷复制删源）。
- `history::OperationDraft` 增加 `fs: &mut FileJournal` 与 `draft.journal()`；`write_with_id_mode` 在写事务外创建装填日志，事务成功才 `disarm()`，`affected=0 && chunks 为空`（记录被丢弃）时也显式撤回。
- 四条写路径改为「做了什么就记什么」，删掉各自的局部回滚：
  - `metadata::move_images_with_id`：每张成功改行后 `renamed`；目标目录本次新建时 `created`。
  - `folders::create_with_id`：只对本次真正新建的目录 `created`。
  - `folders::rename_with_id` / `move_to_with_id`：搬目录后 `renamed`，父目录本次新建时 `created`；原来包在闭包里、按 `result.is_err()` 回滚的写法全部删掉。
  - `folders::place_many`：删掉 `done` 向量与 `rollback_renames`，改由日志统一回退。
  - `edit::save`：暂存目录 `created_tree`、新内容 `published`；删掉 `published` / `operation_id` 两个手工回滚分支。
- `folders::FolderFsJournal`（批次 A 引入）与 `FileJournal` 合并：撤销/重做里 8 处签名与 6 处构造改用同一类型，`rename_directory` 一并迁走，不再有两份「逆序撤回」实现。

## L4：孤儿清理先搬文件再短事务记账

问题：`move_orphans` 在**一个**写事务里插入记录、逐个搬文件、最后才提交。进程在提交前被杀，SQLite 回滚整条记录而文件已经在 `recycle/orphans/`，没有任何记录能撤销；清理几百 GB 时唯一写连接被长期占住，导入 flush、元数据编辑、MCP 写入全部排队。

做法：

- 文件搬移移到事务外，逐个 `move_file` 并记进 `FileJournal`；失败条目照旧进 `failed` 清单，不中断整次操作。
- 搬完后用 `history::write_with_id` 写**一条**短事务记录（`orphanMove` + `(源, 目标)[]` 的 JSON chunk），与其它同步写入共用新时间线语义。
- 记账失败时日志析构把已搬走的文件逆序搬回原位；进程在两步之间被强杀会留下「文件在回收站但无记录」，这类文件仍可手工找回，不影响库内一致性（决策 4）。

## L10：缩略图段与特征包的落盘边界

问题：缩略图段与特征包只 `flush`，而指针事务是持久的（`pack_gc` 甚至用 `synchronous=FULL` 提交指针）。掉电或强杀后数据库认为缩略图/特征存在，实际段文件被截断：网格长期 404，语义搜索静默少图，只有全量重建才能恢复。

做法：

- `ThumbPack`：`PackState` 记录 `unsynced` 字节；追加只 `flush`，累积 8 MiB、换段前（旧段指针已存在）、指针事务提交前（导入批次、缩略图重建、编辑保存）与关闭图库时 `sync_all`。新增 `sync()`，没有待同步字节时是空操作。
- 新增 `thumbs::validate_segments`：打开图库时把 `thumb_segments.size` 与磁盘实际长度比对，缺段或变短就把 `thumb_offset + thumb_length` 越界的指针清成 `thumb_segment = 0`（按段一次 `UPDATE`）。这些行重新算「缺缩略图」，由现有重建任务补上，不需要新任务类型。
- `FeatureStore`：`PackWriter` 记录未落盘字节，累积 4 MiB 落盘；`set_root` / `clear`（换库、关库）先 `sync_writers()` 再丢句柄。重新打开写句柄时若文件末尾不足一条记录（掉电留下半条），先截到整条边界再追加——追加模式句柄只有 `FILE_APPEND_DATA`，截断另开一个写句柄完成。
- 读取路径的越界校验保持原样：缩略图 `read` 与特征 `read` 本来就会拒绝越界指针，现在这些指针在打开图库时已经被清掉，不会再出现「行在、字节不在」的长期状态。

## 测试

新增 8 个单测：

| 位置 | 用例 | 覆盖 |
| --- | --- | --- |
| `library/fs_journal.rs` | `rollback_moves_files_back_and_removes_published_ones` | 搬移、发布、新建目录三类动作逆序撤回，未记录目录不受影响 |
| `library/fs_journal.rs` | `disarmed_journal_keeps_everything` / `default_journal_never_touches_the_disk` | 提交后不撤回；撤销/重做用的未装填日志不会误撤回 |
| `library/fs_journal.rs` | `rename_path_handles_case_only_changes` | 只改大小写的目录改名走中转路径 |
| `library/history.rs` | `write_rolls_back_file_actions_when_the_work_fails` / `write_keeps_file_actions_after_commit` | 写闭包报错时文件回原位且不留空记录；提交成功后文件留在新位置 |

## 未做与遗留

- 写入缩略图指针的撤销/重做（`undo_edit` / `redo_edit`）与空间优化批次没有逐条 `sync_all`，仍靠 8 MiB 阈值与打开时的段校验兜底；如果真实库上重建耗时被 fsync 拖慢，再决定是否也在这两条路径提交前落盘。
- 段校验以 `thumb_segments.size` 为参照，不做全表指针扫描：`size` 在每次指针提交时更新，文件变短即判定截断；如果将来有路径追加缩略图却不更新 `size`，需要同步修改判定。
- 特征包只做「整条边界对齐 + 落盘」，没有逐条指针校验；读取时的越界检查仍然是唯一防线。
- L5–L8、任务/关库/终态、AI/MCP 生命周期按批次 C/D/E 继续。
