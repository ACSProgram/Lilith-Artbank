# 特征检索扩展计划（找相似 · 语义特征三模式）

日期：2026-11-01
前置研究：[`research/patch-retrieval`](../../../research/patch-retrieval/README.md)（450 张真实库样本、26 个查询、四份报告）
当前能力：[当前状态](../current-handoff.md) · 待办：[待办与待决策](../todo.md)

## 目标

「找相似」面板的「指标」仍是 5 项，其中第 4 项从「语义 embedding」改名为「语义特征」；选中它之后，面板里多出一个二级选择，三选一：

| 模式 | 底层 | 回答的问题 |
| --- | --- | --- |
| 整体 | 现有全局 embedding（不动） | 整张图感觉像不像 |
| 偏重主体 | MaxSim：注意力 top-32 → V 投影 → 白化 64 维 | 主体和局部画法像不像 |
| 偏重构图 | 8×8 SPP → 白化 128 维 | 排布、疏密、主体位置像不像 |

三者来自**同一次** SigLIP2 图片塔前向，不存在只算出一半的情况。界面上只出现「语义特征」和三个中文模式名，不出现 embedding / SPP / MaxSim / 局部匹配。

## 研究结论（决定本计划形态的依据）

| 形态 | 每张 | 全库 39.6 万 | 标准落差 | 与全局 top-10 重合 | 查询延迟 |
| --- | --- | --- | --- | --- | --- |
| 全局 embedding（现状） | 3 KB | 1.22 GB | 1.66 | — | 0.89 s |
| SPP 白化 128 | 8 KB | 3.25 GB | **3.55** | 61% | 1.13 s |
| MaxSim 白化 64 | 2 KB | 0.81 GB | 2.24 | 64% | 1.18 s |

延迟均为「全局粗筛 20% + 重排」。全库直扫分别是 2.42 s 与 2.89 s，不采用。

三条关键证据：

1. **加权融合不需要**。全库 z-score 加权 0.5/0.5 得到同目录 48% / 与纯 SPP 重合 83% / 3.31 s；两段式 20% 得到 50% / 94% / 1.37 s。同样的行为，三分之一的时间，且不用标定权重。
2. **截断按比例，取 20%**。2% 时重排等于没做（top-10 与全局完全重合），5% 只保住 71% 的纯 SPP 答案，20% 到 94%。
3. **普通 PCA 对 MaxSim 是负收益**。1536→64 普通 PCA 从 2.51 掉到 1.75，白化 64 只掉到 2.24。原因是 PCA 保留的最大方差方向就是「所有图共有」的分量，降维后局部特征朝同一处偏，MaxSim 退化成整图相似。

## 已定决策

1. **三种口径共用 20% 粗筛**，构图档不放宽。用户判断：SPP 放宽后会带回不同风格的内容，参考性反而下降。
2. **不做分数级加权融合**，见证据 1。
3. **不新增「特征不完整」状态**。现有 `PendingFilter` 本来就按 `(kind, model, dim)` 判定「缺什么排什么」，把条件从「缺 embedding」扩成「缺任一描述子」即可；回填期的图用 embedding 查是已完成、用 spp 查是待处理，这是同一个机制的自然表达，不是新状态。批量任务也因此自动补齐——跑一次就把缺的补上，不需要单独的「补特征」入口。
4. **白化基冻结并版本化**。基是离线拟合产物，不是模型自带；换一次基，全库描述子整包作废。
5. **int8 用固定 scale**，写在基文件里，不进每条记录（`pack.rs` 的包头没有每记录元数据的位置）。
6. **界面只出一个指标「语义特征」**，三种口径做成它的三个模式，不并列成三个指标。理由：三者同源、同一次前向产出，对用户来说是同一件事的三种看法；并列会让指标列表从 5 项变成 7 项，用户要自己猜它们的关系。

## 批次 A · 特征生产

出口：新导入的图片三种特征齐全；老库回填能跑完；`cargo test --lib` 与前端检查通过。

### A1 · 基文件

- 训练脚本固化到 `server/tools/fit_basis.py`，输入是一批图的 `last_hidden_state`，输出：
  - `spp_basis.npz`：mean(1536) + projection(1536×128 f32) + scale，约 786 KB
  - `maxsim_basis.npz`：mean(1536) + projection(1536×64 f32) + scale，约 384 KB
- 放在模型目录下，与 `config.json` 同级；文件内带 `version` 与训练样本数
- 研究阶段只在 436 张上拟合，**正式基要用全库分层抽样重拟合**（至少数千张，覆盖不同画风与画幅）

### A2 · Python 服务

- `/v1/embed/image` 增加 `features` 参数，默认 `["global"]`，可选加 `"spp"`、`"maxsim"`
- 服务端在**同一次前向**里算出三个描述子并返回；**不回原始 patch**（576×1536 走 JSON 是 10 MB+/张）
- 单张返回约 13 KB（global 3 KB + SPP 8 KB + MaxSim 2 KB）
- 基文件在图片塔加载时一并载入，缺失时该能力报不可用而不是静默降级

### A3 · 特征包

- `pack.rs`：`FeatureKind` 加 `Spp = 3`、`MaxSim = 4`；`FeatureDtype` 加 `I8 = 3`
- 维度：`Spp` 用 `dim = 8192`（64 格 × 128 维摊平），`MaxSim` 用 `dim = 2048`（32 局部 × 64 维摊平）
- 沿用现有 `(n, dim)` 扁平记录，**不改 MAGIC 与 VERSION**，现有包不受影响
- 解码侧需要知道摊平后的形状：把「64×128」「32×64」写成常量并与 kind 绑定，不放进包头

### A4 · 待分析条件与回填

- `PendingFilter::Embedding { model, dim }` 扩成 `PendingFilter::Features { model, dims }`，条件是**缺任一 kind**（`NOT EXISTS` 三个 kind 中任意一个）
- 这个条件同时被三处消费，改一处三处一起生效：
  - 批量任务「生成语义特征」的待处理清单
  - 任务开始前的「范围 N 张 / 将处理 M 张」预览
  - 找相似面板的模式门限（见 B3）
- **自动补齐**：批量任务跑一次，缺什么补什么。因为三个描述子出自同一次前向，所以对「有 embedding、缺 spp/maxsim」的图会重跑一次前向并**把三个都写一遍**——embedding 是确定性结果，覆盖无害，换来的是「跑一次就自洽」，不需要判断哪个缺、哪个不缺
- 回填量：39.6 万张。实测 GPU batch=1 为 15.4 张/秒 → 纯前向约 **7.1 小时**；含解码单线程 20–40 小时，多进程流水后 8–12 小时
- 回填走现有 AI 任务队列，进度沿用现有任务面板，不新做界面

### A · 实施记录（2026-11-01，代码完成，待真实模型验收）

- 基拟合脚本在 `server/tools/fit_basis.py`，支持预抽特征 npz（`patch`/`attn`/可选 `patch_v`）或图片目录/清单现场跑图片塔；输出与模型同目录的两份 npz，带 `version`、`samples`、`scale`。
- `/v1/embed/image` 的 `features` 用逗号分隔（缺省 `global`），描述子以 base64 的 int8 记录返回；health 的 `imageEmbedding.features` 列出两种描述子。
- 白化基随图片塔加载，缺基时 `/v1/models/ensure` 返回 422，图片能力整体不可用。
- feature_blobs 的 kind CHECK 需要放开，因此加了 schema v11→v12 重建表；迁移只复制指针，不改行。
- 待处理条件改为 `PendingFilter::Features`，批量任务一次前向写 embedding / spp / maxsim 三条；只有 embedding 的旧图会重跑一次并三条都覆盖。
- 正式基、真实模型回填与界面验收还没做，清单在[待办](../todo.md)。

## 批次 B · 检索与界面

出口：三个模式在同一张图上都能出结果，切换不报错，延迟在预算内，界面上不再出现 embedding 字样。

### B1 · 扫描与两段式重排

- 新增 `spp` / `maxsim` 两个相似分支，读取对应特征包
- 两段式：全局扫描 → 按阈值过滤（阈值始终是 embedding 相似度，见 B4）→ 取 top-N（`N = ceil(0.2 × 有效张数)`，下限 200）→ 只对候选算 SPP / MaxSim 分数 → 按新分数重排
- 扫描沿用现有 mmap 顺序读 + 分块；`Spp` 每张 8 KB 是全局的 2.7 倍，20% 候选约 317 MB
- **先量散读带宽**：候选在包里是分散的，8 KB 散读可能显著低于顺序读的 1.34 GB/s；实测后若超过预算，退路是把 SPP/MaxSim 单独存成按 id 连续排列的包

### B2 · 界面与数据模型

「指标」列表结构不变，第 4 项改名：

| 指标 | 线上值 |
| --- | --- |
| pHash | `phash` |
| 主色 4 色 | `color4` |
| 主色 8 色 | `color8` |
| **语义特征** | **`embedding` + `mode`** |
| 姿势 | `pose` |

选中「语义特征」时，指标列表下方展开三个模式（单选），映射到存储层：

| 模式 | 线上值 | 存储 kind | 每张 |
| --- | --- | --- | --- |
| 整体 | `overall` | `FeatureKind::Embedding` | 3 KB |
| 偏重主体 | `subject` | `FeatureKind::MaxSim` | 2 KB |
| 偏重构图 | `composition` | `FeatureKind::Spp` | 8 KB |

- `kind` 的线上值**仍是 `"embedding"`**：三者确实都出自 embedding，这样不用动 Rust 的分发 match 与 MCP 的参数校验，只新增一个 `mode` 字段，缺省 `overall`
- `FindSimilarConfig` 加 `mode`；`FindSimilarPanel` 的 `useState<SimilarKind>` 旁加一个 `useState<FeatureMode>`，切指标时保留上次选中的模式
- 模式选择只在 `kind === "embedding"` 时渲染，其余指标不显示

### B3 · 数据缺省与模式门限

**缺省数据（只有 embedding）是合法状态，不是待修复状态。** 默认模式就是「整体」，它用的正是现有那份 1536 维向量，所以老库不用回填、不用迁移，升级后行为与现在完全一致。

只有切到「偏重主体」「偏重构图」才需要新数据。这两个模式的门限复用面板里已有的「指标不可用 + 原因」机制（就是现在「姿势」那行置灰并提示「1 张参考图还没有姿势数据」的做法），不新增状态、不新增弹窗：

| 条件 | 不满足时 |
| --- | --- |
| 参考图本身有该特征 | 置灰，提示「N 张参考图还没有语义特征」 |
| 全库不再有待处理 | 置灰，提示「语义特征还在生成（剩余 N 张）」 |

**第二个条件是必须的**，不能用「有多少算多少」：两段式重排只对候选集里**有**该特征的图生效，没有的图会保持全局顺序，结果是同一批候选里两种排序混在一起，排序前后不自洽。

实现上要加两处：

- `ImageCapabilities`（`src/modules/library/types.ts`）加 `spp` / `maxsim` 两个布尔，后端能力查询同步返回
- 门限判断放在 `metricAvailability` 旁边，键从 `kind` 变成 `kind + mode`

回填完成后这两个模式自动变可用，用户不需要做任何操作。

### B4 · 阈值与分组

**阈值统一是 embedding 相似度，三种模式共用一套区间和一套取值。**

三种模式都走同一次粗筛，粗筛用的就是 embedding 分数。所以阈值天然是「入口条件」——筛掉整体不像的图；模式只改变候选集里的排序。这和两段式结构完全一致，也不会因为新增描述子就换一套刻度。

- 顺序：全库扫描 → 按阈值过滤 → 取前 20% → 按模式重排。阈值拉高时候选集自然变小，重排也跟着变快
- **整体模式的语义与现在完全一致**（排序分和阈值分是同一个数），老用户的习惯不变
- **但阈值不能当构图过滤器用**：它只筛整体相似度，筛不掉「整体像、构图不像」的图。文案要避免让人以为它是按当前模式筛的
- **滑块标签只在「语义特征」下改**：`kind === "embedding"` 时显示「最低整体相似度」，其余四个指标（pHash、主色 4 色、主色 8 色、姿势）**保持现在的「最低相似度」不变**。改的是 `FindSimilarPanel.tsx:467` 的 `h4` 与 `:491` 的 `aria-label`，两处要一起改，否则读屏会念成旧文案

**分数显示要跟着改**，否则会被读成「分数低于阈值却还在结果里」：

| 模式 | 卡片上显示 |
| --- | --- |
| 整体 | embedding 分数（现状不变） |
| 偏重主体 / 偏重构图 | **不显示绝对分数**，只显示图片；要反馈就给「第 N 名」或本次结果内的相对百分位 |

- **相似分组固定用「整体」**，不给模式选择——按构图分组没有语义，按主体分组与现有语义分组等价

### B5 · 文案

用户可见的「embedding」全部换成「语义特征」：

### B6 · MCP

MCP 的 `find_similar`（`mcp/tools/read.rs:422`）是 agent 侧入口，要同步三件事：

1. **参数**：`FindSimilarInput` 加 `mode`（`overall` / `subject` / `composition`，缺省 `overall`），只在 `kind = "embedding"` 时有效；其它 kind 传了 mode 直接报错
2. **校验**：`kind` 的五个值不变；`mode ≠ overall` 时不允许 `targetIds` 传多张——SPP 与 MaxSim 都没有定义「多张参考图取平均」
3. **门限**：特征没生成时返回明确错误，而不是空结果：

   > 该图库还没有生成「偏重构图」所需的语义特征，请先运行批量任务生成语义特征（剩余 N 张）

阈值不用改语义：它始终是 embedding 相似度，三个模式一样（见 B4）。agent 传 `threshold = 0.8` 在任何模式下都是「整体相似度不低于 0.8」，行为一致、不会因为换模式就一条都拿不到。

文档与 schema 同步：

- `mcp/server.rs:297` 的工具描述（那段长文案要补三个 mode；阈值语义不变，仍写「相似度下限」）
- `mcp/tools/read.rs` 的 `kind` / `threshold` 的 `schemars` 描述，以及响应里的 `note` 字段
- `docs/modules/mcp.md` 的工具表

**临时区不用改**：`temp_features_generate`（`mcp/tools/feature.rs`）的 `kind` 仍是 `embedding | pose`——批量任务现在一次前向产出三个描述子，跑一次 `kind=embedding` 就把三个都写了。所以外部图对比也能直接用构图模式，不需要新工具、不需要新参数。

权限档不变：`find_similar` 仍是只读工具，不新增确认队列。

### B · 实施记录（2026-11-01，代码完成，待真实库验收）

- 两段式重排落在 `ai/descriptors.rs` 与 `ai/runtime.rs`：全局阈值命中取前 `ceil(20% × N)`（下限 200）后，SPP 用 64 格对位余弦平均、MaxSim 用 32 局部双向最近邻平均重排；int8 的 scale 在余弦里抵消，Rust 侧不读基文件。候选缺描述子时整次拒绝，不混排。
- 能力查询新增 `spp` / `maxsim`，并新增 `get_semantic_feature_pending` 返回全库（不含临时区）剩余张数；面板用这两个来源实现“参考图有特征 + 全库无待处理”的门限。
- MCP 已有的 `mode` 是 `image/text`，无法复用。按用户确认新增 `featureMode`（`overall` / `subject` / `composition`，缺省 overall），只在 `mode=image` 且 `kind=embedding` 时有效；多图与其它 kind 直接报错。这两种模式下 `scoreKind=none`、预览 `score=null`。
- 界面第 4 项改名「语义特征」，选中后显示三个模式；阈值标签只在这一项改成「最低整体相似度」；多张平均参考只能选「整体」。
- 自动检查：`cargo test --lib` 586 通过、9 ignored；前端 `npm run typecheck` 与 `npm run test:web` 121 通过。真实库回填后的排序质量、20% 候选散读带宽与界面观感尚未验收，清单在[待办](../todo.md)。

## 风险与未验证

1. **散读带宽（最关键）**：0.24 s 的估算假设 1.34 GB/s，散读可能只有一半到三分之一。必须先在真实包上量。
2. **基的泛化**：研究阶段的基只在 436 张上拟合，正式基换到全库分层抽样后，质量可能变好也可能变差，需要重跑一次对比。
3. **int8 精度损失未测**：研究全程用 fp32，量化到 int8 后标准落差会掉多少没量过。
4. **白化分数的用户观感**：绝对值低，可能被读成「没把握」。B4 的处理是新模式不显示绝对分数。

## 不做

- 分数级加权融合（证据 1）
- 全库直扫 SPP / MaxSim（2.42 s / 2.89 s）
- 多用途语义投影头（研究阶段）
- PQ / OPQ 量化（int8 够用，且会掩盖特征质量问题）
- 文本搜构图（文本塔只产出一个全局向量）
- 构图筛选分面（传统 CV 描述子那条路，已否决）
