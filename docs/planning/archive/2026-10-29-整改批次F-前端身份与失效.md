## 已确认决策

1. **F1 刷新补页**（报告 #19）：最后一页只请求还缺的几张，精确补到原行数，不再多取后截断。
2. **F3 缩略图跨库**（报告 #20）：切库改为重启应用，重启前弹框确认；缩略图地址带图库 id。

## F1：刷新补页按缺口取行

问题：`removeItems` 先本地删行，`refreshKeepingRows` 以 `previousCount = items.length` 为目标抓页，最后 `collected.slice(0, target)`，游标却取最后一页末尾。原 150 行删 1 行后 target=149，抓 150 行只留 149 行，游标停在第 150 行之后，那一行从此永不显示。

做法：每页按 `Math.min(PAGE_SIZE, target - collected.length)` 传 `limit`，`collected` 恰好等于目标行数，游标自然停在第 `target` 行之后，去掉 `slice`。后端 `normalize` 本来就会把 `limit` 夹到 1..`MAX_LIMIT`，键集与 id 列表两条路径都用它，`list_fingerprint` 已把 `limit` 清掉，所以 id 列表缓存仍按查询而不是按页大小命中。

## F2：详情按 imageId 清空并校验

问题：`ImageInspector` 的 effect 只 `setLoading(true)`，不处理旧 `detail`；异步返回后无条件 `setDetail(next)`。从 A 切到 B 后，请求返回前标题是 B、内容是 A；请求失败会一直显示 A。此时点星级、加删标签、改描述、移动文件夹都使用 `detail.id`，写入落到 A 上。

做法：

- effect 开始时 `setDetail((previous) => previous && previous.id === imageId ? previous : null)`：切图清空，同一张图的写入后重取保留旧内容，不闪加载态。
- 请求返回后再校验 `next.id === imageId`，防止 id 串台的响应覆盖当前图。
- 新增 `patchDetail(id, update)`，所有就地写入（评分、标签、描述、AI 描述）都走它；`setFolderDraft` 用 `imageIdRef` 对一次当前图，切图后不再改新图的输入框。
- 描述草稿仍按图片 id 暂存，切走再回来恢复编辑态的行为不变。

## F3：缩略图地址带图库 id，切库改为重启

问题：URL 是 `/{imageId}?v={version}`，解码缓存是模块级 LRU、无图库维度，协议响应 `max-age=31536000, immutable`，切库只重挂 `LibraryWorkspace`。两个库都存在 id=1、thumb_version=1 时 URL 完全相同，切库后网格/胶片带/相似组直接命中上一个库的缩略图，且长期不失效。

做法：

- `src/shared/thumbUrl.ts` 增加模块级 `libraryId` 与 `setThumbLibraryId(id)`，URL 追加 `&lib=<图库 UUID>`。图库 id 来自 `LibraryInfo.id`（manifest 里的 UUID），由 `AppRuntimeProvider` **在渲染子组件之前**写入——放在 effect 里，已经挂上的 `<img>` 不会重建，仍会命中上一个库。
- 解码缓存按 URL 命中，因此自动按库命名空间隔离，不需要额外清缓存。
- 换库改重启：`LibraryDialog` 在已有图库时先弹确认（标题「更换图库会重启应用」），开库/建库成功后再调新命令 `restart_app`。命令只做 `AppHandle::request_restart()`（非发散版本），退出流程（关库、停 AI 与 MCP）仍走 `RunEvent::Exit`，不另开一条关闭路径。浏览器预览里 `restartApp` 是空实现。
- 先开库再重启，是为了让「目录不是图库」「迁移失败」这类错误仍能在当前对话框里报出来，而不是留给重启后的进程。重启请求本身失败时按「图库已打开、请手动重启」报错，不混进「打开图库失败」。

## 5.2 六个高影响项

| 问题 | 做法 |
| --- | --- |
| 查看器不跟随原图内容变化重新加载 | 原图加载 key 增加 `contentHash` 与 `fileSize`，空间优化/像素编辑换内容后自动重取源 |
| 图片离开当前筛选/集合后查看器仍停留 | `ViewerHost` 用 `useSyncExternalStore(session.subscribe, session.getItems)` 订阅数据源，活动图不在列表里就提示并关闭；列表为空（正在换结果集）时不判定 |
| 相似结果打开时点侧栏文件夹，结果不退出 | `LibraryWorkspace.selectFolderScope` / `selectTrashDirect` 与 `LibraryView.showFolder`（面包屑）统一调 `similarity.clear()`，与其它视图切换一致 |
| 标签写入失效漏 `tagPresence`/`excludeTagIds` | `tagsAffectQuery` 纳入这两项；`metadataSelection` 不再对加标签直接返回 `keep`，改由 `selectionAfterChange` 按写入后的标签集判断 |
| 文件夹移动后选择不裁剪 | `FolderTree` 新增 `onImagesMoved(imageIds, targetPath)` 并透传到工作区，移动图片发带 `ids` 与 `targetFolderPath` 的 `folder` 变化（此前只发空变化，选择不裁剪）；拖放与详情侧栏的移动本来就带这两项 |
| 扩展名分面吞掉已选但计数为 0 的项 | 扩展名列表改为「分面值 ∪ 已选值」，计数为 0 的已选项显示 0 而不是「—」 |
| 删除/合并被筛选标签后筛选条件不清理 | `DataChangePlan` 新增 `dropTags`，`tagCatalog` 计划在删除/合并的标签仍被包含或排除时带出该 id，`combinePlans` 取并集；`LibraryView` 清掉这两条条件并按新查询身份重取首页，同时跳过这一轮的保留旧行刷新 |

### 选择裁剪的精确度边界

写入回执只有标签**名字**，筛选条件里是标签 **id**，两者对不上，所以：

- 「无标签」：按 `rowPatches` 里写入后的标签集判断，非空即离开；批量写入没有行数据时整批按离开处理。
- 「排除标签」：拿不到 id 与名字的对应，加标签按可能离开处理；移除标签只可能让图片进入结果，不裁剪。
- 「包含标签」与搜索：移除标签仍可能让图片离开，保持整批裁剪。

## 筛选面板标签走后端搜索

问题：标签选项固定 `getTags()` 的前若干个，标签库超过上限后靠后的标签既看不到也搜不到。

做法：输入即查后端 `search_tags`（防抖 180 ms、上限 200 条，与后端一致）；首次结果回来前先用初始列表按关键字过滤，避免闪一下「没有匹配的标签」；搜索结果同样过范围计数；已选中的标签（包含或排除）如果不在当前列表里，从「见过的标签」里补在末尾，保证随时能取消。搜索失败在标签列表区单独报错并提供重试，不复用面板顶部的标签列表错误行（那一行的「重试」只重取标签列表，重跑不了搜索）；换关键字时清掉上一条错误，不静默显示成「没有匹配的标签」。

## 未做与遗留

- 换库重启是唯一的重置手段，重启期间（开库到进程退出）会短暂显示新库的界面；如果要避免这一帧，需要把开库与重启合并成一条命令，代价是开库失败只能留给新进程报错。
- 「排除标签」下加标签的裁剪仍是整批的，要精确需要写入回执带上标签 id（`setImageTags` 已经返回 `TagRef[]`，批量接口只回数量）。
- `refreshKeepingRows` 的补页逻辑没有直接单测：它是 React hook，仓库里没有 hook 测试设施；改动的 `limit` 计算由后端分页用例间接覆盖。
