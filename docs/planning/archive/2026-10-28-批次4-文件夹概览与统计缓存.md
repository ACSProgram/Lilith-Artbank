# 使用反馈整改（第二轮）批次 4：文件夹概览与统一统计缓存

日期：2026-10-28
状态：**已归档。实现完成，自动检查通过，等待用户手工验收**。真实库（39 万行）统计耗时与真实窗口观感未验，记入 `docs/planning/todo.md`。

范围对应《[使用反馈整改计划（第二轮）](2026-10-28-使用反馈整改计划（第二轮）.md)》的编号 9，以及其中的批次 4 边界与已确认决策。本批次只新增只读统计与前端缓存；不改数据模型、不建持久化统计表、不做增量计数、不把统计放进筛选面板。

## 一、本批次决策

| 问题 | 结论 |
| --- | --- |
| 统计范围 | 选中文件夹的子树并集；`folderDirect` 只算直属图片；根目录等于全库；多选包含父子时不重复计数。 |
| 可见性 | 始终排除回收站、待释放行与临时区。唯一与列表不同的是全库搜索：列表按既有语义包含回收站，概览只算正常图片。 |
| 筛选 | 应用当前搜索与全部筛选，和网格口径一致；不为概览另写一套条件。 |
| 分布 | 扩展名、评分（补齐 0–5）、最常见 8 个标签（名称与计数）。不做体积占比环图，后续按真实窗口再定。 |
| 位置 | 右侧详情面板：空选且有选中文件夹时显示“文件夹概览”；选中图片后图片详情优先。 |
| 缓存 | 前端按“profile + 视图/集合/搜索/筛选”缓存，容量 48；先显示旧值、后台刷新；`DataChange.facets` 失效；按图库创建与销毁。 |
| 命令 | 合并为只读命令 `get_library_stats`，通过 `StatsProfile` 区分 `facets` / `summary` / `folderDetail`；删除 `get_filter_counts` 与 `get_query_total`。 |
| 索引 | schema v9 只加 `idx_images_visible_bytes(deleted_at, folder_id, file_size)`；分面索引保持窄，避免标签聚合退化。 |
| 不做 | 不建统计表；不做增量计数；不在数据库缓存文件夹统计；不引入图表库；不把统计放进筛选面板。 |

## 二、后端实现

### 2.1 命令与分发

- `src-tauri/src/library/stats.rs`：`StatsProfile`、`StatsRequest`、`SummaryStats`、`StatsSnapshot` 与 `library_stats` 分发；SQL 主体仍在 `query.rs`。
- `StatsSnapshot` 用 `#[serde(tag = "profile", content = "data")]` 序列化，前端按 `profile` 收窄类型。
- `AppState::library_stats` 只取当前图库读连接；命令注册为 `get_library_stats`，走 `run_blocking`，不阻塞窗口事件循环。
- 删除 `get_filter_counts` 与 `get_query_total` 两个命令；筛选面板、集合对话框与任务上下文统一走统计命令。

### 2.2 统计查询

- `query::folder_stats`：`normalize` 后要求 `folderIds` 非空且视图为 `all` / `collection`；清空排序、游标、分页与锚点，避免分页参数影响统计。
- 与列表共用 `PreparedQuery`：可见性、搜索与全部筛选条件都来自同一处；全库搜索不带视图条件时，`require_active_images()` 补 `images.deleted_at IS NULL`。
- 在同一个读事务内依次求：
  1. `count(*)` 图片数；
  2. `coalesce(sum(file_size), 0)` 总字节；
  3. 扩展名与评分分组；
  4. `image_tags` 按标签分组，取前 8，再回连 `tags.name`；
  5. 子文件夹数。
- `subfolder_count` 一次取出全部普通文件夹，按路径祖先链判断“在任一选中路径之下且自身未被选中”；根目录选中时所有非根文件夹都算后代。不再逐 id 查路径与 `LIKE`。
- `stats_tags` 只查前 8 个标签的名称，先取计数再回连，避免为全部标签建名称映射。
- `folder_scope_paths` 改为一次 `IN (…)` 查询，所有带文件夹筛选的查询（列表、计数、统计）都少 N 次点查；`normalize` 已把 id 去重并限制在 256 个以内。

### 2.3 索引与查询计划

- schema v9 迁移只执行 `CREATE INDEX IF NOT EXISTS idx_images_visible_bytes`，不改数据；`downgrade_to_v6/v7/v8` 测试辅助会移除它，迁移测试断言幂等且现有行不变。
- `pin_stats_indexes` 仅在以下条件全部满足时对概览查询加 `INDEXED BY`：`view = all`、无搜索、无导入时间/大小/描述/特征筛选，且视图为图库。标签条件允许保留，因为索引覆盖图片列。
- 总字节固定走 `idx_images_visible_bytes`；扩展名、评分与标签分组走 `idx_images_visible_facets`。
- **没有**在 `filter_counts` 上强制索引：它原本由规划器选择覆盖索引，强制 `INDEXED BY` 会在索引被临时移除（性能 A/B）或库处于异常状态时直接报 “no such index”，也更容易把选择性强的标签筛选逼成全索引扫描。A/B 基准因此仍可运行。

## 三、前端统计缓存

### 3.1 store

`src/modules/library/statsStore.ts`：

- 键：`profile + queryIdentityKey`（视图、集合、搜索范围、筛选）；排序、游标、分页、锚点不进键。与后端忽略这些参数一致。
- 值：`{ data, status, version, error }`；`status` 为 `loading / ready / refreshing / error`。
- 容量 48，按最久未用淘汰；淘汰时清理代次与旧响应标记，避免键表随筛选项无限增长。
- 同一键并发只发一次请求；过期代次、换库（`epoch`）与 `dispose` 后的响应直接丢弃。
- `facets` 成功后可派生同查询的 `summary`；`fetch("summary")` 会等待过期的 facets 刷新完再返回，任务对话框不会拿到旧总数。
- `invalidate()` 递增版本，已就绪条目变为 `refreshing` 并生成新对象（保证 `useSyncExternalStore` 能观察到变化）；在飞请求完成后按版本决定结果状态，并在需要时补一次后台刷新。
- 请求失败保留旧值并记录错误，`retry` 重新请求；`clear/dispose` 清空计时器、在飞请求、代次与条目。

### 3.2 组件

- `StatsProvider.tsx`：提供 store 与 `useStats(profile, query, enabled)`；返回 `data/status/error/retry`。
- `FolderInspector.tsx`：概览 UI；图片数、子文件夹数、总大小三块摘要；扩展名前 6 项（其余合并“其他”）、评分 0–5、标签前 8；空文件夹与无匹配的文案区分；`refreshing` 显示“更新中”，失败保留旧值并给“重试”。
- `Inspector.tsx`：空选且 `folderIds` 非空时标题切为“文件夹概览”，副标题用现有 `folderScopeLabel`；选中图片后仍显示图片详情。
- `LibraryView.tsx`：仅在图库/集合视图且不在找相似时传入 `statsContext`；`plan.facets` 为真时调用 `stats.invalidate()`；“当前视图 N 张”与任务上下文改为 `stats.fetch("summary")`。
- `FilterPanel.tsx`：删除本地计数请求与防抖，改读 `useStats("facets", query, open)`；错误态增加“重试”。

## 四、性能

20 万行合成库、选中顶层文件夹（约 1 万张，子树展开 500 个文件夹）：

| profile | p50 | p95 |
| --- | --- | --- |
| `summary` | 0.71 ms | 3.31 ms |
| `facets` | 37.71 ms | 42.14 ms |
| `folderDetail` | 17.71 ms | 18.17 ms |
| v8 → v9 建索引 | 82.55 ms | — |

- 同一序列里 `filter_counts` 子树为 59 ms；`folderDetail` 少一组文件夹分组，因此更便宜。
- 三轮实测受负载影响约 2 倍（`folderDetail` 14.8–18.5 ms，`facets` 37.7–59.7 ms）。
- 合成库整库在页缓存里，真实库（39 万行、约 1 GB）的 `SUM` 与标签聚合仍需复测；数字见[性能基准](../../guides/performance.md)。

## 六、与计划的差异

1. **索引钉住只用于文件夹概览**：计划没有要求给筛选分面加强制索引；实现中发现强制 `INDEXED BY` 会让 A/B 基准与索引缺失场景直接失败，因此 `filter_counts` 保持由规划器选择索引。
2. **`get_library_stats` 合并三个 profile**：而不是新增多个命令；减少前端 IPC 入口，并让缓存按同一命令管理。
3. **`summary` 可由 `facets` 派生**：筛选面板与集合对话框常同时需要，派生避免重复计数；`fetch` 会等待过期 facets 刷新。
4. **移除 `get_filter_counts` / `get_query_total`**：前端已无调用方，避免保留两条退役路径；模块文档与命令表同步更新。
5. **子文件夹数用路径祖先判断**：计划只要求“文件夹数”；实现选择一次取全量文件夹，而不是逐选中 id 做 `LIKE`，多选时更稳定。

## 七、用户手工验收

1. 打开图库，在普通视图点选一个文件夹，不选图片：右侧应显示“文件夹概览”，图片数、子文件夹数、总大小与树上的计数一致；类型、评分、标签分布出现。
2. 点选其子文件夹，确认多选并集不重复计数；父子同时选中时“子文件夹”数不把选中的子文件夹算进去。
3. 打开“直属图片”模式：副标题提示只统计直属图片，概览数字随之变化；退出后恢复子树统计。
4. 选中一张图片：详情切回图片详情；取消选择：回到文件夹概览。
5. 空文件夹：三个摘要仍显示，分布区显示空态；带搜索/筛选且无命中时文案为“没有匹配的图片”。
6. 切换文件夹、修改搜索/筛选：已有范围先显示旧值并显示“更新中”，新范围显示加载态；完成后数字更新。
7. 导入、移动、回收站、评分、标签、描述变化后：概览在后台刷新，不出现空白或 0。
8. 反复开关筛选面板：计数不重复请求，打开时直接显示缓存值；断开/模拟失败后“重试”可恢复。
9. 切换图库后再选文件夹：不显示上一个图库的概览数字。
10. 回收站、临时文件夹视图与找相似结果：不显示文件夹概览。
