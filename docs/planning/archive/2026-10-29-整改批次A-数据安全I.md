## 已确认决策

1. **L1 多文件夹撤销**：整次当作没发生——任一项失败就逆序把已改的目录改回去，数据库随事务回滚。
2. **L9 路径大小写**：以数据库里的规范路径为准；`ensure_folder_tracked` 返回规范路径，祖先/子树判断统一按分段忽略 ASCII 大小写。

## L1：多文件夹撤销整次回退

问题：一条 `place_many` 记录里有多条 `FolderPathChange`，撤销/重做在同一个事务里逐条搬目录。第 3 条失败时数据库整体回滚，但前 2 条目录已经搬走，行指向的目录在磁盘上不存在。`undo_create` 与导入收尾的 `cleanup_created` 有同一问题（前面的空目录已删、行回滚后指向不存在的目录）。

做法：

- 新增 `folders::FolderFsJournal`（`pub(crate)`），记录三类已落地的动作：`Renamed`、`Removed`（已删空目录）、`Created`（已新建目录）；`rollback()` 逆序撤回，搬移按是否仅大小写变化选择 `rename_directory` 的中转路径，回滚失败只记日志、不掩盖原始错误。
- `undo_path_change` / `redo_path_change` 去掉各自的局部回滚，改为在成功搬移后 `journal.renamed(...)`，由调用方统一回退。
- `undo_create` / `cleanup_created` / `undo_delete` / `redo_create` / `redo_delete` 全部接收 `&mut FolderFsJournal`，删除与新建目录时记账。
- `history::undo_folder` / `redo_folder` 用闭包包住整段 chunk 循环：任一步返回错误即 `journal.rollback()` 再返回；`transaction.commit()` 失败也回退（SQLite 提交失败视为已回滚）。
- `undo_move` / `redo_move` / 导入撤销与重做里的 `cleanup_created`、`redo_create` 同样接入 journal，失败分支与提交失败分支都会回退。

## T1：导入工作线程 panic 时先收口写线程

问题：工作线程 panic 会在 `pool.install` 处展开，`run_inner` 末尾的 `writer.join()` 执行不到；写线程持有通道接收端，会继续把已排队的结果写进库，甚至在本任务 `finish` / `LiveOperation::finish` 之后还在写——用户看到失败，行却在增长，记录可能已被收尾删掉。

做法：

- 新增 `WriterGuard`：`JoinHandle` 放在 `Option` 里，`join()` 取走后返回；`Drop` 里兜底 join。工作池在建写线程之前创建，建池失败提前返回时不会留下等不到通道关闭的写线程；`writer` 声明在 `context`（持有 sender）之前，展开时 context 先释放断开通道，`WriterGuard` 再 join，写线程必然先排空再退出。
- `history::append_live_in_tx` 在记录行已不存在时跳过逆数据写入并记 `warn`：`operation_chunks.operation_id` 有外键，记录被删后整批提交会失败，带走本批已入库的图片。

## L3：撤销暂存目录清理改到写连接

问题：`cleanup_undo_dirs` 用读连接枚举 `operations`，而编辑保存是“先在自己的写事务里建 `.artbank/undo/<id>/`，提交后记录才可见”。两者并发时清理会把在建目录当成无主目录删掉，编辑从此不可撤销。

做法：`cleanup_undo_dirs` 改为 `database.with_writer(...)`，枚举与删除都在单写连接上完成，与建目录的写事务天然互斥；`is_dir()` 预检查留在取锁之前。调用点不变（`after_history_write`、打开图库）。

## L9：文件夹路径以数据库规范路径为准

问题：

1. `ensure_folder_tracked` 按调用方传入的大小写逐段拼路径。库里已有 `Art` 时，`art/sub` 会新建一行 `art/sub`，同一子树出现两种前缀写法。
2. 子树计数 `expand_folder_counts` 用精确字符串查祖先、`subfolder_count` 用精确字符串比祖先路径，前缀大小写不同的子树整段丢计数。
3. `is_in_subtree`、`move_to` 的自身/后代守卫、同级兄弟比较都是大小写敏感的 `starts_with` / `==`；旧数据里前缀大小写不同时，“移动到自身子树”的守卫会失效。

做法：

- `library::paths` 新增 `same_folder`（`eq_ignore_ascii_case`）与 `folder_within`（按字节前缀 + 段边界比较，忽略 ASCII 大小写；空祖先表示根）。附单测覆盖 `Art` / `art` / `Artwork` / `Art/Sub` 的边界。
- `library::import` 新增 `ensure_folder_path`，返回 `(id, 规范路径)`；`ensure_folder_tracked` 保留原签名并转调它。`resolve_folder` 对已存在的行返回库里那一行的 `path`，新行返回插入路径；`ensure_folder_path` 用它逐段拼子路径。
- `folders::create_with_id` 改为先补数据库行拿到规范路径、再按规范路径建物理目录（原来先建目录、后补行）。
- `metadata::move_images_with_id` 用规范路径做目标目录、跳过去重判断与文件发布路径。
- `folders` 内 `is_in_subtree` 删除，全部改用 `folder_within`；`subtree_folder_ids` 的自比较改 `COLLATE NOCASE`；`reorder` / `place_many` 的兄弟父路径比较、`apply_order` 的 `children_by_parent` 键改为忽略大小写。
- `query::expand_folder_counts` 与 `subfolder_count` 的路径索引/集合改为小写键，祖先回溯按小写查。
- `mcp/tools/folder.rs` 的自身子树守卫改用 `folder_within`。
