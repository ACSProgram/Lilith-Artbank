# MCP 图库控制计划

日期：2026-10-25
状态：批次 1（只读）、批次 2（写工具、撤销/重做、询问档）、批次 3（导入、导入回执、审计与收尾）与批次 4（找相似交互重构）已实现（2026-10-26）；批次 2 已经真实客户端实测，批次 3 的真实客户端验收清单见 `docs/modules/mcp.md`。批次 5（临时文件夹）已落地、待验收。批次 6（导入归因与临时区判定）已排期、未实现。实现记录见 `docs/planning/current-handoff.md` 与 `docs/modules/mcp.md`。
代码基线：`main` `2792547`（图片空间优化第三阶段收尾）。当前事实：schema v6、操作记录支持撤销与重做、图片空间优化（估算/执行/导入即压缩）已落地且不可撤销；本批次把设置升到 v6 并加入 MCP。

## 1. 目标

让支持 MCP 的 AI 客户端安全地操控当前图库：

- 看图库概况、文件夹、标签、集合；
- 搜索图片、找相似、按拼图批量审图；
- 批量改评分、标签、描述，移动图片，移入/恢复回收站，管理集合；
- 导入图片并跟踪任务；
- 查看操作记录、撤销与重做。

所有操作都从已打开的图库应用内部执行，和界面共用同一份 `AppState`、任务总线、相似度缓存与操作记录。AI 不直接连 SQLite，不另起一个图库写进程。

## 2. 边界

不开放给 AI：

- 图片空间优化：估算、执行、导入时压缩、`optimize` 相关任务；
- 永久删除、清空回收站；
- 像素编辑（裁剪、旋转、调尺寸）；
- 批量生成 embedding / 描述。批次 6 起只开一个口子：临时区的 embedding 与 pose，见 6.10；永久库仍然不开放，描述仍然不生成。
- 图库创建、打开、关闭、设置修改；
- 任意目录浏览（导入路径除外）；
- 独立 headless 产品模式。

`ImportRequest.optimize` 对 MCP 固定为 `None`。即使以后导入 DTO 再增加压缩参数，MCP 适配层也不透传。

## 3. 现状审查结论

这轮新改动大部分不影响 MCP 的读取、搜索和拼图设计，但有三处必须写进契约：

1. **撤销后可以重做**。历史记录不再在撤销时删除，而是标为 `undone`；选中的目标重做时，重做目标及下方连续的 `undone` 记录。新操作会清空整条重做分支。
2. **压缩记录阻断撤销/重做**。`HistoryKind::Optimize` 不写逆数据，撤销链里只要包含压缩记录，`run_undo` 会在标记 `undoing` 之前返回“压缩操作不可撤销，原图已删除”。MCP 不提供压缩工具，但 `history_list` 会看到这类记录，`history_undo` / `history_redo` 必须原样返回该错误，不能重试绕过。
3. **导入 DTO 新增 `optimize` 与压缩统计**。MCP 导入不传该字段；`tasks_get` 不返回 `optimized` / `optimizedBytes`，避免让 AI 误以为它可以控制压缩。

其余变化（schema v6 的 `optimized_at`、优化任务类型、导入压缩进度）只作为只读背景存在。MCP 不需要新增 schema 迁移；新增的 `TaskKind::OptimizeEstimate` / `Optimize` 只影响任务列表的展示与冲突判断。

## 4. 进程与传输

推荐：

```text
MCP client (stdio) → lilith-artbank.exe --mcp-stdio
                     → 127.0.0.1:18767/mcp (一次性口令)
                     → mcp::ToolService → AppState → library/import/ai/history

MCP client (Streamable HTTP) ────────────────────────┘
```

- MCP 服务在应用进程内运行，工具直接调用 `AppState`，不经过 Tauri IPC，也不复制领域逻辑。
- 同一个 exe 增加 `--mcp-stdio` 分支，在 Tauri 初始化和 single-instance 插件之前处理。stdio 模式下 stdout 只用于 MCP 协议，日志写 `logs/mcp.log`。
- 服务启动时生成随机口令，把配置端口与口令写入程序目录的 `mcp-runtime.json`；stdio 小桥读取它。支持 HTTP 的客户端可以直接连。
- 只绑定 `127.0.0.1`，请求必须带口令。应用关闭或图库未打开时，工具返回明确错误。
- MCP 服务默认关闭；设置里开启后默认使用“询问”档。关闭服务后小桥连接失败。
- 不使用独立 headless 进程。测试用临时图库直接调用工具层；需要传输级测试时开真实应用连小桥。

## 5. 工具清单（21 个）

### 5.1 只读（8）

| 工具 | 关键输入 | 返回 |
| --- | --- | --- |
| `library_info` | — | 图库、计数、schema、AI 能力、特征数量、MCP 档位与限制 |
| `folders_list` | `parentPath?`、`limit?` | 文件夹 id、路径、直接/子树计数 |
| `tags_list` | `query?`、`limit?` | 标签 id、名称、图片数 |
| `collections_list` | — | 集合 id、名称、数量、顺序 |
| `search_images` | 结构化查询、`cursor?`、`pageSize≤50`、`includeFacets?` | 总数、紧凑行、下一页游标 |
| `find_similar` | `mode: text/image`、文本或目标图、kind、阈值、limit | 结果 token、总数、前几条预览 |
| `images_get` | `ids≤50` | 批量详情、标签、描述、能力标记 |
| `image_sheet` | selector、`grid 1–5`、`resolution` | 拼图图片、格子映射、`sheetId`、下一页 |

`search_images` 始终返回 `total`；需要筛选分面时才传 `includeFacets`。2 字搜索与超大集合的分面计数较慢，工具描述要提示按需使用。

`find_similar` 继续使用应用现有的单个相似结果槽：后一次搜索会让前一个 token 失效。语义搜索也走这个工具，不另设工具。

### 5.2 写入（7）

| 工具 | 关键输入 | 返回 |
| --- | --- | --- |
| `images_update` | selector、评分 / 加标签 / 删标签 / 单图描述、`confirmedCount`、`dryRun?` | 影响数、`operationId` |
| `images_move` | selector、目标文件夹、`confirmedCount`、`dryRun?` | `taskId`，完成后附 `operationId` |
| `images_trash` | selector、`confirmedCount`、`dryRun?` | 影响数、`operationId` |
| `images_restore` | selector、`confirmedCount`、`dryRun?` | 影响数、`operationId` |
| `collections_create` | 名称、可选 selector | 集合、数量、`operationId` |
| `collections_modify` | rename / delete、集合、`expectedItems?` | `operationId` |
| `collections_membership` | add / remove、集合、selector、`confirmedCount` | 影响数、`operationId` |

`images_update` 一次只做一类修改（评分、加标签、删标签、单图描述之一），保证一次工具调用只产生一条历史记录。描述只允许 selector 解析为 1 张图。

不提供 `trash_empty`、`delete_images_permanently`、`clear_operation_history`。

### 5.3 记录（3）

| 工具 | 关键输入 | 返回 |
| --- | --- | --- |
| `history_list` | `limit?`、`kind?` | 记录、状态、`canRun`、阻塞原因、待释放统计 |
| `history_undo` | `targetId`、`confirmedSteps`、`confirmedAffected`、`dryRun?` | `taskId` |
| `history_redo` | `targetId`、`confirmedSteps`、`confirmedAffected`、`dryRun?` | `taskId` |

历史状态沿用当前实现：`applied`、`undone`、`redoing`、`undoFailed`。`history_list` 同时返回推导出的“从这条开始撤销会动几条 / 从这条开始重做会动几条”，AI 不需要自己数。

### 5.4 任务（2）

| 工具 | 关键输入 | 返回 |
| --- | --- | --- |
| `tasks_get` | `taskId?`、`waitMs?≤30000`、`includeFailures?` | 任务列表或单个任务；导入附带回执 |
| `tasks_cancel` | `taskId` | — |

`tasks_get` 不带 id 时返回活动任务和最近结束的任务，让 AI 知道为什么写操作被拒绝（例如用户正在跑图片空间优化）。`tasks_cancel` 只允许取消 MCP 自己创建的任务；用户从界面启动的任务不能由 AI 取消。

### 5.5 导入（1）

| 工具 | 关键输入 | 返回 |
| --- | --- | --- |
| `import_start` | 绝对路径、目标文件夹、层级模式、标签、评分、重复策略 | `taskId` |

不传 `optimize`，不传 `workerThreads`。导入永远不压缩。

## 6. 拼图

```text
image_sheet(selector, grid = 4, resolution = "thumb")
```

- 默认 4×4 = 16 张；5×5 = 25 张只用于粗筛；细节确认用 3×3、2×2 或 1×1。
- 画布长边约 1600px，格子等比 `contain`，不裁切，深灰背景。
- `resolution="detail"` 只允许 3×3 及以下，直接从原图解码；1×1 是 AI 的放大镜。`thumb` 读缩略图包。
- 每格左上角画 `A1`…`E5` 编号，使用内置 5×7 位图字体，不引入字体文件。
- 返回映射包含格子、id、宽高、评分、少量标签、文件夹、缩略图是否缺失。
- `sheetId` 只保存映射，最多 128 份、2 小时过期；不缓存图片字节。过期后返回明确错误，要求重新生成。
- 查询来源返回下一页 query 游标；相似结果返回 `nextOffset`。
- 单次最多 25 格；缺图格画占位，不阻塞整盘。

## 7. 选择器、确认数量与批量

所有批量工具共用 selector：

```json
{ "kind": "query", "query": { ... }, "excludeIds": [] }
{ "kind": "ids", "ids": [1, 2, 3] }
{ "kind": "sheet", "sheetId": "...", "cells": ["A1", "A2"], "excludeCells": ["A3"] }
{ "kind": "similarity", "token": "...", "offset": 0, "limit": 16 }
```

`sheet` 是 AI 的主力：`cells` 省略表示整盘，`excludeCells` 表示“除了这几个”。

确认数量：

- `search_images` 返回 `total`；
- `dryRun` 返回 `selected`、`willChange`、`skipped`、`sample`；
- 正式写入必须带 `confirmedCount`，等于解析出的 id 数；不一致直接拒绝并返回最新数量。

AI 不需要提前猜数量。顺序是“查询/试算 → 看到 37 → 带 37 再执行”；如果中途变成 38，就拒绝重来。

写入失败语义：

- selector 解析为空：`noop`，不产生历史记录；
- 部分图片已不存在/已在回收站：返回失败清单，不让整批静默少做；
- 写操作在 MCP 层串行；写 lane 被导入、移动、编辑、优化、撤销/重做占用时拒绝；
- 一次工具调用对应一条历史记录。

## 8. 三档行为与待确认队列

设置项：

```text
mcp {
  enabled: false,
  port: 18767,
  mode: "readOnly" | "ask" | "full"
}
```

默认：服务关闭；开启后 `mode=ask`。设置版本从 v5 升到 v6；schema 保持 v6，不新增数据库迁移。

### 只读

写工具仍然出现在工具列表里，但调用返回“当前是只读模式”。这样客户端缓存 `tools/list` 不会因为切换档位而失效。

### 询问

只有以下操作进入应用内待确认队列：

- `images_trash`（无论几张）；
- `history_undo`、`history_redo`；
- `import_start`；
- 任何影响超过 100 张图片的批量写入。

普通评分、标签、描述、<=100 张的移动/集合操作直接执行。

询问流程：

1. 工具返回 `{ status: "pendingApproval", approvalId, preview }`，不立即执行；
2. 应用 MCP 面板与任务中心显示确认卡片，列出操作、范围、数量、示例、后果；
3. 用户批准后执行；拒绝则取消；10 分钟未处理自动取消；
4. AI 用 `tasks_get(approvalId)` 等结果，`tasks_cancel` 等同于拒绝；
5. 执行前重新解析 selector，并核对 `confirmedCount`；数量或状态变化就拒绝，返回新预览。

确认卡片不是模态框，用户不点也不会卡住界面；AI 会等待或超时。

### 完全

不弹应用内确认，直接执行。仍保留：

- `confirmedCount` 核对；
- 无永久删除、无清空回收站、无压缩；
- 撤销任何记录前仍要显示回退清单并核对步数与影响数。

设置页必须对完全档显示警告：AI 可以读取任意本机图片路径并导入，也可以撤销用户自己的记录。

## 9. 撤销与重做

当前实现是线性的：

- 撤销目标必须是 `applied`；撤销目标及之后所有仍为 `applied` 的记录，最新的先撤；
- 撤销成功不删除记录，标为 `undone`；
- 重做目标必须是 `undone` / `redoing`；重做目标及下方连续的 `undone` 记录；
- 新操作会删除整条重做分支；
- 记录裁剪、清空记录、图片空间优化按当前实现处理。

MCP 规则：

- AI 可以撤销任何记录（用户已确认），包括用户自己的；因此 `history_undo` / `history_redo` 在询问档永远要确认，在完全档也必须先返回回退清单并核对 `confirmedSteps` / `confirmedAffected`。
- `history_list` 返回每条的 `status`、`affected`、`label`、`kind`，并附推导出的 `undoSteps` / `redoSteps`。AI 操作带“AI ·”前缀。
- 撤销链包含 `kind="optimize"` 时，后端会拒绝；MCP 原样返回，不自动改目标、不重试。
- 新写入会清空灰色重做分支；工具描述要写明，AI 不应先撤销再写入再期待重做。
- 撤销/重做是任务；多条记录可以中途取消，取消后已完成部分保留。`tasks_get` 显示进度与失败原因。

## 10. 导入

- 接受任意本机绝对路径，不做目录白名单；路径校验沿用现有扫描器。
- 固定 `optimize = None`，不压缩；不暴露 `workerThreads`。
- 询问档总是要确认，卡片列出来源路径（预览带前 20 条，卡片展开 5 条、其余只给数量）、目标文件夹、初始标签/评分、重复策略。
- `tasks_get` 返回导入的 `imported`、`duplicates`、`merged`、`failed`、`previewIds`、失败清单；不返回 `optimized` / `optimizedBytes`。
- 导入完成后，AI 可以用 `image_sheet(selector.ids = previewIds)` 看最近入库的图。
- 撤销导入沿用现有 `origin_operation_id`；导入压缩不在 MCP 中出现，所以撤销语义不受新压缩功能影响。
- `logs/mcp.log` 记录导入来源路径、时间、档位、任务号与操作号；设置面板显示最近 AI 操作。

## 11. 界面与刷新

- 设置增加 MCP 分类：开关、端口、三档、运行状态、客户端配置复制、待确认列表、最近 AI 操作、完全档警告。
- 询问档有新的待确认操作时发通知；确认卡片放在 MCP 面板，任务中心也能看到同一任务。
- 同步写入成功后发 `library-changed` 事件，前端刷新计数、文件夹、当前页与操作记录；异步任务继续用 `task-finished`。
- 撤销/重做/移入回收站/导入完成后，如果当前查看器里的图片已不可见，关闭查看器。
- 现有 `TaskCenterProvider` 在 `task-finished` 上递增数据版本；MCP 同步写入需要新增事件监听，避免只改后端、界面不刷新。

### 批次 1：能看能搜（已实现，2026-10-26）

- 同 exe stdio 小桥、应用内 MCP 服务、口令与运行时文件；
- 设置 MCP 开关、端口、只读状态；

### 批次 2：能改能撤（已实现，2026-10-26）

### 批次 4：找相似交互重构（已实现，2026-10-26）

#### 4.1 AI 结果展示

- 不新增复制/导出工具。AI 要给用户留下一组结果时，用现有 `collections_create` 创建「AI · 主题」集合；服务端指令与工具描述已经这样要求。
- 如果以后确实要给外部程序用，再单独评估一个显式导出工具；默认不复制图库文件。

#### 4.2 参考图与弹出菜单

- 先把某张图设为“参考图”（网格右键；查看器入口未做）；设置后不自动打开面板，工具栏“相似”打开与筛选同款的下拉面板，顶部显示参考图缩略图与数量。
- 单个参考图列出 pHash、4 色、8 色、embedding、pose 五个指标；多张参考图只列出 4 色、8 色、embedding 的平均。缺少对应特征、目标被删除时置灰并给出原因。
- 面板同时选择“最低相似度”滑杆（0–100%，越大越严格，可勾“不限”；内部换算成 pHash/主色距离或语义/姿势相似度）、结果数量与范围：当前视图（默认）、当前选择、当前文件夹（含/不含子文件夹）、当前集合、全库；范围与指标互不覆盖。临时文件夹的范围选项在批次 5 接入。
- 结果沿用现有相似结果槽与分页，但每页只返回范围内的命中；结果列表可继续建集合、加标签或做其他 selector 操作。
- 后端 `find_similar` 增加范围参数，并让扫描在候选 id 集上收窄；不为了范围退回 O(n²)。全库不解析 id；其它范围先解析成 id 集合再取交集，embedding/pose 只读取范围内的向量。
- 多张参考图的主色用等权加权 k-means 合并成同数量的参考色，embedding 求平均后归一化；最多 100 张。缺特征时不在查询路径里自动生成。
- MCP 的 `find_similar` 同步增加 `scope`、`targetIds` 与浮点阈值，参数与界面弹窗一致；结果仍只保留一个槽。

### 批次 5：临时文件夹（已实现，待验收）

临时文件夹只做“查找用的暂存区”，不承担结果展示；需要保留的结果建集合。

实现时把“建集合”理解成对普通图片的结论：临时图片不能加入集合（关闭后集合项会悬空），要留下就先重新导入图库，而同一内容的临时行还在时会被当作重复跳过，得先清空临时区。

形态与规则：

- 和回收站同级的固定入口（视图栏），不进入普通文件夹树，不参与默认计数、默认搜索与文件夹树计数。
- 底层是一个受保护的图库内目录；schema v7 给 `folders` 加 `kind`（`normal` / `temp`），每个图库固定一个 `temp` 文件夹。界面显示“临时”，内部路径保留，禁止重命名、移动、删除。
- 只能通过导入进入；`images_move` 拒绝把普通图片移入临时，也拒绝把临时图片移出。评分、标签、描述、查看、搜索、找相似保持可用。
- 打开图库、关闭图库、切换图库和退出应用时清空：删除临时图片行与原图文件，清空相似结果缓存并刷新前端。清空是临时数据的生命周期规则，不是用户可撤销的图库操作。
- 临时图不写可撤销的导入记录，只在 `logs/mcp.log` 记录来源；这是对“写路径必须接入操作记录”的唯一例外。若开工时认为必须走记录，则改为不可撤销的 `HistoryKind::TempImport` 并在清空时清理关联记录，需先确认。
- 不给临时文件夹单独开权限系统：AI 仍用同一套三档与工具。**实现时改为临时导入在询问档也免确认**（原计划是“默认仍确认”）：临时区在关闭图库时整目录清空，确认一道会消失的内容没有意义；普通图库导入仍然每次确认，只读档仍然全部拒绝。
- MCP 不新增工具：`import_start` 增加 `target: "library" | "temp"`；`search_images` / selector 增加 `view=temp`；`find_similar` 的范围增加临时；`folders_list` 或 `library_info` 暴露临时入口与计数。
- 导入临时同样固定不压缩，导入回执与 `previewIds` 可继续用于拼图。

### 批次 6：导入归因与临时区判定（已排期，未实现）

数据其实已经在手边，只是没送出来：

#### 6.1 精确重复对（必须）

- `Outcome::Duplicate` 增加 `source_path`、`existing_id`、`trashed`；`existing` 在 `pipeline.rs:313` 已经查过，不额外查库。

#### 6.10 临时区特征生成（新增能力，仅 `target=temp`）

定位：临时区是"先看再决定"的入口。AI 把候选图导进临时区后，需要判断"库里有没有语义/姿势相近的图"，但永久库的批量特征生成仍然不开放。

边界：

- 只接受临时区的图片 id；混入非临时 id 时整批拒绝并给失败清单，不做部分执行。
- 只做 `embedding` 与 `pose`，不做描述（描述模型本轮未接）。
- 不写操作记录、不需要 `confirmedCount`（临时区本来就不写记录）。
- 单次最多 100 张；走任务总线（可取消、有进度），占用 write lane，期间其他写操作按现有冲突规则拒绝。
- 询问档每次确认；完全档直接执行；只读档拒绝。
- 特征写进 `feature_blobs`，临时区清空时随 `images` 行 CASCADE 删除（`library/schema.rs:121-131`）；feature pack 里的字节不回收，留给 S8 维护，文档要写明"清空后不会立刻省磁盘"。

前置修正（不先做就会出错）：

- **全库相似必须排除临时图**。现在 `VisualIndex::load`（`library/similarity.rs:90-92`）、embedding 均值与扫描（`ai/embedding.rs:421`、`494`）、pose 扫描（`ai/pose.rs:150-160`）都只过滤 `deleted_at`；`TaskScope::Library` 直接返回 `None`（`ai/runtime.rs:834-838`）表示不过滤。批次 5 之后临时图的 pHash/主色已经会进"全库"结果，只是暂时没人注意；一旦临时图有了 embedding/pose，污染会明显得多。
- 临时区变化（导入、生成、清空）要失效语义均值缓存：`ensure_mean` 只按 model + dim 命中（`ai/runtime.rs:1084-1096`），不会因为临时区变了就重算。视觉索引按 stamp 失效，需确认临时行变化会更新 stamp。
- `library_info.features` 不要把临时区特征算进库覆盖度；需要时单独给 `tempEmbeddings` / `tempPoses`，否则 AI 会误判"全库已有向量"。

工具形态（待确认）：

- 新增 `temp_features_generate`（推荐）：`ids`（≤100）、`kind: embedding | pose`，返回 `taskId`，完成后 `tasks_get` 给逐张结果与失败清单。工具数从 21 变 22，仍远低于 30。
- 或给 `find_similar` 加 `generateMissing=true`：不推荐。读工具里偷偷跑模型，成本、权限、取消都不可预测。

成本说明（写进工具描述）：

- 临时图导入时已经算好 pHash 与 4/8 主色（`import/pipeline.rs:352-353`），所以"临时图 vs 库内图"的粗筛**现在就能用**，不需要任何生成。本能力只补语义与姿势这两档。
- 库内没有对应特征时，生成临时特征也搜不出东西；工具描述要求先看 `library_info.features`。
- 临时区关闭即清空，重算属于预期浪费；询问档确认是唯一闸门。

#### 6.11 验收

1. 询问档导入含 3 张库内已存在图的目录，`tasks_get(includePairs=true)` 返回 3 条 `sourcePath → imageId`，其中 1 张在回收站时 `trashed=true`。

3. 同一目录放 2 份完全相同的图，`batchDuplicatePairs` 给出一对 `keptPath` / `sourcePath`，`duplicates=1`。
4. 300 张重复时 `duplicatePairCount=300`、`duplicatePairs` 长度 200、`duplicatePairsTruncated=true`；不传 `includePairs` 时回执里没有这几组数组。
5. `target=temp` 导入同样返回 `duplicatePairs`，且不写操作记录。
6. 撤销整次导入后，`images_get` 确认合并前的评分与标签已恢复。
7. 临时区 5 张图生成 embedding：`library_info.features.embeddings` 不变、`tempEmbeddings` 为 5。
8. 以临时图为参考、`scope=library` 搜语义：结果里不出现任何临时图。
9. 以临时图为参考、`scope=temp` 搜：能在临时区内互相命中。
10. 清空临时区后 `feature_blobs` 无残留行，再搜语义不报错。
11. 生成中途取消：已完成张数保留、任务为 `cancelled`。
12. `ids` 里混入一张普通库图片：整批拒绝，不生成任何一张。

## 15. 风险

- rmcp 版本仍是 0.x，开工前做 2–3 天传输 spike。
- Windows 下同一个 GUI exe 的 stdio 是否稳定需要实测；失败就退回独立 console 小桥。
- 4×4 拼图在目标模型上的可读性需要真实美术图验证；不够就默认 3×3。
- 询问档会让 AI 等待用户；确认卡片、超时与拒绝后的重试要测试。
- 完全档 + 任意导入 + 撤销任何记录是强能力；设置页警告、来源日志、无永久删除是底线。
- 任务线程 panic 兜底仍是待办；MCP 不新增裸线程，长任务必须复用任务总线。
- 当前查询 id 列表只缓存 2 份，拼图与搜索交替使用可能让 cursor 失效；错误要可行动。
- 相似结果只有一个 token 槽，AI 不能并行跑两次相似搜索。
- 图片空间优化记录会阻断撤销/重做；工具描述与错误文案必须明确，不能自动绕过。
- 批次 6 的重复对含本机绝对路径：与 `logs/mcp.log` 现有行为一致，但仍只在 `includePairs=true` 时返回，默认不回传。
- 批次 6 的批内归因要在写线程维护 hash → 路径映射；1 万路径约 1 MB 级，超过上限即停止记录并标截断，不能无限增长。
- 批次 6 的临时区特征生成会让模型推理成本落到 AI 手上：单次上限 100 张、询问档确认、临时区关闭即清空（重算属于预期浪费）。库内没有对应特征时这项能力没有收益，工具描述必须先让 AI 查 `library_info.features`。

## 16. 工作量

- 工具 21 个，低于 30。
- 约 31–39 个工作日，单人 6.5–8 周。
- 约 4.5–6.5 千行 Rust（含测试），400–700 行前端。
- 批次 6 只加回执字段与归因，不改 schema、不新增工具，约 2–3 个工作日。
- 6.10 的临时区特征生成另算：约 2 个工作日（含全库扫描排除临时图的前置修正），需要真实 GPU 实测单张耗时后再定上限是否放宽。
- 不编译 release、不做 UI 自动化；真实窗口与真实 MCP 客户端由用户手工验收。
