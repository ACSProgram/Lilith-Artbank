## 能力现状

每条只给结论与契约入口；实现细节在对应模块文档里。

- **图库与元数据**：单库会话，换库（打开另一个图库）要确认后重启应用，下次启动按设置里的新路径自动打开；设置 v7（存一个 `libraryPath` 与导入压缩选项），schema v12（v1→…→v12 链式迁移），多级文件夹与磁盘目录一一对应，临时文件夹为会话级暂存区，操作记录与线性撤销/重做（线性回退、灰色重做分支、延迟释放；撤销失败可单条重试或跳过，清空记录与释放待删文件是两个动作）。文件夹删除把整棵子树搬入 `.artbank/trash/<trashed_at>/<根id>/`，原路径立即释放、可立即建同名文件夹；恢复按整个删除单元搬回原路径，原路径被占用时拒绝；永久删除延迟释放仓库里的行、原图与目录，启动时对账仓库与数据库。见[图库与元数据](../modules/library.md)。
- **导入**：文件/目录/拖放输入，BLAKE3 内容寻址与原子发布，EXIF 方向，512px WebP 缩略图写入追加式 pack，pHash 与 4/8 主色，精确/批内/感知三类重复，进度-取消-失败清单（进度含已写入体积、速度与预计剩余），可选的导入即压缩（选项持久化在设置的 `import.optimize`，动画/多页源保留原图，编码失败单独计数）。解码前按尺寸估算申请全进程共享的 1.5 GiB 字节预算（导入、压缩、估算、查看器、AI 输入与 MCP 拼图共用），大图少并发；压缩路径消费已解码图，不复制第二份全尺寸像素。见[导入与缩略图](../modules/import.md)。
- **浏览与检索**：键集游标与 id 列表游标分页，7 个排序指标、最多 7 级，搜索（描述/标签名/文件夹路径，当前视图或全库），筛选分面计数，文件夹概览与全库概览（子树/多选并集、类型与评分分布、常见标签，先旧值后台刷新），文件夹树可拆成上下双视图（展开与选中共享、滚动独立），回收站左侧换成回收站树（已删除文件夹层级、根行“直属图片”、整文件夹恢复/永久删除）、集合 CRUD 与集合运算；分面与概览共用 `get_library_stats` 与前端统计缓存（容量 48），所有写入统一走 `DataChange` + `planDataChange` 决定失效范围，刷新保留旧行并按活动图锚定滚动，补页按缺口取行不漏页；本地写入按已知增量更新计数，全库特征摘要只在筛选面板打开时读取。缩略图 URL 带图库 id（`v` + `lib`），解码缓存按 URL 自然按库隔离；筛选面板的标签输入走后端 `search_tags`。见[浏览与检索](../modules/browse-and-query.md)。
- **复制与导出**：右键菜单不再显示分组小标题，选项自带完整含义；“复制图片”对单选和多选都可用，`Ctrl+C` 在网格与查看器里是同一条命令的快捷键，以 `CF_HDROP` 文件引用写剪贴板（不解码、数量不限，聊天软件按文件处理）。文件路径与内容哈希的复制入口在详情侧栏：单张在“文件”区、直接用已加载的行内字段，多选在批量侧栏的“复制”区、按完整选中 id 由 Rust 取文本并直接写剪贴板（保持选中顺序、不受已加载行数限制）。右键“导出到文件夹…”复用现有导出任务（固定不附 manifest）。见[浏览与检索](../modules/browse-and-query.md#命令契约)。
- **查看器与编辑**：全屏查看、缩放平移、胶片带、姿势叠加，切换图片时先用 512px 缩略图占位、高清层就绪后淡入；原图加载按 `contentHash` 归属，空间优化或像素编辑后自动重取源；活动图离开当前列表（不再符合筛选、不在集合里、被移入回收站）时查看器提示并关闭。GIF 在查看器播放动画（超大图走静态预览并说明），网格/列表缩略图为首帧静态并带 `GIF` 角标；翻转→旋转→裁剪→缩放可组合，输出 JPEG/PNG/WebP，保存走“新内容发布”（新哈希文件、就地更新行、旧图暂存供撤销）。见[查看器与几何编辑](../modules/viewer-and-editor.md)。
- **批量编辑**：多选后从详情侧栏“批量编辑图片”进入，只作用于当前选择；默认“保持各自原尺寸”（只旋转/翻转），需要时再开启“统一尺寸裁剪”（默认完整显示、可选填满裁边），裁剪只在统一尺寸裁剪下可用。左侧预览缩略图兼作参考图选择。输出保持各格式默认质量（JPEG 90、WebP 85、PNG 无损），选择 JPEG/WebP 后才显示质量滑块。整批一条 `batchEdit` 记录，≤2000 张保留逐张快照、逆序撤销/正序重做；超过时需明确确认，继续则不可撤销并删除旧原图。跳过回收站/临时区/GIF/缺图/超 50MP/无变化，失败单独列出；开始前估算输出体积并检查磁盘。见[查看器与几何编辑](../modules/viewer-and-editor.md#批量编辑)。
- **相似与语义检索**：找相似有 pHash、4/8 主色、语义特征、pose 四项；语义特征下再分「整体 / 偏重主体 / 偏重构图」三种口径，后两者按整体相似度粗筛前 20% 后用 MaxSim / SPP 重排，三种模式共用同一个整体相似度阈值。另有相似分组（范围可选，组内只含范围内图片）、结果分页与“每组只留一张、其余移入回收站”；语义搜索用打开图库时算出的全库均值做中心化余弦，向量 mmap 扫描。见[AI 服务](../modules/ai-service.md#本地检索)。
- **AI 服务**：本机 `/v1` HTTP 服务的进程托管（探活、退避重启、优雅退出）；监督线程按「代次 + 持有者」交接，启动中改设置不会让自动拉起失效。请求单次 120 秒、最多 3 次、总预算 5 分钟，取消时正在飞的请求约 100 毫秒内返回且不计入失败。feature pack 存 embedding（fp16）、pose（f32）与语义描述子 SPP / MaxSim（int8，同一次图片塔前向产出）；批量任务挂任务总线，待处理条件是三种描述子缺任一。Python 侧同时最多 4 个推理请求（超出回 503）、单张解码上限 1 亿像素。描述不实现，`/v1/describe` 返回 404。见[AI 服务](../modules/ai-service.md)。
- **任务与并发**：`app/tasks/` 配合 `concurrency/` 资源表（会话、时间线、内容写、元数据写、AI 服务与文件夹子树路径锁），同一资源 FIFO、路径写优先；路径访问分读 / 原地替换 / 写三级，原地替换只与写互斥（图片空间优化用它，压缩期间查看器与 MCP 读图照常可用）。排队中的任务不占任何资源，只在路径锁上保留写者优先，因此短写（评分、标签、集合）不会被「排队的描述任务」挡住；冲突文案对排队者说「还在排队、尚未开始」。任务总线带图库代次：开库/建库/关库各推进一次，排队者在拿到资源时复核，换过库就直接落「已取消」，不碰旧句柄。短写冲突立即失败，撤销/重做/清空记录不排队；全局图像预算（`performance.workerThreads`，默认逻辑核数 − 1）统一约束导入、压缩、估算、缩略图、查看器预览、AI 解码与 MCP 拼图的并发张数，另有全进程 1.5 GiB 字节预算约束它们同时占用的解码内存。命令层的批量写任务与后台任务共用 `TaskBus::begin_blocking_task`，排队、panic 与终态不走两套实现；panic、线程起不来与提前返回都落到失败终态并释放资源。终态除完成/失败/取消/让位外还有「部分失败」（`TaskPhase::PartialFailed`）：缩略图连续失败、包回收旧段删不掉或半途出错、压缩有旧原图未删除都落它，消息写清未处理张数与未删文件数。批量任务开始前显示“范围 N 张 / 将处理 M 张”，任务 `total` 与 M 一致；批量编辑按选中张数 N 推进，跳过与失败各自计数。快照带运行时长、完成速度、ETA、当前文件与已提交字节；收到取消请求先切“取消中”相位（非终态），收尾完成后才落到“已取消”。
- **图片空间优化**：只读估算 → 确认执行两阶段，分层切片抽样与按层外推，执行前三道复核（参数指纹、候选集合指纹、逐张 `stat`），不可撤销的 `optimize` 记录。进度与收益曲线只用一种计量单位：候选张数——顶部进度条、环图中心、实线终点与里程碑横轴读同一个 `(已替换 + 已跳过 + 失败) / 候选张数`；速度含跳过，ETA 走同一套计数。执行时复用同一张估算视图并填入实际数据：环图四段「已替换 / 已跳过（按 6 个原因展开）/ 失败 / 未处理」，曲线叠一条实际实线，里程碑表多一列实际，结束后顶部换成一行结论并给一行“实际 vs 预计”。体积只出现在「已省 / 已替换体积」区块。见[维护与批量工作流](../modules/maintenance.md#图片空间优化)。
- **MCP 图库控制**：应用内 stateless Streamable HTTP 服务（`127.0.0.1` + Bearer 口令 + `mcp-runtime.json`）与同 exe 的 `--mcp-stdio` 小桥；25 个工具、三档权限、10 分钟确认队列、`logs/mcp.log` 审计。只读 `library_sql` 在专用只读连接上查询 `mcp_*` TEMP 视图，支持 JSONL/CSV 导出；工具响应与错误统一脱敏，响应不含图库根、程序根与临时目录（导出路径是刻意例外）。确认单执行中 10 分钟没有进度只标「疑似卡住」并返回当前进度，任务终态会回写记录；关闭服务会立刻断开已连接的客户端，所有工具入口都校验开关。永久删除、清空回收站、空间优化、像素编辑与普通库批量 AI 生成不开放。见[MCP 图库控制](../modules/mcp.md)。
- **维护与检查**：入口是「任务 → 维护与检查…」的四个分区。检查一次目录遍历同时出四类结论（缺失原图 / 孤儿 / 大小不符 / 哈希不符），快速检查只看存在性与大小、完整校验重算 BLAKE3，不持路径锁而容忍扫描期间变动；孤儿可移入 `recycle/orphans/`（一条 `orphanMove` 记录，可撤销）；缩略图包按段统计垃圾率，超过 20% 且空闲 3 分钟时自动回收（让位落「已让位」），也可手动立即回收；导出复制原图到目录并可选写 `manifest.csv`。见[维护与批量工作流](../modules/maintenance.md)。
- **界面缺口补齐**：标签列表三态（包含 / 排除 / 中性）、「清理 0 张标签」（一条 `tagDelete` 记录）、列表列显示/隐藏（`settings.ui.listColumns`）、`?` 与设置页的快捷键总表；主窗口关闭到系统托盘，托盘菜单提供“打开窗口 / 退出”，左键点击托盘恢复窗口。
- **日志与命令记录**：等级为发布 Info、调试 Debug，`LILITH_ARTBANK_LOG_LEVEL` 覆盖；行前缀是本地时间 + `[run:xxxxxx]`，可按单次运行切分。64 个写命令成对记 `started` / `finished`（带 `elapsed_ms`），35 个读命令只在失败或超阈值时记（默认 500ms，语义搜索与找相似 3000ms），8 个无 `Result` 的命令不包装；不记命令参数。按 4MB 轮转、保留 5 份归档；GUI 显式写 Folder + Stdout，不再受插件默认目标重复输出影响。见[日志与命令记录](../guides/logging.md)。
- **无窗口验收**：`headless` feature 与 `--headless` 命令面（`library`、`settings`、`query`、`fixture`、`logs`、`import`、`metadata`、`folder`、`collection`、`history`、`viewer`、`edit`、`task`、`maintenance`、`optimize`、`ai`、`mcp`、`scenario`）；14 个目标共 50 个用例（默认 47 个 cheap/default，3 个 heavy），覆盖只读、设置/日志、写路径、任务锁与图库代次、空闲回收、维护、空间优化、假 AI 协议与真实 stdio 桥；报告在 `<target>/acceptance/report.jsonl`，裸 `cargo test` 不启动子进程。见[验证策略](../guides/validation.md#无窗口验收入口开发期)。
- **前端契约**：`src/modules/<module>/api.ts` 是命令唯一入口，跨模块编排在 `src/app/`，主题只走 `src/styles/tokens.css` 的语义变量（`index.css` 只按顺序 `@import` 11 个分文件），破坏性操作确认文案统一在 `src/shared/confirm.ts`；提示契约在 `src/shared/notices.ts`，UI 设置类型在 `src/shared/settings.ts`，查询与数据变化 DTO 在 `src/shared/contracts/`，查看器与批量编辑共用的几何换算在 `src/shared/editGeometry.ts`，`shared/` 不依赖 app 或 modules。
