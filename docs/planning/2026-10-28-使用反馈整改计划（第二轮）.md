### 关于“写任务锁全库”的结论

当前没有数据库层面的全库写锁。读查询一直可用；短元数据写入也一直可用；被挡住的是长任务准入与文件夹维护操作。

真实冲突主要在文件系统路径与操作记录，而不是 SQLite：

- 导入向目标文件夹写文件（`src-tauri/src/import/pipeline.rs:203-217`）；压缩在开始时拿到候选路径，之后按路径读取与替换（`src-tauri/src/library/optimize.rs:473-474`、`:559-573`）；移动任务本身改路径；文件夹重命名/移动/删除会 `rename` 磁盘目录。
- 导入、移动、压缩、撤销/重做各自持有 `LiveOperation` 与 lane，交错会破坏批次原子性、撤销时间线与失败回滚。
- 当前实现把这些冲突统一收成“write lane 与所有 lane 冲突 + 文件夹操作要求全库空闲”，代价是纯读图的 AI/扫描任务也会挡住文件夹操作。批次 5 改为资源级判断，而不是继续扩大或简单取消锁。

## 三、各批次边界

### 批次 1：交互修正与文案

- **图片拖放**：按载荷类型判定落点。图片拖到文件夹行时整行都算 `inside`，不再保留上下 25% 的 before/after；文件夹拖动仍保留 25/75 用于同级排序。补上“直属图片”伪行的 drop 目标，或让它不遮挡父文件夹行。
- **多选操作**：给详情面板增加“当前是否回收站视图”。普通视图只显示“移入回收站”；回收站视图只显示“恢复/永久删除”。单图与多选规则一致。文案“部分图片有”改为“部分共同标签”。
- **导入提示**：副标题改为“导入完成前无法使用其他功能，可以取消导入”；删除正文里重复的阶段标题，正文只保留当前文件与百分比。保持模态阻塞，不做非模态导入。
- **描述编辑**：进入编辑态时按内容自动撑高，至少不低于只读态高度；输入时同步调整；保留详情面板自身的滚动，不把整页撑开。
- **清除筛选**：改为次要按钮样式并加清除图标；摘要条字号与按钮字号拉开层级。“清除搜索”是否同步改，等真实窗口看整体平衡后再定。
- **不做**：不改工具栏整体布局；不把导入改成可关闭；不从回收站移除恢复/永久删除；不为拖放引入新的第三方库。

**退出标准**：`npx tsc --noEmit`、`npm run test:web`、`npm run build` 通过；拖放位置判定与多选按钮条件有纯函数测试；用户手工验收拖放、普通/回收站多选、导入运行中、长描述编辑与筛选条。

### 批次 2：标签输入统一

- 统一入口：详情单图、批量编辑、导入初始标签、标签管理器改名/合并，全部使用同一套 chip + 输入 + 建议下拉。
- 下拉行为：输入框聚焦且为空时显示常用标签（按图片数排序的前 12 个）；输入后走现有 `search_tags`，去抖与排除已选项；建议项显示已有图片数，避免与新建混淆。
- 标签管理器：合并目标不再只过滤本地 500 条，改用后端搜索；改名输入复用同一套建议外观，但不把“改名到已存在标签”自动变成合并（保持现有错误语义）。
- 抽取 chip 展示基座，统一详情现有标签、批量共同/部分标签、输入框 chip 的视觉；筛选点击与移除回调保持各自语义。
- **不做**：不改标签 schema；不做层级/分类；不改变 64/32 个上限；不把改名自动改成合并。

**退出标准**：四个入口的建议下拉都来自后端；聚焦显示候选；排除已选与去重正确；`npm run test:web` 覆盖建议过滤与空输入行为；用户手工验收四个入口。

### 批次 3：查看器渐进加载与 GIF 标识

- **GIF**：查看器保持现有动画播放；网格与列表给 GIF 加角标，说明“查看器中播放”。超过 24MP 或带 EXIF 方向而走静态预览时，在查看器给出“已生成静态预览，动画不可用”的说明。编辑 GIF 仍只保留首帧，沿用现有警告。
- **渐进加载**：切换图片时先渲染当前图片的 512px 缩略图层（来自会话项的 `thumbVersion`），按原始宽高比占位；高清图 `onLoad` 后用短淡入替换，缩略图层在其下保留到首帧绘制完成。
- **加载态**：有缩略图时不显示整块“正在读取原图”；延迟 150ms 仍为加载中才显示小 spinner。无缩略图或加载失败时才回到现有错误态。
- **取图时序**：把 `get_viewer_source` 改为异步/阻塞线程执行，避免大图预览生成卡住窗口事件循环；`img://preview` 仍可在缺失时兜底生成。
- **一致性**：缩放、平移、裁剪选区、姿势叠加同时作用于缩略图层与高清层；切换、重试、404 时状态复位。
- **不做**：不在网格播放动图；不新增 GIF/APNG 解码器；不改变编辑输出格式；不提前预加载相邻图片。

**退出标准**：`npx tsc --noEmit`、`npm run test:web`、`npm run build`、`cargo test` 通过；用户手工验收快速切换、慢速大图、GIF、超过 24MP 的图片、原图缺失与重试；确认缩略图到高清无位置跳动、无二次闪烁。

### 批次 4：文件夹详情与统一统计缓存

- **后端统计**：新增只读的统计命令，复用 `PreparedQuery`/`FilterCounts` 的筛选与分组形状，返回图片数、文件夹数、总字节、类型分布、评分分布、最常见的若干标签（含名称与计数）。单文件夹按子树统计，多选文件夹取并集。排除回收站与临时区，口径与浏览一致。
- **不重复实现**：把“可见性 + 筛选”的 SQL 条件抽到同一处；统计和分面计数共享条件，避免出现两套筛选语义。
- **右侧详情**：没有选中图片且选中了文件夹时，右侧从“未选择”切换为文件夹概览；选中图片后图片详情优先。多选文件夹显示合并统计，并标明文件夹数。
- **缓存**：前端按“图库 + 文件夹集合 + 数据版本”缓存，采用先显示旧值、后台刷新的策略；导入、移动、删除、评分、标签等 `DataChange` 到来时失效相关键；缓存有容量上限，不随文件夹数量无限增长。
- **图表**：类型与评分用水平条形，标签用列表加计数；复用现有 SVG/CSS 图表样式，不引入图表库。
- **性能**：在 39 万行真实库上测量根目录/大文件夹统计；命令异步执行，界面保留旧值并显示刷新态。若根目录聚合超出预算，先限制标签数量与图表点数，再评估索引。
- **不做**：不建持久化统计表；不做增量计数；不在数据库里缓存文件夹统计；不把统计放进筛选面板。

**退出标准**：统计 SQL 与筛选结果一致；缓存失效有单测；39 万行下的耗时记录进 `docs/guides/performance.md`；用户手工验收单/多文件夹、空文件夹、切换视图、导入/移动后的刷新。

### 批次 5：并发、锁与线程运行层

**先审计，再改锁。**

- **资源矩阵**：列出每类任务（导入、缩略图、移动、永久删除、清空回收站、撤销/重做、释放文件、压缩、估算、临时区特征、AI embedding/pose/描述、相似分组）读写的资源：数据库、原图路径、缩略图包、操作记录、临时区、AI 进程、前端数据版本。矩阵先写进批次文档，作为改锁依据。
- **收窄准入**：
  - AI/扫描任务不阻塞文件夹操作；文件夹操作不再用 `is_idle()` 一刀切。
  - 导入、压缩、移动、编辑保存等会改写路径的写任务仍拒绝文件夹重命名/移动/删除，错误文案说明是哪个任务、为什么冲突。
  - 图库打开/切换/关闭仍要求空闲，避免换库时旧任务写新库。
  - 不把数据库单写连接改成多写；读始终不经过 lane。
- **路径保护**：为“读取原图”的 AI/扫描任务与“改写路径”的维护操作建立最小粒度的读/写保护，优先按根目录或文件夹子树，而不是全库。锁的获取顺序与释放写进批次文档，必须有超时/取消路径，避免死锁。
- **统一线程运行层**：
  - 一个全局图像工作预算（默认核数减一、上限可配），导入、压缩、估算、缩略图重建共用；不再各自出现 1-128 与 8 两套策略。
  - 统一进度/吞吐/ETA 工具；进度按像素或预计工作量加权，而不是只按张数。
  - 压缩：编码与下一批提交重叠（双缓冲），缩小提交批次；进度在提交/删旧阶段继续推进，不出现“100% 但仍在写”的假象。
  - 导入：写线程收尾期间显示“正在写入最后一批”；工作队列按单文件动态取任务，减少固定分片造成的尾部；必要时按文件大小加权进度。
- **生命周期与同步审计**：任务终态与 lane 释放、取消后的 join/收尾、`LiveOperation` 与 `HistoryRunGuard`、SQLite 写事务边界、缩略图包追加、临时预览缓存清理、导入任务表、估算结果缓存、前端 `DataChange` 与进度事件。逐项给出“谁在写、谁在读、何时失效”。
- **不做**：不换数据库；不做通用作业调度器；不做每文件一把锁的细粒度方案（先按子树）；不自动重启 AI 服务；不改变 write 优先与排队规则。

**退出标准**：资源矩阵与锁顺序文档完成；path guard 有冲突/取消/死锁测试；任务总线测试通过；压缩末尾 5% 与导入收尾有基准对比；用户手工验收“AI 运行时重命名文件夹”“压缩时重命名被拒绝且文案清楚”“取消任务后无残留”。

### 批次 6：批量任务计划数与执行进度

- **开始前计数**：新增只读预览命令，返回范围总数 `total` 与将处理数 `willProcess`。缩略图按缺失指针计数；embedding/pose 按当前模型与维度统计缺失；描述按缺失文本统计，勾选“重新生成”时排除手写描述，与任务实际过滤一致。
- **离线 AI**：服务离线时无法知道模型/维度，`willProcess` 显示“—”，并提示“连接 AI 服务后计算”；缩略图任务不受影响。`willProcess = 0` 时禁用开始并说明“没有需要处理的图片”。
- **界面**：范围选择器旁显示“范围 N 张 · 将处理 M 张”，切换类型、范围、跳过已有时刷新；过期请求丢弃；计数结果可按范围指纹短时缓存，写入后失效。
- **执行进度**：扩展任务进度详情，增加原始字节、已节省字节、当前文件、速度与 ETA；压缩任务主动调用 `percent` 与 `set_current`，不再只靠完成张数。沿用 150ms 的事件节流。
- **进度面板**：执行时把估算面板切换成同一布局的动态面板：完成百分比、已处理/总数、已节省体积、速度、ETA、当前文件、失败/跳过；预计值保留为对照，完成后显示实际 vs 预计。收益曲线改为“进度/时间 vs 累计节省”，保留原曲线作为预估参考。
- **不做**：不改压缩算法与质量参数；不在批次 6 重做估算公式；不新增第二套任务进度通道。

**退出标准**：预览计数与任务实际 `total` 一致（各类型、跳过/不跳过、离线/在线）；进度面板在取消、失败、跳过时数字自洽；`npm run typecheck`、`cargo test` 通过；用户手工验收开始前后数量与执行面板。

### 批次 7：压缩估算准确性

- **先测量**：在复制样本上记录每一层的预测与实际（读取、编码、哈希、重算、写盘、提交、删除），并把估算与实际执行都写成可对比的回测；同时记录机器负载与线程数。
- **解释已知现象**：执行按 bpp 降序，所以先慢后快；收益曲线按 bpp 桶累计，斜率递减，呈直线或下凹是排序结果，不是抽样错误。界面要能说明这一点，避免用户把“曲线不陡”当成估算错。
- **修正外推**：当前点估计用一次样本墙钟乘上按工作加权的全局像素比（`optimize_estimate.rs:1456-1482`），把不同层、读盘等待与并行尾部混在一起。改为按层分别外推工作与读取，再按线程数折算成墙钟；写盘与提交继续用校准值，但不再用一个全局倍率覆盖所有层。
- **误差区间**：保留切片重抽；把“样本并行尾部”“负载波动”“未覆盖体积”作为独立项，不再只覆盖抽样方差。覆盖 100% 时仍报 0。
- **实时 ETA**：执行中按已完成批次的真实吞吐修正剩余时间，按 bpp 层或像素权重计算；与批次 6 的进度面板共用。
- **建议目标**：时间中位偏差 ≤10%，节省空间中位偏差 ≤5%，误差区间覆盖实际值；达不到时如实记录，不把“更接近”写成“已准确”。若数据表明 `s5` 层内部异质仍是主因，再按 todo 中的 bpp 细分方案把 12 层拆成 18 层。
- **不做**：不改压缩判据、质量梯子或跳过策略；不新增抽样档位；不为估算引入机器学习模型；不编译 release。

**退出标准**：至少一份 300 张级真实副本与一份万张级副本的回测；预测 vs 实际按层可查；误差区间覆盖率有记录；真实库估算后执行的用户验收步骤写清楚。

## 四、跨批次原则

1. **先核对，再改。** 用户观察与代码不一致时，先说明现状；不为迎合反馈破坏已经自洽的行为。
2. **先测量，后优化。** 批次 4、5、7 都先留基线；没有基准就不引入缓存、锁或新线程策略。
3. **锁要对应资源。** 数据库并发交给 WAL 与单写连接；文件路径并发交给子树锁；不再用“全库空闲”代替冲突判断。
4. **缓存必须有失效键。** 文件夹统计、批量计划数、查看器缩略图都必须说明“谁失效、何时失效”。
5. **进度必须可解释。** 张数、字节、阶段与 ETA 的口径一致；取消、失败、跳过时不能出现互相矛盾的数字。
6. **不把计划写成已验收。** 每批完成后另写批次记录；未验证项继续留在 `todo.md`。
7. **界面由用户验收。** 代理不启动应用、不截图、不驱动窗口；每批给出可执行的手工验收步骤。
8. **边界不变。** 前端模块不互相导入；Tauri 命令只做适配；真实库只读；不新增版本号、CHANGELOG 或法务文件。

## 五、已确认决策

1. **GIF**：只保证查看器播放动画；网格与列表保持静态首帧，加 GIF 角标；不做动图缩略图。
2. **多选操作**：恢复/永久删除只在回收站视图显示，单图与多选一致；普通视图只保留移入回收站。
3. **导入遮挡**：本轮只改文案与重复标题，保持模态阻塞；非模态导入不实现，记入后续待评估。
4. **后台锁定**：AI/扫描任务期间允许文件夹重命名/移动/删除；导入、压缩、移动等改写路径的写任务仍拒绝，并给出原因。
5. **批量数量**：开始前同时显示范围总数与将处理数；离线 AI 无法计算时显示待计算。
6. **文件夹详情**：放在右侧详情面板，单文件夹与多文件夹（合并统计）都支持。
7. **压缩估算**：先按层测量，再改分层外推并增加执行中实时 ETA；不只放宽误差区间。
8. **线程模型**：采用统一线程预算与共用运行层，保留导入/压缩各自的任务循环；不把所有任务塞进一个全局池。

## 八、风险

- **批次 5 风险最高**：路径锁与 lane 交叉容易死锁或饥饿；必须先写资源矩阵与获取顺序，再做最小实现；取消路径必须覆盖等待中的锁。
- **批次 4 统计可能过重**：根目录或大文件夹的 `SUM`、标签聚合计可能达到数百毫秒；异步与缓存只能改善观感，不能替代查询优化，必须以真实库测量为准。
- **批次 3 渐进层可能干扰几何编辑**：缩略图与高清图尺寸、方向、裁剪坐标必须共用同一套显示尺寸；GIF 动图与缩略图层的切换要避免反复闪烁。
- **批次 2 统一 chip 可能影响筛选交互**：详情现有标签 chip 同时承担筛选菜单，抽取基座时不能丢掉“点击筛选/ Ctrl 叠加/移除”。
- **批次 1 隐藏按钮可能让操作找不到**：恢复/永久删除只在回收站显示后，普通视图用户可能找不到入口；右键菜单与单图规则必须同步。
- **批次 6 计数与任务实际过滤不一致**：模型/维度、手写描述、回收站、临时区的口径必须与 `filter_missing` 完全一致，否则会出现“预览 M 张、实际 N 张”。
- **批次 7 会改变用户看到的估算数字**：同时要解释误差与排序造成的曲线形状，不能只追求更接近实际；未达标要如实写。
- **所有批次**：不要为了“统一”引入新的全局状态；缓存、锁、线程预算都必须有明确生命周期与退出清理。
